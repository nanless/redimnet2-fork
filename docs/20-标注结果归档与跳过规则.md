## 1. 一句话规则

开源模型标注的整轮产物（`labels/`、`queue/`、`final-*`）按**代次日期**归档到
`/root/group-shared/voiceprint/open_annotation/redimnet2-silver-<YYYYMMDD>/`；
起新一轮之前，先从各代 `queue/completed/*.json` 建去重索引，再用索引过滤候选源清单。
旧代次只读，不再写入；`queue/completed` 是“哪些源已经做完”的唯一权威。

命名规则：

- 目录名只由 `redimnet2-silver-` 加 8 位日期组成，日期用**这一代开始生产的那天**，不用结束日。10-25/26 记 `20261025`，10-27 记 `20261027`，10-28 记 `20261028`，11-08/09 记 `20261109`。一个日期只对应一代，不把两批不同合同塞进同一个日期目录。
- 模型、profile、run 版本都写在目录内部（`<handoff>/run-<n>/labels/<profile>/`），不要写进日期目录名。以后同一日期要起新批，用新日期建新目录，不往旧代次里追加。
- 归档后不改名、不合并日期。收据里存的是写入时的绝对路径（v6 的 `sources[].producer_sidecar_tree` 就是旧路径），改名会让证据指向不存在的位置。
- 层级以原件为准：`20261025` 的 handoff 根下直接是 `labels/`、`queue/`，没有 `run-*` 层；迁移和建索引时不要为了“统一”强行加一层。
- `_index/` 只放派生文件，可以整目录重建；它不能反过来当标注结果的权威。

迁移做法与红线：

1. 先停写：确认这一代没有生产者、worker 或看板进程在写。
2. 用 `rsync -a --info=progress2 <旧目录>/ <目标目录>/` 分代复制，不用 `mv`。`/root` 与 `/root/group-shared` 是两个挂载点，`mv` 会退化成逐个复制再删除；中途失败会留下半棵树。
3. 核三样再算完成：`queue/identity.json` 的 sha 相同、`queue/completed` 的文件数相同、随机抽一个侧车 `sha256sum` 相同。有 `final-*` 的代次再核 `final-*/index.json` 与 `report.json` 存在且可解析。
4. 旧副本不要立刻删。`producer_sidecar_tree` 记的是旧绝对路径，先确认新归档能独立回答“这条收据对应哪棵树”，再按存储规范清理；清理动作要单独记录，不要和复制混在一起。
5. 迁移完成的代次在 `_index/migrations.json` 记一行（源、目标、收据数、identity sha、核对时间）；没核完的代次不要写成“已归档”。

## 3. 每一代必须保留什么

| 必须保留 | 具体位置 | 作用 | 缺了会怎样 |
|---|---|---|---|
| 逐源侧车 | `run-<n>/labels/<profile>/{cnceleb2,voxblink2,voxceleb2}/` | 实际的文字、时间、原始与修补结果 | 只能重跑模型，不能从收据还原文本 |
| 侧车树身份 | `run-<n>/labels/<profile>/identity.json` | 绑定 profile 树与合同、索引身份（`redimnet2-sidecar-tree/v1`） | 同名 profile 无法区分是哪份合同写的 |
| 分片提交收据 | `run-<n>/queue/completed/*.json` | 每个分片的 `source_count`、`sources[].source_id`、`decision`、侧车 sha | 无法判断哪些源真的做完，也无法去重/跳过 |
| 队列身份与完成槽 | `run-<n>/queue/identity.json`、`completion_map.bin`、`broker.json` | 绑合同/索引 sha，记录完成片与恢复位置 | 收据无法证明属于哪条队列，断点也无法核 |
| 终态材料 | `final-<n>/index.json`、`final-<n>/report.json`（或 `retained-partial.jsonl`） | 记录终态计数、保留/剩余划分、是否完整收口 | 分不清“跑完停止”和“中途被打断” |
| 运行证据（随 run 保留） | `resources-attempt1/` 的 worker 日志、`failure.json`、回执 | 解释失败与资源归还 | 只能看到结果，看不到为什么停 |

终态材料的现状要如实记：`20261109` 这一代有 `final-v6/`；`20261025`、`20261027`、`20261028` 的 run 目录里没有 `final-*`。后三代迁移时不要伪造 `final-*`，而是在代次根写一份 `archive-manifest.json`，记清收据数、最后一份收据、`queue/identity.json` 的 sha 和“没有 final 原件”的事实；等有真实终态材料再补，不能拿手写 JSON 冒充生产终态。

### 3.1 为什么 `queue/completed` 是权威

1. **它在提交时写，和“完成”是同一件事。** 一个分片只有提交后才在 `completed/` 出现一份收据；`labels/` 里可能有写了一半、失败回退或孤儿侧车，光看文件在不在说明不了这个源已经完成。
2. **它带决策和身份。** 收据里有 `sources[].source_id`、`decision`、`sidecar_sha256`、`source_count`，以及整份收据的 `schema` 与 `contract_sha256`。这些字段是“哪个源、用哪份合同、得到什么状态”的最小完整记录，侧车文件本身没有。
3. **进度与去重都从它求和。** `tools/annotation_progress.py` 和 `tools/gen_status.py` 都只读 `queue/completed/*.json` 的 `source_count`；在 GPFS 上 `find labels -type f | wc -l` 要几十分钟，而且把半成品和孤儿也算进去，得不到可对账的数。
4. **它可复核。** 正常停止时 `queue/completed` 的份数与 `broker.json` 的 `completed_chunks` 同量级；每份收据的 `shard_sha256` 还能和索引描述对上。侧车树只能证明“有这个文件”，不能证明“这个分片整体提交过”。

因此：**收据与侧车冲突时，以收据为准**；不要为了“让数字好看”去补收据、改 `source_count` 或把侧车文件数当完成数。反过来，只有侧车、没有收据的源不能算完成；只有收据、侧车缺失的源仍算完成（可跳过），但消费文字前要单独记账，不能把缺失侧车当成有文字。

## 4. 以后标注：先建索引，再过滤队列

顺序不能反。先起生产者、事后再去重，等于把已经做完的源又标一遍，还会让两代收据对同一 `source_id` 给出不同合同，后面无法判断哪份有效。

### 4.1 操作顺序

1. 停写并确认旧代次只读。
2. 从所有代次的 `queue/completed/*.json` 重建 `_index/`（4.2 的命令）。
3. 明确这一轮**要跳过哪些代次**，写进 `SKIP_GENS`。不要默认“所有代次都跳过”：`20261028` 与 `20261109` 是同一条队列的两次尝试（同一批 `source_id`、不同合同），把 `20261028` 当已有一刀切跳过，会把这一轮要重算的源全部挡掉。跳过集合只放已经验收、不会再重算的代次。
4. 用索引过滤候选源清单，得到新的 `queue-candidates-<日期>/`（4.3 的命令）。
5. 再按当次冻结入口生成新队列并起跑；新 run 写在新日期目录，不写旧代次。
6. 本轮结束后把新 run 与终态归档，重跑 4.2 的索引，更新 `counts.json` 与 `migrations.json`。

### 4.2 建索引（完整命令）

下面这段直接整段粘进 shell 执行；本文不往仓库加新工具。它只读收据，不写任何一代目录。

```bash
python3 - /root/group-shared/voiceprint/open_annotation/_index <<'PY'
import hashlib, json, sys
from concurrent.futures import ThreadPoolExecutor
from pathlib import Path

BASE = Path('/root/group-shared/voiceprint/open_annotation')
OLD = Path('/root/dsh-workspaces-mac/02_实验与标注_ReDimNet2/redimnet2/open-annotation-ultra-20261025')
OUT = Path(sys.argv[1])
if (OUT / 'source_ids.txt').exists() or (OUT / 'by-generation').exists():
    raise SystemExit('index already exists: %s' % OUT)
# 两处都扫（新归档 + 02 根旧树）；旧 /root/experiments 已不存在，别再写它。
GEN_ROOTS = {
    '20261025': [BASE / 'redimnet2-silver-20261025', OLD / 'formal-three-training-ultra-v1'],
    '20261027': [BASE / 'redimnet2-silver-20261027', OLD / 'portable-successor-20261027-v1'],
    '20261028': [BASE / 'redimnet2-silver-20261028', OLD / 'native-speed-successor-20261028-v1'],
    '20261109': [BASE / 'redimnet2-silver-20261109', OLD / 'handoff-v4r2-20261108-v6'],
}
ALLOWED = {'redimnet2-chunk-commit/v1', 'redimnet2-bounded-chunk-commit/v1'}

def completed_dirs(root):
    if not root.is_dir():
        return []
    found = []
    for pattern in ('queue/completed', '*/queue/completed', '*/*/queue/completed', '*/*/*/queue/completed'):
        found.extend(p for p in root.glob(pattern) if p.is_dir())
    return found

def receipt_files(gen, dirs):
    for d in dirs:
        for p in sorted(d.glob('*.json')):
            yield gen, p

def load(item):
    gen, path = item
    raw = path.read_bytes()
    d = json.loads(raw)
    schema = d.get('schema')
    if schema not in ALLOWED:
        raise ValueError('unexpected schema %r in %s' % (schema, path))
    srcs = d.get('sources') or []
    if len(srcs) != int(d.get('source_count') or 0):
        raise ValueError('source_count mismatch in %s' % path)
    ids = []
    for s in srcs:
        sid = s.get('source_id')
        if not sid:
            raise ValueError('missing source_id in %s' % path)
        ids.append(sid)
    return {'gen': gen, 'path': str(path), 'shard_id': d.get('shard_id'),
            'shard_sha256': d.get('shard_sha256'), 'contract_sha256': d.get('contract_sha256'),
            'schema': schema, 'source_count': len(ids),
            'receipt_sha256': hashlib.sha256(raw).hexdigest(), 'source_ids': ids}

files, seen_dirs = [], set()
for gen, roots in GEN_ROOTS.items():
    dirs = []
    for root in roots:
        for d in completed_dirs(root):
            if d not in seen_dirs:
                seen_dirs.add(d)
                dirs.append(d)
    files.extend(receipt_files(gen, dirs))
files.sort(key=lambda x: (x[0], str(x[1])))

ids, gen_ids, receipts, seen = set(), {}, [], set()
for rec in ThreadPoolExecutor(max_workers=16).map(load, files):
    # 同一份收据可能在新旧两处各有一份；按 代次+合同+分片 去重，跨代同源不合并。
    key = (rec['gen'], rec['contract_sha256'], rec['shard_id'], rec['shard_sha256'])
    if key in seen:
        continue
    seen.add(key)
    bucket = gen_ids.setdefault(rec['gen'], set())
    for sid in rec['source_ids']:
        ids.add(sid)
        bucket.add(sid)
    rec.pop('source_ids')
    receipts.append(rec)

OUT.mkdir(parents=True, exist_ok=True)
(OUT / 'source_ids.txt').write_text('\n'.join(sorted(ids)) + '\n')
by_gen = OUT / 'by-generation'
by_gen.mkdir()
for g, v in sorted(gen_ids.items()):
    (by_gen / (g + '.txt')).write_text('\n'.join(sorted(v)) + '\n')
(OUT / 'receipts.jsonl').write_text(''.join(json.dumps(r, sort_keys=True) + '\n' for r in receipts))
counts = {g: {'sources': len(v), 'receipts': sum(1 for r in receipts if r['gen'] == g)}
          for g, v in sorted(gen_ids.items())}
(OUT / 'counts.json').write_text(json.dumps(
    {'generations': counts, 'unique_sources': len(ids), 'receipts': len(receipts),
     'duplicate_receipts_skipped': len(files) - len(receipts)},
    ensure_ascii=False, indent=2, sort_keys=True) + '\n')
print(json.dumps({'files_scanned': len(files), 'receipts_kept': len(receipts),
                  'unique_sources': len(ids), 'generations': counts}, ensure_ascii=False, indent=2))
PY
```

几点说明：

- 首次全量要读几万份收据（2026-11-09 实测约 5.5 GB），按 GPFS 当时的速度预留几分钟。当前版本每次都全量重建，好处是可重复、可对账；收据数量再涨时，再按 `receipts.jsonl` 只处理新路径，本文不展开。
- `source_ids.txt` 是所有代的并集，只用于查“这个源出现过没有”；**不要拿它直接当跳过集合**。跳过用 `by-generation/<日期>.txt`，按第 4.1 步选代次。
- `receipts.jsonl` 是索引的账本：每行一份收据的路径、分片、合同、源数与**收据文件的 sha256**。它不复制侧车内容，但能证明建索引时读到的收据没被换过。
- `counts.json` 的 `sources` 是**该代去重后的 source_id 数**，不是收据 `source_count` 的简单相加；同一代内重复提交的源只算一次。
- `source_ids.txt` 已存在时脚本会报错退出，这是故意的：重建先挪走旧索引，不要覆盖后才发现半份；`migrations.json` 可以单独留在 `_index/`。
- 建完写一份校验清单：

  ```bash
  cd /root/group-shared/voiceprint/open_annotation/_index
  sha256sum source_ids.txt counts.json receipts.jsonl by-generation/*.txt > SHA256SUMS
  ```

  以后迁移或换机器，先 `sha256sum --check SHA256SUMS` 再相信索引。

### 4.3 过滤候选队列（完整命令）

```bash
INDEX=/root/group-shared/voiceprint/open_annotation/_index
SKIP_GENS=20261025,20261027        # 只写已验收、不会再重算的代次
IN=/root/dsh-workspaces-mac/02_实验与标注_ReDimNet2/redimnet2/open-annotation-ultra-20261025/catalog-three-training-only-v1/shards   # 历史路径：源清单在 02 根旧树
OUT=$INDEX/queue-candidates-20261110
python3 - "$IN" "$OUT" "$SKIP_GENS" "$INDEX" <<'PY'
import json, sys
from pathlib import Path

IN_DIR, OUT_DIR, INDEX_DIR = Path(sys.argv[1]), Path(sys.argv[2]), Path(sys.argv[4])
skip_gens = [g.strip() for g in sys.argv[3].split(',') if g.strip()]
skip = set()
for gen in skip_gens:
    f = INDEX_DIR / 'by-generation' / (gen + '.txt')
    if not f.is_file():
        raise SystemExit('missing generation index: %s' % f)
    skip.update(f.read_text().splitlines())

if OUT_DIR.exists():
    raise SystemExit('output already exists: %s' % OUT_DIR)
OUT_DIR.mkdir(parents=True)
stats = {'files': 0, 'kept': 0, 'skipped_existing': 0, 'skipped_duplicate': 0}
for src in sorted(IN_DIR.glob('*.jsonl')):
    dst = OUT_DIR / src.name
    seen = set()
    kept = skipped_existing = skipped_duplicate = 0
    with src.open() as fi, dst.open('x') as fo:
        for line in fi:
            rec = json.loads(line)
            sid = rec.get('source_id')
            if not sid:
                raise SystemExit('missing source_id in %s' % src)
            if sid in skip:
                skipped_existing += 1
                continue
            if sid in seen:
                skipped_duplicate += 1
                continue
            seen.add(sid)
            if not line.endswith('\n'):
                line += '\n'
            fo.write(line)
            kept += 1
    stats['files'] += 1
    stats['kept'] += kept
    stats['skipped_existing'] += skipped_existing
    stats['skipped_duplicate'] += skipped_duplicate
(OUT_DIR / 'filter-stats.json').write_text(json.dumps(stats, ensure_ascii=False, indent=2) + '\n')
print(json.dumps(stats, ensure_ascii=False, indent=2))
PY
```

怎么读结果：

- `kept + skipped_existing + skipped_duplicate` 应等于输入行数；三个数对不上就是有行没读或重复计数，先停下查。
- 第一次跑先拿一小批源清单试（例如只放一片 `*.jsonl` 进临时目录），确认 `kept` 不是 0 且抽样行的 `source_id` 不在跳过集合里，再对全量目录跑。若整批都落在已验收代次里，`kept: 0` 是正常结果，不是脚本坏了。
- 输出目录里每个文件与输入同名、逐行保留原字节，只删行不重排；这是为了让下游还能按 `source_ids_sha256` 校验。
- 这一步做的是**跨代去重**；当次冻结入口自己的“保留完成片”逻辑（如 `prepare_speed_continuation.py` 的完成槽保留）仍要照做，两步不能互相替代。
- 过滤后的目录不是新队列本身。把其中每个 `*.jsonl` 作为新队列的源清单输入，交给当次冻结入口的 `manifest_builder.py --config`（或同级入口）生成 bounded shards；合同、索引 sha、`--new_run_root` 都由当次冻结包固定，本文不复制这些参数，避免和版本一起过期。

## 5. 各代差异（只引用结论）

逐字段对照见 `tools/open_annotation/annotation-format-consistency.md`（该文件由标注工具侧维护；本文不复制字段表）。落到归档和索引上，只需要记住三条：

1. **收据 schema 有两种。** `20261025`、`20261027` 用 `redimnet2-chunk-commit/v1`；`20261028`、`20261109` 用 `redimnet2-bounded-chunk-commit/v1`。后者的 `sources[]` 多出 `producer_contract_sha256`、`producer_sidecar_tree`、`retained_existing` 三个字段。索引器只依赖 `source_id`、`source_count`、`contract_sha256` 和分片身份，所以两种都要收，不能因为字段少就把旧代次跳过。
2. **队列身份也有两种。** `20261025`、`20261027` 是 `redimnet2-work-queue/v1`；`20261028`、`20261109` 是 `redimnet2-bounded-work-queue/v1`。`identity.json` 的 `contract_sha256`/`index_sha256` 是区分同名代次的依据，迁移核对时比的就是这两个值和收据数，不是目录名。
3. **同名 `source_id` 会在多代出现，这是正常的。** 2026-11-09 实测：`20261109` 的 966,520 个源全部落在 `20261028` 的 4,447,318 个源里——两代是同一条 9,903,741 源队列的两次尝试，收据 `shard_id` 相同、`contract_sha256` 不同。所以索引必须按“代次 + 合同 + 分片”记收据、按代次出跳过文件；只按 `source_id` 做全局集合，会把 `20261109` 当成 `20261028` 的重复而整代漏掉。

不要“升级”旧收据的 schema 来统一格式。收据是写入时的证据，改字段或改 `source_count` 等于伪造；需要统一的是**索引器**，不是原件。
