# 22 续标注：按文件核对跳过集合，重建候选索引

这页记录 2026-11-10 的续标注准备流程与实测数字。它补 `docs/20` 的一处缺口：`docs/20` 把所有 `queue/completed` 收据当成"已完成"，而实测有 22.62% 的收据源在磁盘上没有侧车文件。

## 1. 为什么不能只信收据

`queue/completed/*.json` 是分片提交的权威凭据，它证明"这个分片被提交过"，不证明"每个源的侧车还在"。2026-11-10 全量核对 6,062,771 条收据源：**1,371,568 条（22.62%）四代目录里都没有侧车文件**，集中在 `redimnet2-silver-20261028/labels/.../voxblink2` 的 speaker `id114242..id214887` 连续带（51,665 个空目录）。收据口径的完成度是 52.62%，**文件口径只有 4,691,203 源 = 40.7%**。

只按收据跳过，这 1,371,568 个源会被永久跳过，训练端永远读不到它们的标注。

## 2. 三步准备

1. **核对侧车是否存在**：对 done-index 每一条，按 `sidecar_relpath` 在四代 `labels/<profile>/` 下 stat；缺失的 `source_id` 写成一个清单。本次 6,062,771 条用 64 进程跑了 975 秒，结果 `_index/done-missing-sidecar.txt`（1,371,568 行）。
2. **过滤候选分片**：`tools/open_annotation/prepare_resume_queue.py --shards <catalog/shards> --done-index <done-index.jsonl> --missing <清单> --out <candidates>`。逐行保留原字节，规则是"只有 `sid` 在 done 且不在 missing 时才丢弃"。本次 11,521,178 行 → 保留 6,829,975、跳过 4,691,203、坏行 0，顺序单进程 190 秒（多进程版本在本机 fork 大集合时会卡死，见 3.2）。
3. **重新分片成索引**：`tools/open_annotation/manifest_builder.py --config <config> --output <build>`，config 的 `inputs` 是上一步每个非空 `*.jsonl`（`kind=source_jsonl`）。本次 6,829,975 源 → 26,784 片，耗时约 29 分钟，索引 sha `62f851cc9693006a51ab84ba76d21dd9671a3d93df79e6ef82083f683c064be1`。

## 3. 两个操作坑

### 3.1 大目录上的通配会静默失败

`ls <dir>/*.jsonl` 与 `grep -l <pattern> <dir>/*.jsonl` 在两万多个文件时会 `argument list too long`，输出为空但不报错。改用 `find <dir> -name '*.jsonl'` 或 `grep -r`。

### 3.2 fork 继承大集合的多进程会卡死

用 `ProcessPoolExecutor` 让每个子进程继承 600 万条目的 `done` 集合时，本轮实测卡在 296 个文件、34 个进程 0% CPU。同样的工作改成单进程顺序流式，45,975 个分片 / 19 GB 只用了 190 秒。

## 4. 验收

- `kept + skipped + bad == 输入行数`；本次 6,829,975 + 4,691,203 + 0 = 11,521,178。
- 新索引 `source_count` 等于过滤后的行数；`shards` 的 `count` 之和等于 `source_count`。
- 抽样双向核对：新索引里抽源，`done` 末清单命中应为 0；`missing` 清单抽源，新索引命中应为全部。
- 续跑前再确认：新索引里**没有**任何"有收据且有文件"的源。
