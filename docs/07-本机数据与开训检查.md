# 07 · 本机数据现状与开训前检查

上一篇：[实验配方与复现](05-recipes-and-repro.md) · 下一篇：[术语表与 FAQ](06-glossary-faq.md)

这一篇回答一个很实际的问题：**照着文档准备训练，现在这一步能不能开跑？差什么？**

数据是否齐全、路径对不对，只看文档里的旧记录是不够的，会踩空。本文的每个数字都是
在 2026-10-13 到 10-14 期间在本机用命令实测出来的，并写明了用什么办法数的。
如果你以后又拷贝或重转了数据，请重新计数后再改本文。

---

## 1. 先看结论

| 训练线 | 现在能不能开训 | 差什么 |
|--------|----------------|--------|
| 只练 VoxCeleb2（`examples/vox2`） | **数据全齐，但还差一步路径** | `/data/wespeaker_data` 在本机不存在，要先建软链接或改覆盖文件 |
| 混合数据（`examples/vb2_vox2_cnc2`） | **还不能** | 同一个路径问题，外加 `mix_join` / `mix_join_lm` 两份样本清单还没生成 |

原始语料本身两条线都齐，不缺音频。挡住训练的是路径和"还没拼清单"这两件事。

---

## 2. 本机没有 `/data` 这个目录

这是最容易踩的第一个坎。

仓库里 18 份配方、`docs/` 各篇、以及 `AGENTS.md`，默认都写 `/data/wespeaker_data/...`。
但在本机执行 `ls -d /data` 会直接报 `No such file or directory`，**根目录下根本没有 `data` 这一项**。

数据实际在共享盘上：

```text
/root/group-shared/voiceprint/data/wespeaker_data/
```

其中 `/root/group-shared` 是一个软链接，指向 `/shared/group-shared`，
两个路径指向同一块 GPFS 共享盘（`readlink -f` 的结果一致）。

这带来的后果很直接：**照文档直接启动训练，会在读训练样本清单那一步失败。**

仓库里**没有任何脚本会替你建 `/data` 软链接**（在 `applications/` 和 `scripts/` 下
搜索建软链接的命令，没有任何命中）。所以要自己动手，两种做法二选一：

```bash
# 做法一：建软链接，让配置里原有的 /data/... 变得可达
mkdir -p /data
ln -s /root/group-shared/voiceprint/data/wespeaker_data /data/wespeaker_data
```

```yaml
# 做法二：不建软链接，用本地覆盖文件把路径全改掉（推荐给只想跑单条线的人）
# 存成 /tmp/vox2-b0-local.yaml 之类，启动时交给 --config_overrides
train_data: /root/group-shared/voiceprint/data/wespeaker_data/vox2_dev/data.list
train_label: /root/group-shared/voiceprint/data/wespeaker_data/vox2_dev/utt2spk
validation:
  vox1: /root/group-shared/voiceprint/data/wespeaker_data/vox1-test
exp_dir: /root/group-shared/voiceprint/data/wespeaker_data/exp/vox2/b0_ptn
```

> **注意：两个 examples 的 README 里给的覆盖模板，示例路径写的也是 `/data/wespeaker_data/...`**，
> 在本机同样不可用。照着模板抄完，路径还是错的，要按上面的真实位置改。

做法二要改的地方不止 `train_data`：`validation.vox1` 要改，增强用的
MUSAN 与 RIRS 目录（在 `dataset_args.aug_setup` 里）也要改。
改增强部分时**要整段带上 `aug_setup`** —— 配置里的列表是整段替换的，
只改一半容易让其中某几项还指着旧路径。

## 3. 磁盘余量：别把训练输出写到容器根上

| 挂载点 | 类型 | 容量 | 可用 | 使用率 |
|--------|------|------|------|--------|
| `/root` 与 `/shared/group-shared`（同一块盘） | GPFS | 164 T | **18 T** | 90% |
| `/aispeech-cfs` | cfs-fuse | 11 T | **3.1 T** | 71% |
| `/`（容器根） | overlay | 20 G | **约 2 GB** | 90% |
| `/dev/shm` | tmpfs | 325 G | 325 G | 0% |

**容器根只剩约 2 GB。** 训练日志、过程中的临时文件、以及 `exp/` 下每个轮次的权重，
如果落在这上面，几个轮次就会把盘写满，然后训练以一种很难看懂的方式失败。

建议：`exp_dir` 写到共享盘上；如果想让读写更快，写到 `/dev/shm`（本机有 325 GB，够用，
但断电或重启会丢，适合临时实验）。

另外 VoxBlink2 同级还留着 20 多个约 40 GB 的分卷归档（合计约 1.6 TB），
共享盘已经用了 90%，清理与否自己权衡。

（上表在 2026-10-14 实测。磁盘余量会随使用变化，动手前建议自己再 `df -h` 看一眼。）

## 4. 逐项实测结果

统计办法都写在表里。注意 `musan` 和 `simulated_rirs` 是**软链接**，
数文件时 `find` 不加 `-L` 会得到 0，这是很容易白忙一场的坑。

| 数据 | 期望 | 实测 | 用什么数的 |
|------|------|------|------------|
| VoxCeleb2 开发集句数 | 1,092,009 | **1,092,009** | `wc -l` 数 `data.list` 与 `utt2spk` |
| VoxCeleb2 开发集说话人 | 5,994 | **5,994** | `wc -l spk2utt`；`wav/` 下也是 5,994 个软链接目录 |
| VoxCeleb2 开发集 wav | 同句数 | **1,092,009** | `find -L ... -name "*.wav"` |
| VoxCeleb2 测试集句数 | 36,237 | **36,237** | 与开发集合计 1,128,246，反推得到 |
| VoxCeleb2 说话人目录 | 6,112 | **6,112** | `ls` 数目录，瞬间完成 |
| MUSAN（音乐 / 噪声 / 语音） | 660 / 930 / 426 | **660 / 930 / 426 = 2,016** | `find ... -name "*.wav"` |
| RIRS 模拟房间脉冲 | 60,000 | **60,000** | `find -L`（要跟随软链接），几秒 |
| VoxCeleb1 说话人与句数 | 1,251 / 153,516 | **1,251 / 153,516** | `ls` 数目录 + `find` 数 wav |
| VoxCeleb1-O 试验条数 | 37,611 | **37,611** | `wc -l veri_test2.txt` |
| VoxCeleb1-O 用到的 wav | — | **4,708**，缺失 0 | 逐条核对列表里每个句子是否落得到文件 |
| CN-Celeb2 说话人 | 1,996 | **1,996** | `ls` 数 flac 与 wav 目录，各 1,996 |
| CN-Celeb2 句数 | 各约 524,787 | **flac 与 wav 各 524,787** | `find -name "*.flac"` / `*.wav` |
| VoxBlink2 说话人目录 | 约 111,284 | **111,284** | `ls audio \| wc -l` |
| 混合线 `mix_join` / `mix_join_lm` | 还没有 | **确实不存在** | 全盘查找 `vox2_vb2_cnc2_v0`，无命中 |

一句话：**数量层面文档的期望值全部对得上，没有缺项。**

### Vox1-test 的 WAV 数量为什么是 4,708 而不是 4,874

这两个数字都对，只是含义不同：

- **4,874** 是官方小包里全部文件数，`prepare_data.py` 也用它做校验。
- **4,708** 是本机实际链接过来的数量 —— 这里是**按 `veri_test2.txt` 用到的句子挑着链的**，
  正好 4,708 条，逐条核对无缺失。

所以按这份列表做训练中的验证完全够用，两个数字并不冲突。

### VoxBlink2 的全量句数还没统计过

上面只数了说话人目录数（111,284）。全量句数至今没人统计过 —— 那个目录有 11 万个说话人子目录、
千万级文件，`find` 会跑很久。**要写进报告的话得单独补一次**，建议分批统计或用抽样估算，
不要直接对整个目录跑 `find`。

### CN-Celeb2 的路径

混合线用的是 **CN-Celeb2**，路径上是这两个：

```text
.../speaker_verification/cnceleb/CN-Celeb2_flac/data/
.../speaker_verification/cnceleb/CN-Celeb2_wav/data/
```

同级还有 `CN-Celeb_flac` / `CN-Celeb_wav`（这是第一代 CN-Celeb，不要混），
以及几个空的清单临时目录。

## 5. 一处过时的说法：旧树其实是齐的

`AGENTS.md` 原先写着，下面这棵旧的 VoxCeleb 树是**不完整的**，不要拿它当训练主数据：

```text
/aispeech-cfs/voiceprint/data/voxceleb/vox2/wav
```

但在 2026-10-13 到 10-14 实测下来，这棵旧树的计数与约定主目录**完全一致**：

| 项 | 旧树实测 | 约定主目录实测 |
|----|----------|----------------|
| 说话人目录数 | 6,112 | 6,112 |
| wav 句数 | 1,128,246 | 1,128,246 |
| 抽查若干文件大小 | 逐字节相同 | 同左 |

也就是说，**"少一截"的旧状态现在不成立了** —— 可能是后来补齐了，也可能当初描述的是更早的时刻。

按 `VoxCeleb约定主目录说明.txt` 的约定，仍然**建议以约定主目录为准**：

```text
/root/group-shared/voiceprint/data/speech/speaker_verification/voxceleb/
```

但这里要如实记一句：**就本机当前的计数而言，这棵旧树并不差**，不能再说它"不完整"。

**附带一条**：`checkpoints/reports/musan_restore_status.txt` 末尾记着一条
"`/data/wespeaker_data` 指向共享盘"的软链接记录，但当前 `/data` 整个不存在，
**这条记录不成立**。

## 6. 开训前检查清单

照着走一遍，能避开上面提到的所有坎。

**通用（两条线都要）**

1. 确认数据实际位置：`ls -d /root/group-shared/voiceprint/data/wespeaker_data`，应当能看到目录。  
2. 处理路径：要么建 `/data/wespeaker_data` 软链接，要么写一份本地覆盖文件把
   `train_data`、`train_label`、`validation.vox1`、以及增强的 MUSAN / RIRS 目录都改掉。  
3. 确认 `exp_dir` **不在**容器根上，改到共享盘或 `/dev/shm`。  
4. 确认样本清单行数合理：`wc -l` 数 `data.list` 与 `utt2spk`，应当各 1,092,009 行。  
5. 确认清单里引用的音频真的读得到：从 `data.list` 抽几条，看 `wav` 字段指的路径是否存在。
   （本机清单里的路径前缀是 `/shared/group-shared/...`。）  
6. 确认验证列表可读：`wc -l /.../vox1-test/veri_test2.txt`，应当是 37,611 行。  
7. 确认增强目录存在：`raw/musan/{music,noise,speech}` 与 `raw/rirs/simulated_rirs`。
   它们是软链接，检查时记得跟随软链接（`ls -L` 或 `find -L`）。

**只练 VoxCeleb2**

8. 直接可跑。建议先单卡 1 个轮次冒烟（见 [05 第 4 节](05-recipes-and-repro.md)），
   跑完打开 `exp_dir/val_log.csv`，确认写出了等错误率。
   **但这一列不能直接和官方数字比**：它算的是每段音频开头 8 秒的窗口，不足 8 秒还会循环补齐；
   要对官方表得用读整段音频的评测脚本（见 [05 第 9 节](05-recipes-and-repro.md)）。  

**混合数据**

9. 先跑 `prepare_vox2_vb2_cnc2_data.sh` 生成 `mix_join`，再跑 `prepare_vox2_vb2_cnc2_lm_data.sh`
   生成 `mix_join_lm`。两条命令里的 `--output-root`、`--vb2-root`、`--cnc2-root` 都要换成真实位置。  
10. 跑之前确认目录层级符合脚本要求：VoxBlink2 是 `<vb2-root>/audio/`，
    CN-Celeb2 是 `<cnc2-root>/CN-Celeb2_flac/data/`，不匹配脚本会直接退出。  
11. 确认 `b6/lm.yaml` 加载的到底是哪一轮的权重（配置、注释、`exp_dir` 三处对不上，
    见 [05 第 5 节](05-recipes-and-repro.md)）。
