# 有界八卡等待与材料交接的 CPU 检查

本次新增专用 `bounded_speed_queue_handoff.py`，用于候选真实选型通过后，先给新八卡实例分配资源并等待实际请求，再由操作者受控停止明确的旧标注任务。程序本身不停止旧标注、不操作 PTN、不提交平台任务、不创建 CUDA context，也不做全库审计或数据库。本节不声称新八卡任务已经提交或通过真实恢复。

完整流程、命令、开发机发布条件及三个必填模板见[有界八卡排队与材料交接](../../tools/open_annotation/有界八卡排队与材料交接.md)。旧 `queue_handoff.py` 继续只接受其旧 portable `/v1`、`/v2`；新协议未放宽旧入口。

## 实现和实际修正

新蓝图在提交前固定实际候选证据、cf7e859 专属新 GPU 软件、新合同、前一实际 run、原解释器、原 UUID 锁根、输出与 1800 秒上限。外层控制包独立发布，18 个共同 helper 逐字节来自固定 GPU bundle；31 个模型／资源／控制关键源固定为 `cf7e8599eedda5a8a61a57cc6c30e1b4c764a2aa`，不会接受工作目录中未验原生 batch4/8 的合同或后端。GPU 包保持原字节，不能直接向冻结目录添加 wrapper 或改旧清单。

新请求绑定实际 task、hostname、PID、start ticks、boot ID、nonce 和私有原件摘要。请求前只读 NVML，须见八张空闲 A800、零 compute PID 和足够显存；没有导入 torch。平台观察必须来自这个请求之后的真实读取，最近旧 task 与 worker 都须终态、active_workers 为零，新实例唯一 worker 则为 Running。旧 task 与 worker 的实际终态允许不同，保留 Failed 等原始状态，不伪装成一致成功。

终态后发布只调用既有有界准备：最多八个在途片逐源检查；未来未领取片只读元数据。最终报告、薄索引、runtime、request／nonce／reply 和新鲜平台材料反复绑定。等待使用墙钟及单调钟，SIGINT／SIGTERM、超时、旧父锁仍持有、源码／观察／身份被换等均拒绝并保留证据。发布后才建立独立 run，最后直接 exec 原 GPU 父入口，原 W2、挂载、祖先锁、最近旧 writer 锁、永久唯一生产者声明、UUID 资源协议和精确清理继续执行。CPU 的 reply 或 exec-intent 不授 GPU 资格。

初版曾把 wrapper 要求放进同一个 GPU 包，随后按固定 cf7e859 不变的要求改为独立 outer 控制包；没有修改实际冻结 GPU 目录。文件系统合成测试还发现浮点伪时钟到微秒 ISO 序列化可能造成极小“未来时间”，导致预期的后续反例提前拒绝。修正的是测试伪时钟起点，生产时效门未放宽；两份初始失败日志保留。早期测试模块直接导入另一个 TestCase 类，使其 20 项被额外发现并重复执行，现改为按模块引用，当前新入口独立 25 项计数准确。

## 实际运行的 CPU 检查

- 新入口 25 项普通模式 1.845 秒、`-O` 1.921 秒全部通过、无跳过。包括活动旧 writer 的默认检查零源读取、真实文件发布／等待／exec 参数、超时和信号、错误新 task、旧 Running、旧锁被占、观察早于请求、nonce 和运行配置篡改、重复发布、进程身份漂移、未知 compute PID、错误卡数、DDP 环境、多种真实终态、外层 helper／导入目录差异及固定 GPU 源版本。
- 与已有有界准备、队列、正式 runtime 和旧排队交接组合，共 136 项普通模式 7.844 秒、`-O` 7.944 秒全部通过、无跳过。它们证明 CPU 格式、实际小文件、锁和计账条件，不代表模型、八卡恢复或人工字界通过。
- 另外实际从上述 cf7e859 提交生成代码归档，在临时目录用明确标成“CPU 格式样本、不是模型”的合同冻结，再构建独立 outer。31 个关键源 SHA、18 个共同 helper、复制前后 GPU 包全部成员摘要一致；检查结束后临时目录释放。没有加载模型或访问 GPU，不把该合成合同与临时 bundle 当真实生产原件。
- 三个模板均为合法 JSON，blueprint 和 runtime_base 字段与实现精确相等；占位符故意不可执行，必须以现场实际文件摘要和新鲜平台材料替换。`git diff --check` 通过。

私有完整日志、初始失败和归档构建收据保留在仓库忽略目录 `.audit-local/bounded-handoff-20261028/queue-wrapper/`。维护源、模板和说明进入仓库，实际业务音频、标注原件、完整日志和模型不进入公开提交。

## 仍需现场完成

独立复审后，再按真实选型结果构建最终 GPU 包与 outer，核新八卡表单及实际请求，明确旧标注停止对象，取得真实终态、准备最多八片原件，并完成新实例的原 GPU 协议、已有结果零重跑和恢复检查。等待实例已经分配并可能计费；1800 秒材料等待不能写成免费排队，也不能用开发机 `/proc` 代替云节点进程或任务状态证据。若新原生批处理之后实测更快，另建其独立协议与准入，不能把本轮单窗证据直接复用到新计算源码。
