# WebShell 真实试验故障、证据和标注接续

本记录区分真实 GPU 尝试、CPU 修复、原标注任务与主训练。时间均为北京时间，除非明确写 UTC。**本次 vLLM 真实试验失败，没有产生可验收的原生转写结果；不能据此报告提速、文字一致或字界质量通过。** 原标注任务在本次试验中被中断，原因是维护者没有在第二个 CUDA 进程启动前核对旧父进程的持续独占约束。这是本次操作错误，不能解释成平台随机失败。

## 实际发生了什么

用户要求在八卡标注任务的真实机器上用 WebShell 测试。现场核到八张 A800 各运行一个原标注 worker，每卡约占 14 GiB。维护者错误地把“进程归属已知、显存有余量”当成允许同卡测试的条件，还制作了单独的共享许可描述。这个描述不能覆盖原父进程持有的物理资源锁和持续检查协议。

试验只选择三训练域各两个完整原件，共六个，合计 23.8764375 秒，没有再次按任意时长裁片。整原件输入并不证明自然句或完整字边界已经人工验收。没有将诊断样本投入生产。模型和原声输入保存摘要；没有调用外部模型 API。

| 时刻或阶段 | 实际结果 | 能证明什么 |
|---|---|---|
| 准备模型输入 | 完整模型没有 `tokenizer.json`，初次准备拒绝；修后从真实处理器文件读取并交叉核 EOS，六条输入生成 | 输入准备兼容了该模型目录；不证明 GPU 推理 |
| 第一次真实构造 | 安装的 vLLM 0.19.1 对 UUID 形式的 `CUDA_VISIBLE_DEVICES` 作整数转换，构造失败 | 该环境下 UUID 可见卡方式不兼容；无原生结果 |
| 第二次真实构造，15:16:49 | 在核实 NVML index、UUID 和 PCI 映射后改为数字卡号，EngineCore 开始初始化 | 引擎子进程开始启动；尚不能证明推理成功 |
| 15:16:50.401693 | 原监控在同一 GPU 记录两个 compute context | 直接对应原父进程的独占拒绝条件 |
| 15:17:05 | 原平台标注任务 `t-20261025054739-4kzhp` 及唯一实例失败 | 原标注八 worker 已中断；不能写成试验对现有任务无影响 |

原 `failure.json` 的实际调用顺序为 `gpu_launch.py → challenge.monitor(snapshot) → gpu_challenge.py`，拒绝原因是 `multiple compute rows on target UUID; refuse unknown process`。原父进程随后按其精确 worker 身份清理八个自有 worker。完整异常、两次部署版本、输入摘要、监控冲突行和平台终态已保存在本机私有审阅目录；没有覆盖旧失败版本，也没有修改旧冻结清单。

## 已做的代码修复及限制

`prepare_vllm_live_inputs.py`保留完整原声和实际 PCM 身份，核 ASR 模型文件身份、EOS 和本机依赖，输出有限试验输入。它没有核定位模型来源。它的 CPU 测试包括真实小 WAV 和两种 EOS 文件布局，不启动模型。

`vllm_live_probe.py`已经拒绝旧共享许可；任何已有 compute PID 都不能以“已知进程”获准。独占准备要求两次空闲快照、明确的物理 UUID 与原协作锁身份。不能用新建临时锁代替原资源协议。

独立复审进一步用一个纯 CPU 子进程重现了异常退出缺口：旧助手从 factory 抛错返回时，子进程仍存活，而锁已能被其他文件描述符重新取得。只等待进程组 leader 退出也不能证明 EngineCore 已退出。**完整 supervisor、后代和 CUDA context 归还机制尚未实现，因此当前维护版明确关闭真实模型构造。** 缺少任一阶段缓存就拒绝；生产或 pilot 不能通过注入自定义 factory 绕过。只保留检查、CPU 假引擎和完整阶段缓存零模型调用恢复。不能把这项禁用写成生命周期算法已修好。

三十项助手测试、十九项原适配器测试及独立复核通过。曾有两套 CPU 测试争用同一假 UUID 临时锁，已用每个 fixture 独立临时目录修正；失败输出保留。所有这些都是 CPU 证据，不是 GPU 的速度、质量或异常清理验收。

新增的 `resume_existing_annotation.py`只处理已明确终止的同合同任务。默认只读检查；执行需原声明、原部署协议、完整冻结源码、原解释器、真实终态与无竞争后继的观察、原锁及旧部分片身份全部相符。它保留原一次声明，另建永久 `resume-attempt2` 声明，使用原队列和标签，仅新增资源记录。原 gate 和挂载脚本仍按实际旧 v2 参数执行，不冒充现行 v3。不能直接重跑原 fresh-only shell、删除声明、手改租约或改运行目录躲开原限制。详细接口见[同合同标注任务接续](../../tools/open_annotation/同合同标注任务接续.md)。

独立审查曾发现 gate 后源码被改仍可调用 GPU 的缺口；已经修复为门后及 GPU 入口前重核整个冻结包、成员、原启动器、检查脚本、解释器、共享别名和语义锁 inode。实际二十一项恢复 CPU 用例通过，三种检查中篡改源码的反例均为零 GPU 调用。

### 不能掩盖的设备号差异

同一共享原音在旧标注记录中的 device 为 2097194，在开发容器中为 1048736，在另一个云容器中为 54；已核样本的 inode、字节数、mtime、ctime 相同。设备号具有节点和挂载环境属性，但旧冻结 worker 明确以完整 stat 判断已发布音频是否改变。

所以本次严格接续**继续比较完整 stat**。开发机默认预检已实际按上述设备号差异拒绝，没有创建恢复声明或启动 GPU。不能删除 device、伪造旧 stat、改旧侧车或先算到尾部再处理。

实际只提交了一个严格接续任务 `t-20261027155513-hbql2`，名称 `redimnet2-ultra-3train-resume-8a800-p6-20261027-v1`。已回读单机八张 A800、优先级 6、原镜像和两项挂载、720 小时保护上限、重试关闭。入口命令通过编辑器全选复制回读，2,453 字节与已审阅原文逐字一致。新容器在 15:56:31 实际执行 `run → inspect → partial_snapshot → retained_for_resume` 时拒绝：**actual device=79，expected device=2097194**；同一拒绝行的 inode、字节数、mtime 和 ctime 相同。平台实例 15:56:29 启动、15:56:46 失败。完整异常已通过平台日志终端的全选复制操作保存本机。

该拒绝发生在 `evidence.mkdir`、接续声明和原 GPU 入口之前，不是模型计算失败。**当前标注仍未恢复，不能把任务创建成功或保护检查拒绝算作恢复通过。** 不重复提交同一入口碰运气。平台截图接口连续超时，保留了实际任务详情文本和日志复制原文，不制作替代截图冒充平台画面。

16:05:07 的共享存储只读复核再次核到 1,158,718 已封账来源；原声明摘要不变，原冻结包及全部成员摘要相同。`resume-attempt2.claim.json`、`resources-attempt2` 和控制器执行目录均不存在，旧父锁可用只读文件描述符独占取得。这些事实与“在声明和 GPU 前拒绝”一致，没有清空队列或重跑旧结果。

跨节点备用方案应另建有明确内容校验账本的后继协议：保留旧 producer 与原字节，逐源核实际音频内容 SHA 和稳定前后 stat，仅用新队列处理真正缺失来源，再核联合全库不重不漏。原合同同时固定 `sidecar.py` 和 `worker.py` 的源码摘要，因此不能改读取逻辑后继续声称是同一冻结合同；新实现与旧结果的联合读取须有新的明确身份和准入。该备用方案还没有实现或验收。

## 统一任务名称前缀

用户随后明确要求所有任务名以 `zhounan_` 开头。控制台的“更多→编辑”支持原地修改名称，已经逐项给本轮查到的13个 ReDimNet2 云任务添加前缀，并按同一任务ID回读；没有为了改名复制或重启任务。列表采用虚拟滚动，末尾两项另开详情核实，不能因当前DOM只渲染11项就误记漏改。

因此本页此前出现的原名字是**提交时名称**。主训练当前显示名是 `zhounan_redimnet2-b6-ptn-r47-capture-8a800-p6-20261026-v2`；本次严格接续任务当前显示名是 `zhounan_redimnet2-ultra-3train-resume-8a800-p6-20261027-v1`。完整13项前后名称与ID映射保存在私有审阅目录，不改旧冻结包或历史日志。

未来标注准入描述、平台准备文件及PTN构建收据均加入同前缀约束。CLI非法名前缀会早于读取输入或创建输出拒绝；历史缺名称字段的描述仍可读，只为未来表单给建议。命名辅助模块不提供平台提交能力，不修改模型运行合同。

独立复审实际发现新冻结包漏带命名辅助模块，导致两个表单准备 CLI 在仓库之外导入失败。已经修复为新冻结包显式携带同字节模块并纳入包摘要，重复冻结也取自身受控副本；不会优先加载父目录同名模块。实际完成“首次冻结→父目录放同名干扰模块→再次冻结→两个版本各两个外部目录 CLI 帮助”的 CPU 复验。模型语义模块集合不变，原合同和旧冻结副本不改。失败和修复后的输出分别保留。
