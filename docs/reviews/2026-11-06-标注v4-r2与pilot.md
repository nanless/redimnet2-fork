## 根因三段证据

1. **原件本身退化**：CN-Celeb2 `id10052/live_broadcast-04-007.flac` 只有 **442 B / 16 kHz / 171 帧 = 0.0106875 s**。
2. **窗口规划把它整段当窗口**：`plan_windows()` 只保证窗口覆盖 `[start,stop)`，没有最小长度下限，于是 171 帧文件产出 1 个 171 帧窗口。
3. **特征提取前置条件被撞破**：`torch.stft`（`n_fft=400`、`center=True` 两侧各 pad 200）要求输入 ≥201 帧，171 < 201 → `RuntimeError: padding (200,200) at dimension 2 of input [1,1,171]`。

旁证：`…/labels/…/cnceleb2/id10052/` 下 04-003/005/006/008 齐、**独缺 04-007**——只有它没有侧车。

判失败的门是 `gpu_launch.py` 的 `need(state['phase'] in ('draining','exited') and rc == 0, 'worker exited before ACK or failed: …')`。`terminal_ready.json` 只属审计材料，不是判据；`failure.json` 里那句 "worker exited before ACK" 是**父进程的判决措辞**，真因只在 worker 日志尾部。合同本身写着 `GPU_error_policy: abort_own_attempt_no_silent_batch_reduction`，所以"一个 worker 崩就整轮停"是设计如此，不是误判。

## 准入阻断（决定性）

修短窗要改 `worker.py`，但 `worker.py` 在合同的 `engine_source_files`（16 项）里，而 `check_formal_bundle()` 第 214–215 行对引擎源是**无条件等式**：

```
Refused: native formal bundle changed actual tested math ENGINE source: worker.py
```

`REVIEWABLE_CONTROL` 的白名单只有 4 个 CPU helper（`native_batch_admission.py`、`native_batch_readback.py`、`native_batch_queue_handoff.py`、`bounded_speed_runtime.py`），且**要引擎源全等之后**才轮到它，所以没有任何 review pin 能豁免引擎源改动。结论：**改它必须用新包重跑 native pilot 出新 admission**。

若只改 `gpu_launch.py` / 新增模块（非引擎源），换包会先撞另一道门：

```
Refused: native formal GPU executable bundle must equal actual selected pilot bundle
```

两道门实测都在，前者是后者的上游。改合同把 `worker.py` 移出引擎集合则会让 `version` 变化，4.4M 已有侧车树身份失效——不可取。

## `st_dev` 的语义修正

| 位置 | 实测 device |
|---|---|
| dev 节点（三样本：孤儿源 / 已提交源 / 组共享只读文件） | 全部 **57** |
| 八卡容器侧车里记录的 `stat_after.device` | **2097190** |

device 由挂载命名空间决定，不反映文件是否被改过。因此**排除 device**、而 `inode/bytes/mtime_ns/ctime_ns`（外加已存的 `file_sha256`/`pcm_sha256`）仍逐项严格相等，少一项即拒；device 漂移只落 `device_relaxed=true` 的回执字段与一行日志。侧车本身只能记录 producer 侧 device，consumer 侧 device 只能进回执与日志——这是物理边界，不是实现取舍。

由此也说明**不能用 dev 读数推断云端**：pilot 在 dev 上量到 57，只是 dev 的 57。

## cohort 归档（改名是必要条件）

8 个在途分片（24197、24199–24205）的组目录已 rename 到 `.native_torch_cohorts.attempt1-crashed/`：**101 个组目录**，`MANIFEST.json` 记录 old/new 路径、新旧 producer、identity sha 与回滚命令；**未删除任何文件**。

不改名就续跑的失败模式（二选一，取决于包是否变更）：`stored fixed plan identity differs`，或 `no partial retry`（`plan.json` 崩溃前已写盘，护栏少给一行就会撞）。所以改名不是"清理现场"，是续跑的必要条件。

## 不能宣称的

- **标注仍未恢复**；pilot 结束 ≠ 已有新 admission ≠ 续跑已开始。
- pilot 的加速比与 512 恢复零新计算要按产物字段核（`cold_end_to_end_speed_ratio>1`、`new_ASR_calls==new_FA_calls==0`、`sidecar_cache_hits==512`、`sidecars_committed==0`），本文不给这些数字。
- 52.64% 只是"已完成下界"，`unknown` 占 3,116,787 不代表"错误"，也不代表可训练产量。
- device 语义修正不放宽 `inode/bytes/mtime/ctime`；任何一项变化仍必须拒。
