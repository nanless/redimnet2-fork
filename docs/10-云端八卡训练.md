# 在火山引擎上用 8 张卡训练 b6 混合数据模型

这份文档面向要在一台 8 卡机器上把训练跑起来的同学。它讲清楚四件事：
要训练的是什么、在火山引擎机器学习平台上敲哪条命令、脚本里每个环境变量是什么意思、
以及训练过程中怎么判断进展、被抢占之后怎么接着跑。

## 0. 先看这里

要复现的官方权重是 `b6-vb2+vox2+cnc2_v0-lm.pt`。在 VoxCeleb1-O 试验列表上，
官方这个权重的等错误率（EER）是 **0.255**（本仓库的表格按百分数写，也就是
**0.255 个百分点**，越小越好）。它对应的主训练权重 `b6-vb2+vox2+cnc2_v0-ptn.pt`
是 0.420。这两个数字在本仓库的 `checkpoints/reports/02-VoxCeleb1结果.md` 里有全表。

训练分两个阶段，必须按顺序跑：

| 阶段 | 配置文件名 | 训练清单 | 每卡批大小 | 轮数 |
|------|-----------|----------|-----------|------|
| 主训练阶段（PTN） | `applications/speaker_rec/examples/vb2_vox2_cnc2/recipes/redimnet2/b6/ptn.yaml` | `mix_join`，11,521,178 句 | 96 | 120 |
| 大间隔微调阶段（LM） | `.../recipes/redimnet2/b6/lm.yaml` | `mix_join_lm`，5,021,010 句 | 48 | 1 |

两个阶段各有一个启动脚本，都放在 `applications/speaker_rec/scripts/cloud/`：

- `train_b6_mix_cloud_8gpu.sh`：主脚本，两个阶段共用，用 `STAGE` 区分。
- `train_b6_mix_cloud_8gpu_lm.sh`：大间隔微调的入口，只是把 `STAGE` 固定成 `lm` 再转给主脚本。

脚本**不会改配方文件**。它把配方读进来，把里面写死的路径替换成你给的 `DATA_ROOT`，
再写出一份新的完整配置交给 `launch.sh`。原因见第 4 节。

## 1. 在火山引擎上要敲的命令

先把两件事准备好：

1. 把本仓库放进镜像或挂进容器，记住仓库根目录（下面写成 `/workspace/redimnet2-fork`，
   按实际路径替换）。
2. 把训练数据放到掉电不丢的存储上（例如 vePFS），结果目录也放在同一块存储上。
   结果目录必须能跨实例重启保留，否则被抢占后没法接着跑。

主训练（8 卡）：

```bash
cd /workspace/redimnet2-fork
NUM_GPUS=8 \
DATA_ROOT=/mnt/vepfs/wespeaker_data \
EXP_DIR=/mnt/vepfs/exp/b6_cloud/ptn \
applications/speaker_rec/scripts/cloud/train_b6_mix_cloud_8gpu.sh
```

大间隔微调（8 卡，等主训练跑完之后再跑）：

```bash
cd /workspace/redimnet2-fork
NUM_GPUS=8 \
DATA_ROOT=/mnt/vepfs/wespeaker_data \
EXP_DIR=/mnt/vepfs/exp/b6_cloud/lm \
PTN_EXP_DIR=/mnt/vepfs/exp/b6_cloud/ptn \
applications/speaker_rec/scripts/cloud/train_b6_mix_cloud_8gpu_lm.sh
```

大间隔微调会自动从 `PTN_EXP_DIR` 里按修改时间找最新的 `models/model_<N>.pt`
当起点，并把同目录的 `spk2id.json` 拿来把分类头重新拼起来。不需要手动填哪个轮次。

`DATA_ROOT` 下面要有这些内容（目录名与配方里写的一致）：

```text
$DATA_ROOT/vox2_vb2_cnc2_v0/mix_join/data.list        # 主训练样本清单
$DATA_ROOT/vox2_vb2_cnc2_v0/mix_join/utt2spk          # 主训练：哪句属于哪个说话人
$DATA_ROOT/vox2_vb2_cnc2_v0/mix_join_lm/data.list     # 大间隔微调样本清单
$DATA_ROOT/vox2_vb2_cnc2_v0/mix_join_lm/utt2spk
$DATA_ROOT/vox1-test/veri_test2.txt                   # VoxCeleb1-O 试验列表
$DATA_ROOT/vox1-test/wav/                             # 上面列表引用到的音频
$DATA_ROOT/raw/musan/music/                           # 增强：音乐
$DATA_ROOT/raw/musan/noise/                           # 增强：噪声
$DATA_ROOT/raw/musan/speech/                          # 增强：人声
$DATA_ROOT/raw/rirs/simulated_rirs/                   # 增强：模拟房间脉冲
```

如果云端就把共享盘挂在配方原来写的路径上（`/root/group-shared/voiceprint/data/wespeaker_data`），
那么不用设 `DATA_ROOT`，默认值就是它，脚本不会做任何改写。

## 2. 每个环境变量是什么意思

主脚本里所有路径都通过环境变量传入，下面每一项都有默认值。

| 变量 | 默认值 | 作用 |
|------|--------|------|
| `STAGE` | `ptn` | 跑哪个阶段，只能是 `ptn` 或 `lm`。用 `train_b6_mix_cloud_8gpu_lm.sh` 时会自动设成 `lm`。 |
| `REPO_ROOT` | 由脚本所在位置往上推四级得到仓库根 | 仓库根目录。一般不用设。 |
| `RECIPE` | 按 `STAGE` 选 b6 的 `ptn.yaml` 或 `lm.yaml` | 用哪份配方。脚本只读它，不改它。 |
| `DATA_ROOT` | `/root/group-shared/voiceprint/data/wespeaker_data` | 云端数据根目录。配方里所有以 `RECIPE_DATA_PREFIX` 开头的路径都会改成它下面的同名子路径。 |
| `RECIPE_DATA_PREFIX` | `/root/group-shared/voiceprint/data/wespeaker_data` | 配方里写死的旧前缀。换成别的配方时，用这个变量告诉脚本要替换什么。 |
| `EXP_DIR` | 主训练 `exp/vox2_vb2_cnc2/b6_cloud/ptn`，大间隔微调 `.../b6_cloud/lm` | 训练结果目录。权重、`train.log`、`val_log.csv`、`spk2id.json`、生成的配置都写在这里。**续训靠它，必须放在掉电不丢的存储上。** |
| `NUM_GPUS` | `8` | 用几张卡。脚本会检查 torch 看得见的卡数不少于它。 |
| `PYTHON_BIN` | 留空 | 用哪个 Python 解释器。留空时按 `launch.sh` 的规则找 conda 环境 `redimnet2`。也可以用 `REDIMNET2_ENV` 指定环境名、`REDIMNET2_PYTHON` 指定解释器路径（这两个由 `launch.sh` 识别）。 |
| `MASTER_PORT` | 留空 | 多卡通信端口。留空时 `launch.sh` 自动挑一个空闲端口。单机训练不用设；将来做多机训练必须显式指定，且各节点用同一个值。 |
| `EXPECT_TRAIN_LINES` | 主训练 `11521178`，大间隔微调 `5021010` | 期望的 `data.list` 行数。换成别的数据子集时改这里；设成 `0` 表示只查文件在不在、不比对行数。 |
| `CKPT_SIZE_MB` | `650` | 估算磁盘用量时，一个 b6 权重按多少 MB 算。 |
| `DISK_HEADROOM_GB` | `20` | 磁盘预算里除权重之外额外留的余量。 |
| `NUM_EPOCHS` | 留空（用配方里的值） | 覆盖配方里的 `num_epochs`。想多跑几轮时改这里，脚本会写进生成的配置。 |
| `SAMPLE_NUM_PER_EPOCH` | 留空（用配方里的值，配方是 `0`，表示用整个训练集） | 覆盖每轮用多少句。小样测试时把它调小，几轮就结束。 |
| `BATCH_SIZE` | 留空（用配方里的值） | 覆盖每卡批大小。 |
| `SAVE_EPOCH_INTERVAL` | 留空（用配方里的值，配方是 `1`） | 覆盖存权重的间隔。**这是控制磁盘占用的主要手段**：设成 `5` 就大约每 5 轮留一个权重。 |
| `VOX1_TEST_DIR` | 留空（用配方里的值） | 覆盖 VoxCeleb1 验证目录。想用别的试验列表时设它。 |
| `PTN_EXP_DIR` | `exp/vox2_vb2_cnc2/b6_cloud/ptn` | 只在 `STAGE=lm` 时用：从哪个主训练结果目录找起点权重。 |
| `MODEL_CKPT` | 留空 | 只在 `STAGE=lm` 时用：直接指定某个权重文件当起点，优先级高于 `PTN_EXP_DIR` 的自动查找。 |

下面这些开关用来在小样测试时跳过某一项开训前检查，值都是 `1` 表示跳过：

| 变量 | 跳过的检查 |
|------|-----------|
| `SKIP_PREFLIGHT` | 一次跳过下面全部检查 |
| `SKIP_DATA_LIST_CHECK` | 训练样本清单是否存在、行数是否等于 `EXPECT_TRAIN_LINES` |
| `SKIP_UTT2SPK_CHECK` | `utt2spk` 行数是否等于 `data.list` 行数 |
| `SKIP_AUG_CHECK` | 四个增强音频目录是否存在、里面有没有 `.wav` |
| `SKIP_VOX1_CHECK` | VoxCeleb1 试验列表与音频目录是否存在 |
| `SKIP_GPU_CHECK` | torch 看得见的卡数是否不少于 `NUM_GPUS` |
| `SKIP_DISK_CHECK` | 结果目录所在磁盘剩余空间是否够放权重 |
| `SKIP_LOCK_CHECK` | 同一个 `EXP_DIR` 是否已经有训练在跑 |

## 3. 需要什么镜像和依赖

训练要跑在本仓库自己的环境里，镜像里需要有：

- Python 3.10 到 3.12（`pyproject.toml` 的要求），实测用的是 3.11。
- **PyTorch 2.x 和同版本的 torchaudio**。`launch.sh` 会检查 torch 版本不低于 2.0，
  低于 2.0 会直接停下并说明原因。实测环境是 torch 2.4.0 + cu124。
- 训练栈的其余依赖：`numpy`、`scipy`、`pandas`、`pyyaml`、`soundfile`、`resampy`、
  `lmdb`、`fire`、`tableprint`、`tqdm`、`scikit-learn`、`pyarrow`。
  完整列表在根目录 `requirements.txt` 的「Training only」一段，也可以按
  `applications/speaker_rec/pyproject.toml` 装。

如果镜像里的 conda 环境不叫 `redimnet2`，用 `PYTHON_BIN=/path/to/python` 指定解释器，
或者用 `REDIMNET2_ENV=<环境名>`。脚本自己只用这个解释器做三件事：读 YAML 生成配置、
查可见卡数、跑 `launch.sh`；真正训练时 `launch.sh` 也用它。

显卡驱动和 CUDA 要能让 torch 看到全部 8 张卡。上机第一件事可以跑
`python -c "import torch; print(torch.cuda.device_count())"` 确认看到的是 8。

## 4. 路径改写是怎么做的，为什么不直接改配方

配方里的路径是写死的。以 `b6/ptn.yaml` 为例，涉及这些：

- `train_data` 与 `train_label`：`.../vox2_vb2_cnc2_v0/mix_join/` 下的两张表；
- `validation.vox1`：`.../vox1-test`；
- `exp_dir`：结果目录；
- **四个 `dataset_dir`**：藏在 `dataset_args.aug_setup` 这棵「列表套字典」的树里，
  分别是 `raw/musan/music`、`raw/musan/noise`、`raw/musan/speech`、`raw/rirs/simulated_rirs`。

它们都以 `/root/group-shared/voiceprint/data/wespeaker_data` 开头。

`launch.sh` 支持命令行上的 `--config_overrides <文件>`，它是按 YAML 合并的，
而 YAML 合并遇到列表是**整段替换**。那四个增强路径正好在列表里面，
所以没法只改这四条。脚本采用的稳妥做法是：

1. 用 Python 读出配方 YAML；
2. 递归遍历整份配置，把所有以 `RECIPE_DATA_PREFIX` 开头的字符串替换成
   `DATA_ROOT` 下面的同名子路径（前缀本身相同就原样不动）；
3. 把 `exp_dir` 改成 `EXP_DIR`；大间隔微调阶段再把 `model_ckpt` 指向主训练的结果、
   `spk2id_map_path` 指向主训练目录里的 `spk2id.json`；
4. 把 `NUM_EPOCHS`、`SAMPLE_NUM_PER_EPOCH`、`BATCH_SIZE`、`SAVE_EPOCH_INTERVAL`、
   `VOX1_TEST_DIR` 这几项（如果设了）写进配置；
5. 把结果写到 `$EXP_DIR/cloud_config_<阶段>.yaml`，再交给
   `launch.sh <这份配置> <NUM_GPUS>`。`launch.sh` 会把 `--config` 原样传给 `train.py`。

脚本还会检查有没有漏改：如果新配置里还残留旧前缀开头的路径，直接停下报错，
不会带着半改的配置去训练。写完之后会把实际用到的关键路径都打印成 `TRAIN_PATHS` 行，
上机时可以照着核对一遍。

生成的配置文件名是 `cloud_config_<阶段>.yaml`，和训练代码自己写的
`$EXP_DIR/config.yaml` 不冲突（后者是 `train.py` 每次启动时把当前配置再存一份）。

有一点要说明：生成的配置是把配方重新读出来再写一遍得到的，
所以配方文件里的**注释不会保留**。配置的键值内容和配方一致，
只有上面说的那几条路径被改掉。本机验证时做过逐键比较：
除 7 条路径和 `exp_dir` 外，生成配置与配方完全相同。

## 5. 被抢占之后怎么接着跑

这是脚本在云端最重要的一点：**同一条命令重跑就会接着上次继续，不会重头再来。**

依据是训练代码 `train.py` 已有的行为（不是脚本新加的）：

- 启动时扫描 `$EXP_DIR/models/model_<N>.pt`，取**修改时间最新**的那个，
  令 `start_epoch = N + 1`；
- 训练循环是 `for epoch in range(start_epoch, num_epochs + 1)`，
  已经跑过的轮次不会再跑；
- 已经跑满时（最新轮次不小于 `num_epochs`）什么都不做，正常退出，退出码 0；
- 优化器的动量、混合精度的缩放系数也跟着权重一起存在 `model_<N>.pt` 里，
  续训时会一起读回来。

所以实例被抢占后，只要 `EXP_DIR` 还在，重新拉起同一条命令即可。
脚本为此只做两件事：不删除 `EXP_DIR`；不传 `--checkpoint` 去钉死某个权重文件。

判断这次是从第几轮开始的，看脚本打印的 `TRAIN_START` 行：

```text
TRAIN_START epoch=37 num_epochs=120 prev_ckpt=/mnt/vepfs/exp/b6_cloud/ptn/models/model_36.pt
```

`epoch=37` 就说明前 36 轮已经跑过、这次从第 37 轮继续。

另外，同一个 `EXP_DIR` 不允许同时跑两个训练。脚本会在 `EXP_DIR` 里加一把
`flock` 锁（并写一个 PID 文件）；已经有一个在跑时，第二次启动会直接拒绝并说明占用进程，
不会两个进程同时写同一批权重。`SKIP_LOCK_CHECK=1` 可以跳过这项检查，
但正常使用不要跳。

## 6. 训练过程中怎么看进展

脚本打印的行都带固定前缀，平台外层可以直接用 `grep` 抓。

```text
TRAIN_REWRITE stage=ptn prefix=... data_root=... changed=7 leftover=0
TRAIN_REWRITE old=... new=...
TRAIN_PATHS config=... exp_dir=... train_data=... train_label=... vox1=...
TRAIN_PATHS aug_1=... aug_2=... aug_3=... aug_4=...
TRAIN_CHECK name=data_list status=ok data_list_lines=11521178 expected=11521178
TRAIN_CHECK name=utt2spk status=ok ...
TRAIN_CHECK name=aug_dir status=ok index=4 wavs=60000 dir=...
TRAIN_CHECK name=vox1 status=ok dir=... trials=37611
TRAIN_CHECK name=gpu status=ok visible=8 requested=8
TRAIN_DISK required_gb=97 available_gb=500 n_ckpt=120 ckpt_size_mb=650 save_epoch_interval=1 num_epochs=120 headroom_gb=20
TRAIN_CHECK name=disk status=ok ...
TRAIN_BEGIN stage=ptn recipe=... exp_dir=... num_gpus=8 python=...
TRAIN_START epoch=1 num_epochs=120 prev_ckpt=none
TRAIN_LOG path=/mnt/vepfs/exp/b6_cloud/ptn/cloud_launch_ptn.log
TRAIN_CKPT path=/mnt/vepfs/exp/b6_cloud/ptn/models/model_120.pt epoch=120
TRAIN_END status=ok reason=finished exit=0 last_epoch=120
```

（`TRAIN_BEGIN` 是在开训前检查都通过、准备启动训练时才打印的，
所以它排在各项检查后面。平台侧抓 `TRAIN_START`、`TRAIN_CKPT`、`TRAIN_END` 就够了。）

失败时会是这样，并且退出码非零、日志末尾 60 行会打到标准错误：

```text
TRAIN_END status=failed reason=training_failed exit=1
```

常见的 `reason` 取值和含义：

| reason | 含义 |
|--------|------|
| `data_list_missing` | `data.list` 或 `utt2spk` 不在 `DATA_ROOT` 下面 |
| `data_list_count_mismatch` | `data.list` 行数和 `EXPECT_TRAIN_LINES` 不一致 |
| `utt2spk_count_mismatch` | `utt2spk` 与 `data.list` 行数不一致 |
| `aug_dir_missing` / `aug_dir_empty` | 四个增强目录有一个不在或里面没有 `.wav` |
| `vox1_missing` / `vox1_protocol_missing` / `vox1_wav_missing` | VoxCeleb1 验证数据不全 |
| `gpu_count_too_low` | torch 看得见的卡数少于 `NUM_GPUS` |
| `disk_too_low` | 结果目录剩余空间不够放权重 |
| `exp_dir_locked` | 同一个 `EXP_DIR` 已经有训练在跑 |
| `ptn_ckpt_missing` / `ptn_spk2id_missing` | 大间隔微调找不到主训练的权重或 `spk2id.json` |
| `config_generation_failed` | 读配方或生成配置失败，具体原因在 Python 报错里 |
| `training_failed` | 训练本身非零退出，末尾日志会打出来 |
| `unexpected_error` | 脚本没预料到的失败，带出错行号 |

训练本身的逐步进度在 `$EXP_DIR/cloud_launch_<阶段>.log`（脚本用 `tee` 把
`launch.sh` 的输出同时写到那里）和 `$EXP_DIR/train.log`（训练代码自己写的）里。
每个 epoch 的验证结果累加在 `$EXP_DIR/val_log.csv`。

## 7. 磁盘与时间预算

**磁盘。** b6 每个权重约 650 MB。本机小样里实测过：模型参数 81,422,833 个，
权重本身 326 MB，加上 SGD 动量缓冲后整份 `model_<N>.pt` 是 650.8 MB，
和 650 MB 这个估计一致。配方里 `save_epoch_interval: 1`，
按训练代码的保存逻辑，这个值等于 1 时**每一轮的权重都会留下**（不删旧的）。
主训练 120 轮就是：

```text
120 × 650 MB ≈ 78 GB
```

脚本在开训前会按这个算式估一遍（`n_ckpt × CKPT_SIZE_MB + DISK_HEADROOM_GB`），
剩余空间不够就停下并给出提示。想省磁盘，把 `SAVE_EPOCH_INTERVAL` 调大：

| `SAVE_EPOCH_INTERVAL` | 大约留下多少个权重 | 大约占多少磁盘 |
|-----------------------|-------------------|----------------|
| 1（配方默认） | 120 | 约 78 GB |
| 5 | 约 34（每 5 轮一个，另加最后 10 轮） | 约 22 GB |
| 10 | 约 22 | 约 14 GB |

注意：调大之后续训能回到的最近位置会变粗（最多退回到上一个留下的权重）。
大间隔微调只有 1 轮，一个权重 650 MB，可以忽略。

**时间。** 本机 2 张 A800 上实测：b6、每卡批大小 96（两卡合起来等效批大小 192），
一步 0.419 秒，约合每秒 458 句。主训练清单 11,521,178 句：

```text
2 卡：每轮 11521178 ÷ 192 ≈ 60006 步，× 0.419 秒 ≈ 6.98 小时
      120 轮 ≈ 838 小时 ≈ 35 天
8 卡：每轮步数变成 1/4，如果速度能线性提升，120 轮 ≈ 8.75 天
```

**这里必须说清假设**：8 卡的数字是从 2 卡实测速度按「卡数翻四倍、速度接近翻四倍」
推算的，本机只有 2 张卡，**没有在 8 卡上实测过**。多卡数据并行通常不会完全线性，
所以现实区间取 **9 到 11 天**（效率约 0.8 到 1.0）；如果效率掉到 0.7，会接近 12.5 天。
这个估算不含首次 `torch.compile` 的开销（实测第一步要多花约 220 秒，
只在每次进程启动后的第一批发生）。

大间隔微调只有 1 轮、清单 5,021,010 句、每卡批大小 48，按同样口径
每卡每秒的吞吐与主训练同量级，8 卡大约半天以内。**这一项没有实测过，只是按主训练的
吞吐推算。**

   动量项（提交 `619dad0`，不是本次脚本改动引入的）。也就是说，
   大间隔微调阶段要求这个提交在代码里；更早的检出跑不通。
7. **`SAVE_EPOCH_INTERVAL` 调大后磁盘占用的估算只是近似。** 第 7 节的
   「大约留下多少个权重」是按训练代码的删除条件推出来的，没有实测过
   `SAVE_EPOCH_INTERVAL=5` 或 `10` 跑完之后的实际文件数。
8. **磁盘检查只看结果目录所在的那一块文件系统。** 如果权重和训练数据不在同一块盘上，
   脚本只检查结果目录那块，不会去检查数据盘。

## 11. 和官方配方的一致性：哪些会变、哪些不会变

### 11.1 脚本只改路径，超参一处都不动（已逐键核对）

不设任何超参环境变量时，把脚本生成的配置和原配方**逐键对比**，只差 8 处，**全是路径**：

```text
dataset_args.aug_setup.augmentors[0].augmentors[0].dataset_dir   (MUSAN music)
dataset_args.aug_setup.augmentors[0].augmentors[1].dataset_dir   (MUSAN noise)
dataset_args.aug_setup.augmentors[0].augmentors[2].dataset_dir   (MUSAN speech)
dataset_args.aug_setup.augmentors[1].dataset_dir                 (RIRS)
train_data
train_label
validation.vox1
exp_dir
```

超参（`num_epochs`、`batch_size`、`initial_lr`、`aug_setup` 的各个概率、模型结构等）
**一处都没动**。所以八卡上跑的就是配方原样。

### 11.2 万一超参被环境变量覆盖，日志里会喊出来

脚本允许用 `NUM_EPOCHS`、`SAMPLE_NUM_PER_EPOCH`、`BATCH_SIZE`、`SAVE_EPOCH_INTERVAL`
覆盖配方，**这几个是给冒烟测试用的**。一旦设了，会打印：

```text
TRAIN_WARN 超参被环境变量覆盖，本次已偏离配方: num_epochs = 120 -> 4
TRAIN_WARN 共 2 处超参偏离配方；复现官方结果请不要设 NUM_EPOCHS / ...
```

**要复现官方结果，这四个变量一个都不要设。** 有 `TRAIN_WARN` 就说明这次跑的不是官方那组超参。

### 11.3 卡数会改变实际学习率（这是配方自己的行为，不是我们改的）

配方里写的是 `initial_lr: 0.06`，而 `lr_scaling` 走的是默认值 `legacy`：
它会把 `scale_ratio = 卡数 × 每卡批大小 / 64` **乘到整个训练过程上**。
b6 的 `batch_size` 是 96，于是：

| 卡数 | scale_ratio | 实际峰值学习率 |
|------|-------------|----------------|
| 1 | 1.50 | 0.090 |
| 2 | 3.00 | 0.180 |
| 4 | 6.00 | 0.360 |
| **8** | **12.00** | **0.720** |

（2 卡那一行是实跑日志里 `[lr]` 那行打印出来的，不是估算的。）

**所以 2 卡小样和 8 卡正式训练不是同一组超参。**
2 卡小样验证的是**流程能不能跑通**（路径对不对、续训接不接得上、存档写不写得出），
**不能用来判断训练结果好不好** —— 学习率差了 4 倍。要复现官方结果，只能以 8 卡那次为准。

### 11.4 还没确认的事

官方那批权重是在几张卡上训的，配方里没有记录。

- 如果官方就是 8 卡，那么 0.72 这个实际学习率就是对的；
- 如果官方用的是别的卡数，那"照配方原样跑"得到的学习率和官方**仍然不同**。

这一点和配方里 epoch 数的矛盾（`ptn.yaml` 写 120 轮、`exp_dir` 名写 `100ep`、
`lm.yaml` 的 `model_ckpt` 指向 `model_115.pt`）一样，**都属于尚未确认的信息**，
不能靠猜，需要找到官方训练记录才能定。

## 12. 复现官方结果的专用实验

第 11 节说明：照配方原样跑**不能**逐位复现官方结果。这一节给出**能**复现的那份实验。

### 12.1 用哪份配方

```text
applications/speaker_rec/examples/vb2_vox2_cnc2/recipes/redimnet2/b6/official_repro_ptn.yaml
applications/speaker_rec/examples/vb2_vox2_cnc2/recipes/redimnet2/b6/official_repro_lm.yaml
```

它们和同目录的 `ptn.yaml` / `lm.yaml` 只差两处，其余一字不改（已逐行核对）：

```yaml
compile_backbone: null          # 关掉编译
dataset_args:
  legacy_aug: true              # 退回官方增强行为
```

### 12.2 为什么是这两处

**`compile_backbone: null`** —— 官方配方开着 `torch.compile`。实测同一棵树、同一份配置：

| | 连跑两次的结果 |
|---|---|
| 开着编译 | **不同**：673/747 个权重张量，最大绝对差 0.63 |
| 关掉编译 | **逐位一致**：0/747，最大绝对差 0.000e+00 |

开着编译时训练**连自己都不能复现自己**，所以逐位对比必须先关掉。

**`legacy_aug: true`** —— 本仓库修过 `augs.py` 两处缺陷，那两处会改变增强的随机流：

1. `_random_int` 的上界：官方 `np.random.randint(lo, hi)` 与本模块"两端都含"的约定不符，
   于是 `hi` 永远取不到（babble 只可能抽到 3~6）；
2. `CustomNoise` 取噪声：官方对短文件用 `np.pad(..., 'wrap')` 循环补齐，
   实测 5%~15% 的抽取会命中比目标短的噪声文件，补出来的尾巴是开头的逐字复制。

`legacy_aug: true` 让这两处退回官方行为，只用于复现，**新实验不要打开**。

### 12.3 实测：确实逐位一致

```text
官方基线（只补 meters 命名空间）  vs  HEAD + official_repro_ptn.yaml
  逐位不同 0 / 823 个权重张量，最大绝对差 0.000e+00
```

同一命令下日志会打印：

```text
LEGACY_AUG : True（退回官方增强行为，用于复现官方结果）
```

### 12.4 还有一项不需要开关

官方基线 `9d38486` 的 `meters.py` 漏了 `meter` 命名空间，
而 `executor.py` 用的是 `tnt.meter.X`，**18 份配方全部在第 1 步就崩**。
本仓库已修。这一项修的是崩溃，不改变数值，所以不需要开关。

### 12.5 怎么用

```bash
bash applications/speaker_rec/launch.sh \
  applications/speaker_rec/examples/vb2_vox2_cnc2/recipes/redimnet2/b6/official_repro_ptn.yaml 8
```

第二阶段同理，把配方换成 `official_repro_lm.yaml`。
在 8 卡上跑要注意第 11.3 节的提醒：卡数会改变实际学习率，而这一份**没有改任何超参**，
所以它复现的是"官方配方在 8 卡上的行为"，不是"官方在别的卡数上的行为"。

### 12.6 这份实验的边界

- 它复现的是**官方代码路径的行为**，不是官方发布的那组数字本身。
  官方训练用的数据版本、卡数、以及那个尚未确认的 epoch 数（120 / 100ep / model_115）
  仍然未知，见第 11.4 节。
- 它**保留**了两处已知缺陷（`augs.py` 的两个问题），这是为了逐位一致而付出的代价。
- 验证是在 2 卡、小样本（384 条/轮、1 轮）上做的，不是完整训练。
