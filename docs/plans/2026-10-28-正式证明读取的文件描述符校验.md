# 正式证明读取的文件描述符校验

第二次真实 CPU 成本测量中，首个 worker 之后的七次串行底层检查耗时
29.830 秒，超过现有 20 秒 ACK 等待时间。不能靠延长时限接续，也不能
把已经发生过内容碰撞的文件属性当成 SHA。这里先减少每个文件反复遍历
共同祖先目录的成本，保持原冻结包、运行协议和时限不变。

原 `_verify_snapshot` 已持有完整有限文件清单及唯一祖先目录集合，但
每个文件调用 `R.pinned_file` 时还会多次逐层检查相同祖先。新实现先对
唯一祖先集合核一次设备、inode、模式，再逐文件安全打开。使用
`O_RDONLY | O_NOFOLLOW | O_NONBLOCK`；打开前只核末级路径的六个属性，
打开后再以 `fstat` 核设备、inode、模式、
大小、mtime 和 ctime，并确认是普通文件，然后读取所有字节计算 SHA。
读完再次核文件描述符与路径的六个属性，最后再核完整祖先集合。
所有描述符均在 `finally` 关闭；软链接、FIFO、替换文件或读取中改变
立即拒绝。文件属性只用于拒绝变化，完整内容 SHA 每次仍实际计算。

首次快照 `_snapshot_verified_pins` 保持原逻辑。普通 JSON 声明仍不能
自行产生运行能力；memfd 身份、封印、父子进程、当前平台和租约门均
不改。不加入默认线程池，不建立数据库，不修改数学源码或正在运行的
正式包。当前改动只进入仓库维护版，旧正式 v2 与成本 v2 原件保留。

验证分三步：本机普通及 `-O` 对抗测试；独立审阅后在新 Linux CPU
目录执行原 61 项加新增文件描述符测试，并复查原 64 个同 tick 反例；
最后由操作者固定新正式包后，在全新成本目录测量实际速度。测试必须
覆盖祖先集合完整性与前后检查、软链接、FIFO 不阻塞、相同字节但不同
inode 的错误描述符、读取中改内容、读完路径替换、父目录替换及
描述符正常和异常关闭。合成检查通过不能替代实际时间或 GPU 启动验收。

## 已完成的 CPU 复验

最终维护源 `bounded_speed_runtime.py` 的 SHA 为
`58823a3a06bc6585c4c6dfd479be05db004d82b935565275161384922b2bde78`。
新文件描述符测试共 11 项，其中 FIFO 既检查原先存在时在打开前拒绝，
也在路径预检查后立刻替换成 FIFO，确认真实非阻塞打开后在读取前拒绝。
原重复读取测试改为观察实际描述符读到 EOF 的次数与字节量，不能因为
实现不再调用 `R.file_sha` 就删掉每次读取完整内容的要求。

独立审阅后，在开发机新建的纯 CPU 目录实际执行 72 项普通模式和
72 项 `-O` 模式，分别用时 8.002 秒和 10.089 秒，全部执行、没有跳过。
它们包括真实 Linux memfd、fork、exec、继承描述符与封印检查。另只读
复核先前保留的 64 个同 tick 改写反例：全部拒绝，其中 24 个属性仍然
碰撞的文件由实际 SHA 拒绝，其余 40 个由属性变化拒绝。64 份旧文件
字节均保持原样，没有重新构造反例掩盖原失败。

部署包装器第一次在 Python 解析阶段失败，没有执行解包或测试；原
SyntaxError 日志保留。修正的是包装器的变量传值方式，实际测试仍使用
同一份已审维护源，没有改冻结包或旧结果。

Linux 测试收据摘要为
`6e0fbfa15ea9c5fb2c174fbd1ebe3280b1affe8435ff5f5d509e9ca238c4152a`，
原 64 例复核收据摘要为
`018667c89a4bf9beebf47743ab37134f0179a51ea882aeb4d84aea4050a60571`。
完整小日志和源清单仅保存在仓库私有证据目录，不上传 GitHub。
这些结果说明当前安全检查没有在已测试反例中削弱；新的正式包实际
启动成本仍未测量，不能据此宣称已满足 20 秒等待时间。
