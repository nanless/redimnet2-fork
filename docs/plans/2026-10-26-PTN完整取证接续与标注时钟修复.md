# PTN完整取证接续与标注时钟修复计划

目标是修复本轮发现的具体缺陷，并把主训练恢复到可验证、可追踪的状态。历史48轮故障没有保存当时的模型与随机状态；不能凭model47阴性重放宣称首坏原因已定。新版本保持模型计算、损失、AMP、学习率、批量和数据不变，先补完整故障取证，再作严格的受控接续。它仍遇到非有限值就保存证据并停止，不跳批、不自动改精度。

维护源始终为本仓库；部署使用新目录和新摘要。旧189文件树、旧16成员恢复包、运行中的标注包和所有原件均不覆盖。使用现有隔离维护分支，不改活跃任务环境。分工分别覆盖数值取证、接续门、标注时钟；主维护者交叉审阅、部署与实测。

## 1. 数值故障取证

- 修改`applications/speaker_rec/wespeaker_lite/utils/executor.py`，新增同目录`numerical_failure.py`。正常批只保存必要的前向前随机状态和可变buffer快照，不每批复制全部模型/优化器。
- 失败时保存准确的增强后wav、targets、可选lengths/软标签、前向前buffer/RNG、当时模型/优化器/scaler及配置/模式。所有输出新建并原子发布完整摘要；保存失败仍拒绝训练，不能输出虚假的完整取证声明。
- 检查FP16向量、FP32分类头和损失的先后关系，保留所有进程共同停止的协调。新增CPU反例覆盖失败字段、部分写入、重复输出、BN/RNG和坏rank协调。
- 不把故障批前向改变后的BN或第47轮状态冒充前向前现场。不因scaler数值下降而宣布本批前向NaN根因。

## 2. 新恢复合同与执行入口

- 新建`tools/ptn_resume/`的合同、只读构建器和实际状态比较函数。绑定原189成员及原95源码凭据，只允许新executor与一个取证helper形成明确差异，建立独立190文件树。
- 固定model47完整SHA、原说话人映射、两个旧段新鲜控制面终态、稳定锁、唯一新输出；起始48轮、绝对迭代705047、原学习率0.72与margin0.2。
- 主维护者实现参数化的新父/worker入口：先CPU完整构造并精确恢复模型/SGD/scaler，再在八rank第一次前向前重新核对并all-gather放行。原24数据进程/rank的分片和legacy augmentation检查保留。
- 旧35→36脚本不直接执行；新包所有维护依赖随包固定，不能依赖可变仓库安装。父进程只管理有nonce与启动身份的自有子进程。
- 先合成反例，再实际CPU完整恢复，再指定双卡的真实B6工程验证。双卡用独立工程输出，不冒充八卡正式轨迹或完整数据质量验证。

## 3. 标注时钟与文本输入

- 先审固定16条已封账侧车、原ASR、原生时间、FIX修补、最终items及源时钟，不读整库或拿任意混合数据冒充代表来源。
- 已证相接16.24秒被二进制乘法制造1采样点重叠。新增精确有理数时钟版本，基于明确最终小数秒及整数源偏移计算floor/ceil，不加统一容差，也不删除真实交叠。
- 旧VAD时钟和旧侧车v1验证保留；新窗口必须声明新映射版本。对照真实例、分数采样点真重叠和非等长采样率等反例，修后该例仍因原库内修补维持待复核。
- 词内ASCII撇号的旧归一化可能改变官方模型允许的整词。另建明确profile，保原ASR和目标变化审计，用相同原件、缓存及固定模型作两卡A/B后再决定适用范围；不直接删旧复核旗，也不改运行中的八卡旧包。

## 4. 云端接续和后续边界

- 两卡验证、严格恢复与新鲜终态均通过后，按现有授权准备并提交唯一优先级6八卡PTN后继任务；不停止或迁移标注任务，不重复提交。回读实际入口、挂载、rank、首优化步、完整下一轮检查点和验证记录。
- 更完整取证的接续成功不等于历史根因已定位；若复发，用新完整状态复现首坏位置，再做有证的最小数值修复、审阅及复验。
- LM谱系需1—35、36—47、48—120三段。旧两段准备器继续拒绝；三段协议另建，不能把失败段伪写为成功到120轮。
- 所有实测结论区分CPU合成、真实恢复、GPU工程、正式推进、标注候选和人工完整字验收。分阶段中文提交、push，作者和提交者均为nanless，相关文档/Skill源随修复更新。
