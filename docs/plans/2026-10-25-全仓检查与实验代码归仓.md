# ReDimNet2 实验代码归仓与全面检查实施计划

**目标：**把本聊天涉及的现行主训练接续、开源模型标注、完整字消费、自然变长训练和评测维护入口纳入本仓库；逐项检查，发现问题后先保留证据、修复，再独立审阅和测试。所有新增提交作者与提交者均为 `nanless <francis7999@outlook.com>`，标题和正文用详细中文。

**实现方式：**以 GitHub 当前主分支 `0a3f6dd501e224a2bed85b6207df7c99046b4272` 为基础，在本机独立副本内维护。采用普通可导入模块和明确命令入口，不覆盖当前云任务的冻结文件或运行目录。历史记录说明当时事实；新的维护版本使用新的源码身份，不重写旧摘要。

**技术条件：**Python、unittest/pytest、Bash、Git；先做无网络、无模型下载、无 GPU 的可重复检查，需要实际模型或服务器的项目逐项写清尚缺证据。当前 Git 网络不可用时，使用连接器按 Git 对象摘要核实读取源码，不把资料目录的空 Git 当作目标仓库。

## 1. 固定仓库身份与审查范围

1. 核 GitHub 地址、主分支、189个受控文件与权限、当前 `AGENTS.md`。
2. 为全部受控代码、脚本、配方、文档建立目录级审查表，补登记实验目录中尚未入库的现行实现及依赖。
3. 仓库本地配置作者与提交者；使用 `codex/` 分支，不覆盖服务器已有未提交修改。
4. 公开仓库只存代码、说明、非敏感配置示例和合成夹具；音频、模型、完整日志、业务标注原件与凭据不入库。依赖这些原件的检查必须支持显式受控输入，缺失时拒绝或如实跳过。

## 2. 主训练、大间隔微调及自然变长训练

1. 检查普通脚本入口、数据子进程继承、分类头映射、同阶段恢复和跨阶段冷优化器、保存与导出。
2. 将跨段大间隔微调准备器及必要固定依赖纳入 `tools/lm_continuation/`；整理独立合成测试，不依赖 Mac 实验目录。
3. 检查并纳入 `duration_ft/`、`word_ft/`、`word_ft_v3/` 及相应启动/评测脚本的现行实现，保持正式完整字输入与工程候选的拒绝边界。
4. 不启动训练、不查询或清理未知进程、不运行旧冻结入口；现训和原冻结清单不改。

## 3. 三训练域开源标注与完整字消费

1. 将已核生产实现整理到 `tools/open_annotation/`；补来源、合同、原声时钟、原始与修复时间层、发布和中断恢复的中文说明。
2. 纳入完整字消费维护入口；外部诊断保护引用必须按显式固定摘要校验，公开测试用合成原件，不上传真实诊断样本名单。
3. 检查拒绝返回码、路径/软链、原子发布、并发代次、锁、缓存来源和资格字段；拒绝信息不能掩盖错误。
4. 当前正式标注只包含 VoxCeleb2、VoxBlink2、CN-Celeb2 的实际训练来源，自动候选不等于人工边界真值。

## 4. 中文文档与项目技能

1. 更新中文总入口、仓库约定、训练/标注/消费操作说明及历史与当前状态的区别。
2. 项目技能的维护源放在本仓库 `.agents/skills/`，需要时新增引用，写清代码位置、可运行命令、验收范围与现场条件。
3. 相关本机已安装技能只从仓库维护源同步，保存摘要，避免继续出现仓库外唯一实现。
4. 自动核对新增文档链接、脚本示例和命令退出码，避免把准备完成写成云端执行完成。

## 5. 修复、交叉审阅与验证

1. 三个并行检查分别负责训练/接续、标注/消费、文档/完整性；根统一集成，文件归属明确。
2. 每项确定问题登记触发条件、影响、修复文件、针对性反例和独立审阅结论；修后仍有问题继续修复。
3. 集成后执行语法检查、Bash检查、核心与新模块测试、文档链接和发布内容核验。
4. 完成一轮没有新确定性问题的独立复审再提交。无法取得 GPU/网络/人工边界证据的项目列为未验项目，不以软件测试代替，也不承诺数学意义的零缺陷。

## 6. 提交与推送

1. 逐文件复读差异；明确列出新增、修复、测试结果和仍待现场验证的项目。
2. 用仓库本地身份提交，核作者与提交者都是 nanless，检查提交内容不含音频/权重/凭据/业务原件。
3. 推送 `codex/` 分支并回读远端提交摘要；若 Git 传输不可用，先保完整本地提交，再使用已连接服务的等价安全路径，不能以接口返回成功冒充作者或远端摘要已核实。
