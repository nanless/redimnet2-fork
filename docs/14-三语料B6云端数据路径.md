# 三语料 B6 的云端数据路径与检查方法

本次目标是 VoxCeleb2、VoxBlink2、CN-Celeb2 三套训练语料的 B6 模型，最终完成大间隔微调。数据检查分两处做：开发机检查现有数据表和音频，云端容器检查挂载之后的同一批路径。开发机能读到文件，不能替代云端挂载验证。

## 1. 共享盘怎样挂载

2026-10-19 在 `dev_a800_2gpus` 实查得到：

- `/root/group-shared` 是指向 `/shared/group-shared` 的软链接。
- `/shared/group-shared` 来自 GPFS 共享文件系统 `fs_vepfs-cnbjc90fab4fcf40` 的 `/aiplatform-speech/group-shared` 子目录。
- 训练表、三套训练语料、MUSAN、RIRS、VoxCeleb1、VOICES 和 CN-Celeb 评测数据都位于这套共享盘。所检查的根目录和抽样音频没有跳到 `/aispeech-cfs`。

推荐云任务按下面的路径挂载，实际共享盘名称和可选子目录仍须以提交页面为准。

| 共享盘中的源目录 | 容器目标目录 | 权限和作用 |
|---|---|---|
| `/aiplatform-speech/group-shared/voiceprint/data` | `/shared/group-shared/voiceprint/data` | 只读，训练和评测数据 |
| 新实验专属的持久输出目录 | `/training-output` | 可读写，训练权重、日志和检查结果；创建任务前确定真实源目录 |
| 本次核实过的代码副本，或平台下载解压的代码包 | `/workspace/redimnet2`，或平台实际代码目录 | 代码只需可读；不要让权重写回代码包目录 |

容器内的数据、输出、代码目标目录互不嵌套。如果平台只能挂载整个 `/aiplatform-speech/group-shared`，可将其挂到 `/shared/group-shared`，但仍应让训练只写本实验专属目录。

`DATA_ROOT` 应设置为 `/root/group-shared/voiceprint/data/wespeaker_data`。仅修改这个变量，不会修改 `data.list` 内部的绝对音频路径。现有表里既有 `/root/group-shared/...`，也有 `/shared/group-shared/...`，所以这两个根目录都必须可用。

## 2. 安全准备两类绝对路径

在启动训练前执行：

```bash
PYTHON_BIN="${PYTHON_BIN:-python3}" \
SHARED_DATA_MOUNT=/shared/group-shared \
bash applications/speaker_rec/scripts/cloud/prepare_b6_cloud_paths.sh
```

脚本先检查共享盘中的训练表和真实增强源目录，再准备 `/shared/group-shared` 与 `/root/group-shared` 两个目录别名。已有正确链接时直接保留；已有不同链接、非空目录或文件时退出，不覆盖它们。只有空目录会在确认后被删除并替换为软链接。脚本不会改写训练表、复制音频或创建 LMDB。

增强数据本身也用了绝对软链接：

- `wespeaker_data/raw/musan` 指向同一共享盘的 `voiceprint/data/noise/musan/musan`。
- `wespeaker_data/raw/rirs/simulated_rirs` 指向 `voiceprint/data/noise/rirs_noises/RIRS_NOISES/simulated_rirs`。

因此，只挂载 `wespeaker_data` 子目录还不够；必须同时覆盖真实音频和增强目录。上面的 `voiceprint/data` 挂载范围已经包含这些内容。

## 3. 两阶段训练表检查

使用训练环境运行：

```bash
python applications/speaker_rec/scripts/cloud/check_b6_mix_data.py \
  --data-root /root/group-shared/voiceprint/data/wespeaker_data \
  --output /training-output/data_check.json
```

检查程序逐行读取 `data.list` 和 `utt2spk`，核对每行的样本编号与说话人，统计三套语料、说话人数和路径根目录，计算两个表的 SHA-256。程序同时确认微调阶段说话人是主训练阶段的子集，并检查训练表中的音频路径没有出现在本次评测列表中。

它不会逐个访问一千多万条训练音频。每套训练语料在两个阶段分别抽取 12 条、共 72 条音频，完整解码，检查 16 kHz、单声道、有限数值；微调样本另外检查至少 5 秒。此处的训练与评测隔离指文件路径和数据目录隔离，不代表做过人名身份辨认或音频内容去重。

主训练说话人编号表必须传给微调阶段。微调阶段使用主训练说话人的子集，不应重新按微调表生成另一套编号，避免同一个类别编号指向不同说话人。

## 4. 评测数据目录

共同前缀为 `/root/group-shared/voiceprint/data/speech/speaker_verification`。

| 命令行参数 | 对应目录 | 用途 |
|---|---|---|
| `--vox1-root` | 前缀下的 `voxceleb1` | 完整语音的 VoxCeleb1-O/E/H，以及 VoxCeleb1-B |
| `--voices-root` | 前缀下的 `voices` | VOICES 评测 |
| `--cnceleb-root` | 前缀下的 `cnceleb` | CN-Celeb 评测，使用 `--cnceleb-mode avg` |

CN-Celeb 评测使用 `CN-Celeb_flac/eval/lists/enroll.map` 和 `trials.lst`，读取 `CN-Celeb_wav` 下音频，并对注册片段的说话人向量取平均。它与训练使用的 `CN-Celeb2_flac` 是不同数据目录。

训练过程中的小验证集是 `/root/group-shared/voiceprint/data/wespeaker_data/vox1-test`。它只覆盖 VoxCeleb1-O 的试验，不应作为完整 O/E/H 评测根目录。

检查程序直接调用正式评测脚本的数据读取函数，核对各协议涉及的所有音频路径存在，再均匀抽样完整解码。增强数据则递归重新统计所有 wav 文件，并抽样解码。
