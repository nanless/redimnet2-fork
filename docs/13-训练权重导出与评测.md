# 训练权重导出与评测

训练程序保存的检查点现在可以直接交给 VoxCeleb1 和域外评测程序，也可以先导出为只含说话人向量模型的发布权重。官方发布权重的读取方式不变。这里解决的是格式和接口问题，完整测试集上的等错误率（EER）要等正式训练跑完才能测。

> 本文引用的 `/root/codex_artifacts/...` 检查与评测证据都是 2026-11-09 之前的旧基址（**历史路径**）。新评测按存储规范写 `/root/group-shared/voiceprint/artifacts/redimnet2/eval-<日期>/`（导出权重等实验产物写 `experiments/redimnet2/<实验名>/`），见 [19 号第 6 节](19-今日工作与后续入口.md)。

## 1. 两种文件分别保存什么

训练检查点通常含 `model`、`optimizer`、`scaler` 和 `epoch`。其中 `model` 内的 `backbone.*` 是声纹模型，`projection.*` 是用训练说话人编号分类的损失计算层。正式说话人验证只使用前者。

官方发布权重含 `model_config` 和 `state_dict`：模型配置和声纹模型参数放在同一个文件内，不需要训练数据的说话人编号表。新增的 `scripts/export_checkpoint.py` 负责完成这种转换。

转换要用该次实验实际保存的 `config.yaml`：模型按其中的 `model_args` 构建，换错配置会得到形状不对的分类头。程序只移除明确属于 `projection.*` 的分类参数，识别多卡包装的 `module.` 和编译包装的 `_orig_mod.`，随后严格检查所有声纹参数和缓冲张量。参数缺失、多出、形状错误、去前缀后重名或出现其他网络分支都会报错。它不根据文件名猜 B6 的模型配置，也不用 `strict=False` 忽略错误。

PyTorch 的完整反序列化会执行文件里的代码，所以只读可信来源的权重。原来的官方权重读取也是这个行为。

## 2. 导出大间隔微调权重

下面的 `/mnt/vepfs/redimnet2_runs/b6_mix_repro/lm` 是示例实验目录，正式任务换成实际使用的目录：

```bash
python scripts/export_checkpoint.py \
  --checkpoint /mnt/vepfs/redimnet2_runs/b6_mix_repro/lm/models/model_1.pt \
  --training-config /mnt/vepfs/redimnet2_runs/b6_mix_repro/lm/config.yaml \
  --output /mnt/vepfs/redimnet2_runs/b6_mix_repro/released/b6-mix-repro-lm.pt
```

输出含 `model_config`、`state_dict`，以及记录来源路径、来源检查点和配置的 SHA256、轮数、移除分类参数名的 `export_info`。优化器和梯度缩放器状态不写入发布权重。原检查点保留，可继续用于恢复训练。输出文件已存在时程序拒绝覆盖。

## 3. 完整评测命令

下列数据目录是开发机上的约定路径。火山引擎任务要把相同内容挂到可读目录；挂载后的路径不同时，改对应的 `--*-root` 参数。

VoxCeleb1 使用全量音频与 O/E/H 三套清洗后的试验列表：

```bash
python scripts/eval_vox1_checkpoints.py \
  --ckpt-dir /mnt/vepfs/redimnet2_runs/b6_mix_repro/released \
  --checkpoints b6-mix-repro-lm.pt \
  --vox1-root /root/group-shared/voiceprint/data/speech/speaker_verification/voxceleb1 \
  --protocols O,E,H \
  --out-csv /mnt/vepfs/redimnet2_runs/b6_mix_repro/eval/vox1_O_E_H.csv
```

训练时的 `/root/group-shared/voiceprint/data/wespeaker_data/vox1-test` 不能代替全量 VoxCeleb1：训练验证目录只有 O 协议所需的部分音频，覆盖不了 E/H 和 Vox1-B。

域外评测使用 Vox1-B、VOICES 和 CN-Celeb。CN-Celeb 使用多段注册语音的向量平均，与现有官方结果的比较方式保持一致：

```bash
python scripts/eval_ood_checkpoints.py \
  --ckpt-dir /mnt/vepfs/redimnet2_runs/b6_mix_repro/released \
  --checkpoints b6-mix-repro-lm.pt \
  --benchmarks Vox1-B,VOICES,CN-Celeb \
  --vox1-root /root/group-shared/voiceprint/data/speech/speaker_verification/voxceleb1 \
  --voices-root /root/group-shared/voiceprint/data/speech/speaker_verification/voices \
  --cnceleb-root /root/group-shared/voiceprint/data/speech/speaker_verification/cnceleb \
  --cnceleb-mode avg \
  --out-csv /mnt/vepfs/redimnet2_runs/b6_mix_repro/eval/ood.csv
```

也可以不先导出，直接对训练检查点评测：把 `--ckpt-dir` 指向实验的 `models`，把 `--checkpoints` 设为 `model_1.pt`，并增加 `--training-config /该实验目录/config.yaml`。这个参数对已有官方发布权重没有影响。

两份程序均按完整音频、未编译模型、归一化向量和余弦相似度评测。训练日志里的前 8 秒验证分数与这里的完整评测不是同一口径，不能互相代替。

## 5. 正式任务结束后的六组并行评测

`applications/speaker_rec/scripts/cloud/evaluate_b6_mix_reproduction.sh` 接收 `RUN_ROOT`、`PYTHON_BIN` 和 `REPO_ROOT`，从 `RUN_ROOT/lm/models/model_1.pt` 导出发布权重。发布权重已存在时，只有其中记录的来源检查点和配置 SHA256 均匹配才复用；来源不对的文件不会被覆盖。

脚本把官方三语料 B6 大间隔微调权重复制到 `RUN_ROOT/reference/official-b6-vb2+vox2+cnc2_v0-lm.pt`，记录并核对 SHA256。然后在前六张可见卡上分别运行 O、E、H、Vox1-B、VOICES、CN-Celeb，每一组都测复现权重和固定官方参考权重。CN-Celeb 保持多段注册向量平均。只有六个程序全部正常退出、结果完整且有限时，才写出 `summary.json` 和 `summary.csv`（账本）；各组原始 CSV 和日志也保留在该目录。按 2026-11-09 存储规范，评测产物默认写 `/root/group-shared/voiceprint/artifacts/redimnet2/eval-<UTC日期>/<run目录名>/`；旧布局 `RUN_ROOT/evaluation` 属于历史路径，可用 `EVAL_DIR` 显式指回去。

```bash
RUN_ROOT=/root/group-shared/voiceprint/experiments/redimnet2/b6-mix-repro \
PYTHON_BIN=/实际Python解释器路径 \
REPO_ROOT=/实际冻结代码目录 \
bash /实际冻结代码目录/applications/speaker_rec/scripts/cloud/evaluate_b6_mix_reproduction.sh
```

`VOX1_ROOT`、`VOICES_ROOT`、`CNCELEB_ROOT` 可以覆盖数据根目录；默认仍是上一节已核实的开发机路径。`OFFICIAL_REFERENCE` 可以指定可信官方权重的路径。脚本不会改变上游参考文件。

当前提取程序均逐条完整音频前向，没有把多段补齐成一个批量，也没有分桶。最长单条音频决定显存峰值；截短之后就不再是同一协议。

2026-10-19 在开发机实查：O/E/H 分别为 4,708 / 145,160 / 137,924 条不同音频；Vox1-B、VOICES、CN-Celeb 分别为 42,561 / 11,392 / 18,576 条。对应的全部试验所需文件均存在。域外试验列表在 CPU 上保留，评分时的 25 万条分块会产生数百 MB 的临时向量矩阵。六组并行建议至少留出 32 GB 主机内存，并考虑 24 个数据读取进程的开销。

使用官方 B6 权重，在单张 A800 80 GB 上对固定抽取的 32 条完整 Vox1-O 音频测速：总音频 214.442 秒，每条长 4.160–14.760 秒，读取和前向共 1.318 秒，约 24.29 条/秒；GPU 已分配峰值约 630 MB，缓存保留峰值约 2,778 MB。仅按这个速度外推，E 协议同时测两份权重约需 3.3 小时，是六组并行的主要耗时（推断，样本只有 32 条）。正式云端的磁盘速度、最长音频、评分和共享读取竞争都可能使耗时增加，这个数不能当作完成时刻的承诺或最长音频显存上限。

统一检查日志已复制到 `/root/codex_artifacts/verification/volcengine/redimnet2-b6mix-20261019/checkpoint-eval/`（历史路径），原目录保留。`resources_and_paths.log` 保存协议与文件计数，`embedding_benchmark.log` 保存测速条件，`import_paths.log` 确认新代码目录优先，`wrapper_mock.log` 保存六路成功、子进程失败和来源 SHA 不匹配时的检查结果。

## 6. 正式权重导出与九格长度矩阵评测（2026-11-06）

PTN 跑满 120 轮后，正式权重已从检查点导出，并在 CPU 上按“注册字数 × 测试字数”的九格矩阵评测过一次。这一节分开写能支持的结论和不能支持的判断。

### 6.1 两枚发布权重

| 项 | 实测 |
|---|---|
| 文件 | `$RUN/released/v1/ptn-model_115.pt`、`ptn-model_120.pt`（`$RUN` 指 PTN 第三段的运行目录） |
| 体积 | 各 **51,411,906 字节** |
| sha256 | `f41e1ad9…`（115 轮）、`fc1b4baa…`（120 轮） |
| 加载检查 | 821 个键严格加载通过 |
| 来源绑定 | 两枚的 `source_checkpoint_sha256` 与 `ptn_success.json` 记录一致 |

体积与第 4 节那次不同要分开看：第 4 节是 2026-10-19 用短测检查点导出的 51,408,286 字节测试文件，来源检查点和用途都与这里的两枚不同。

### 6.2 评测环境要显式设置的一项

该环境的系统 `libsndfile` 是 **1.0.28**，而冻结口径要求 **1.2.2**。两个版本解码行为不同，比较前先设：

```bash
export LD_LIBRARY_PATH=$EXP/runtime_audio/lib:$LD_LIBRARY_PATH
```

这是环境差异，与模型无关。不设也能跑完，但解码口径与冻结口径不一致，结果不可比。

### 6.3 链路自校验：官方权重 48 格 0 差异

用同一套评测程序重跑官方权重的 48 个格子，与历史结果逐格 0 差异，连每格 `scores.csv` 的 sha256 都相同；`cache_hits=0/180`，说明是真重算而不是读旧缓存。这一项证明评测链路本身没漂，是后面九格对比能成立的前提。

### 6.4 九格结果与它不能支持的判断

| 模型 | 九格均值 EER（%） | AUC |
|---|---:|---:|
| 官方权重 | 4.6871 | .98960 |
| PTN 第 115 轮 | 4.6743 | .99132 |
| PTN 第 120 轮 | 5.3512 | .99006 |

这张表不支持复现成败的结论：27/27 组置信区间两两重叠，样本只有 30 人 180 条，EER 的分辨率约 1/30 ≈ 3.33%，这个规模下 4.6743 与 5.3512 的差别不足以区分。

能支持的结论只有一条：三个模型都表现出注册端越短越难，方向一致。

还要分清三件事：这是 PTN 权重在长度矩阵上的结果，不是 LM 权重，也不是第 7 节的六列协议评测。LM 的运行目录已于 2026-11-07 03:05–05:37 UTC 跑完 1 轮（13,075 步、`training_exit_code=0`、`vox1-eer-8s` = 0.293%），这里的结论只到运行目录这一层，不涉及任务号：产物里没有 `task_id`，平台侧记录里完成者是 `t-20261106110454-vd8pq`（本地无留档）。第 5 节那套 `evaluate_b6_mix_reproduction.sh` 没有对 LM 跑过，运行目录下也没有 `released/`、`evaluation/`；第 7 节的六列由另一套协议匹配的评测在 11-07 产出。两件事要分开：六列有数了，发布权重导出和那套自动汇总入口仍然缺。

## 7. 与官方结果表的完整对比（2026-11-08 实测）

> 协议：整段音频、eager float32、L2 归一化、cosine；CN-Celeb 用 avg enrollment。单位 %，越低越好。
> 每个数字都来自 `/root/codex_artifacts/eval-official-20261108/csv/<weight>__{vox1OEH,ood,vox1O_8s}.csv`（历史路径），可逐格复算。

先校准再看差值：用同一套脚本重跑官方权重，六列逐列落回 README（最大偏差 +0.015 pp）——O 0.255/0.26、E 0.409/0.41、H 0.790/0.79、B 1.153/1.15、VOICES 3.029/3.03、CN-Celeb 3.605/3.59。校准过了，下表的“我们 vs 官方”差值才有可比性。

| 列 | README | 官方实测 | PTN115 | PTN120 | 本实验 LM | LM − 官方 |
|---|---|---|---|---|---|---|
| Vox1-O | 0.26 | 0.255 | 0.420 | 0.399 | **0.287** | +0.032 |
| Vox1-E | 0.41 | 0.409 | 0.530 | 0.529 | **0.391** | −0.018 |
| Vox1-H | 0.79 | 0.790 | 0.983 | 0.974 | **0.735** | −0.055 |
| Vox1-B | 1.15 | 1.153 | 1.405 | 1.510 | **1.235** | +0.082 |
| VOICES | 3.03 | 3.029 | 4.731 | 4.755 | **3.147** | +0.118 |
| CN-Celeb | 3.59 | 3.605 | 3.717 | 3.768 | **3.378** | −0.227 |

读这张表前先避开三个坑（2026-11-09 复核）：

- `csv/equiv__*.csv` 里的 Vox1-E 是 **0.28**，不是 0.409。这两份文件来自被 `head` 截断成 5,000 行的夹具，`equiv__repo_stock.csv` 里的 `delta-E=-0.13` 就是截断造成的，数值不可引用。
- `summary.csv` 与 `cells.csv` 是跑之前的空模板：32 格全写 `NOT_RUN`，`SITW` 记 `DATA_MISSING`。结果只看 `csv/<weight>__*.csv` 与 `ledger.csv`。`ledger.csv` 记了每次运行的 `start_utc`、`end_utc`、`exit_code`，12 次运行全部 `exit_code=0`（实测）。
- 协议身份在 `provenance.json`：每个协议文件的 `sha256` 与 `trials`（O 37,611 / E 579,818 / H 550,894 / B 808,574 / VOICES 3,607,516 / CN-Celeb 3,484,292），四个权重的 `sha256` 也在同一份文件里。引用数字时把它一起给出，才能证明两次比较用的是同一协议、同一权重。

结论：本实验 LM 在 E / H / CN-Celeb 三列优于官方，在 O / B / VOICES 三列略差，平均绝对偏差约 0.09 pp。

PTN → LM 的改善（同口径）：O −0.112、E −0.138、H −0.239、B −0.275、**VOICES −1.608**、CN-Celeb −0.390。改善在域外集最大、Vox1-O 最小，说明 LM 阶段主要补的是域外泛化，不是把 Vox1 拟合得更紧。PTN 段 VOICES 偏高（4.755）属于阶段差，不算缺陷。

8 秒短验口径（训练期指标，不可与 README 相减）：官方 0.239、PTN115 0.404、PTN120 0.399、本实验 LM 0.293。

SITW 无法复现：`sitw` 目录仅 3.5 KB（`ACCESS_REQUIRED.txt` + HuggingFace 403 gated 残留 `.lock`），0 个 wav、0 条 trials；卡点是数据集授权（SRI 邮件 / HF `confit/sitw-full` 约 19.9 GB），不是代码。代码侧补齐约 1 小时（推断）。
