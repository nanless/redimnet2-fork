# 训练权重导出与评测

训练程序保存的检查点现在可以直接交给 VoxCeleb1 和域外评测程序，也可以先导出为只含说话人向量模型的发布权重。官方发布权重的读取方式不变。这里解决的是格式和接口问题，完整测试集的等错误率（EER）仍需在正式训练后测量。

## 1. 两种文件分别保存什么

训练检查点通常含 `model`、`optimizer`、`scaler` 和 `epoch`。其中 `model` 内的 `backbone.*` 是声纹模型，`projection.*` 是用训练说话人编号分类的损失计算层。正式说话人验证只使用前者。

官方发布权重含 `model_config` 和 `state_dict`：模型配置和声纹模型参数放在同一个文件内，不需要训练数据的说话人编号表。新增的 `scripts/export_checkpoint.py` 负责完成这种转换。

转换时必须指定该次实验实际保存的 `config.yaml`，以其中的 `model_args` 构建模型。程序只移除明确属于 `projection.*` 的分类参数，识别多卡包装的 `module.` 和编译包装的 `_orig_mod.`，随后严格检查所有声纹参数和缓冲张量。参数缺失、多出、形状错误、去前缀后重名或出现其他网络分支都会报错。它不会根据文件名猜测 B6 的模型配置，也不会用 `strict=False` 忽略错误。

只读取可信来源的权重。权重使用 PyTorch 的完整反序列化方式；这与原来的官方权重读取行为相同。

## 2. 导出大间隔微调权重

以下命令中的 `/mnt/vepfs/redimnet2_runs/b6_mix_repro/lm` 是示例实验目录，必须替换成正式任务实际使用的目录：

```bash
python scripts/export_checkpoint.py \
  --checkpoint /mnt/vepfs/redimnet2_runs/b6_mix_repro/lm/models/model_1.pt \
  --training-config /mnt/vepfs/redimnet2_runs/b6_mix_repro/lm/config.yaml \
  --output /mnt/vepfs/redimnet2_runs/b6_mix_repro/released/b6-mix-repro-lm.pt
```

输出含 `model_config`、`state_dict`，以及记录来源路径、来源检查点和配置的 SHA256、轮数、移除分类参数名的 `export_info`。优化器和梯度缩放器状态不写入发布权重。原检查点保留，可继续用于恢复训练。输出文件已存在时程序拒绝覆盖。

## 3. 完整评测命令

下列数据目录是开发机上的约定路径。火山引擎任务必须将相同内容挂载到可读目录；如果挂载后的路径不同，修改对应的 `--*-root` 参数。

VoxCeleb1 使用全量音频与 O/E/H 三套清洗后的试验列表：

```bash
python scripts/eval_vox1_checkpoints.py \
  --ckpt-dir /mnt/vepfs/redimnet2_runs/b6_mix_repro/released \
  --checkpoints b6-mix-repro-lm.pt \
  --vox1-root /root/group-shared/voiceprint/data/speech/speaker_verification/voxceleb1 \
  --protocols O,E,H \
  --out-csv /mnt/vepfs/redimnet2_runs/b6_mix_repro/eval/vox1_O_E_H.csv
```

这里不能用训练时的 `/root/group-shared/voiceprint/data/wespeaker_data/vox1-test` 代替全量 VoxCeleb1：训练验证目录只有 O 协议所需的部分音频，不能覆盖 E/H 和 Vox1-B。

域外评测使用 Vox1-B、VOICES 和 CN-Celeb。CN-Celeb 使用多段注册语音的向量平均，与现有官方结果比较的方式保持一致：

```bash
python scripts/eval_ood_checkpoints.py \
  --ckpt-dir /mnt/vepfs/redimnet2_runs/b6_mix_repro/released \
  --checkpoints b6-mix-repro-lm.pt \
  --benchmarks Vox1-B,VOICES,CN-Celeb \
  --vox1-root /root/group-shared/voiceprint/data/speech/speaker_verification/voxceleb1 \
  --voices-root /root/group-shared/voiceprint/data/speech/speaker_verification/voices \
  --cnceleb-root /root/group-shared/voiceprint/data/speech/speaker_verification/cnceleb \
  --cnceleb-mode avg \
  --out-csv /mnt/vepfs/redimnet2_runs/b6_mix_repro/eval/ood.csv
```

也可以不先导出，直接对训练检查点评测：将 `--ckpt-dir` 指向实验的 `models`，将 `--checkpoints` 设为 `model_1.pt`，并增加 `--training-config /该实验目录/config.yaml`。这项参数对已有官方发布权重不作改动。

两份程序均按完整音频、未编译模型、归一化向量和余弦相似度评测。训练日志中的前 8 秒验证分数不能代替这里的完整评测。

同样的检查还用于已有大间隔微调检查点 `/dev/shm/cloud_t/final/lm/models/model_1.pt` 及其 `config.yaml`，8 项检查通过，四种方式的最大绝对差也均为 0。随后使用 4 段从真实 VoxCeleb1 音频截取的 2 秒片段，分别从命令行执行「导出权重 → VoxCeleb1 评测」和「训练检查点 → Vox1-B 评测」，均成功写出 CSV。这 4 段音频的试验列表是为测试程序执行而人工组成，所得分数没有模型准确率含义。

本轮检查日志与这组小测试文件位于开发机的 `/root/codex_artifacts/verification/redimnet2-repro-20261019/checkpoint_eval/`，其中 `lm_export_test.log` 保存实际大间隔微调检查点的比较结果，`cli_test.log` 保存两份命令行程序的执行记录。正式评测必须换回完整官方协议，不能使用该小测试目录。


## 5. 正式任务结束后的六组并行评测

`applications/speaker_rec/scripts/cloud/evaluate_b6_mix_reproduction.sh` 接收 `RUN_ROOT`、`PYTHON_BIN` 和 `REPO_ROOT`，从 `RUN_ROOT/lm/models/model_1.pt` 导出发布权重。若发布权重已存在，只有其中记录的来源检查点和配置 SHA256 均匹配时才复用；错来源文件不会被覆盖。

脚本把官方三语料 B6 大间隔微调权重复制到 `RUN_ROOT/reference/official-b6-vb2+vox2+cnc2_v0-lm.pt`，记录并核对 SHA256。然后在前六张可见卡上分别运行 O、E、H、Vox1-B、VOICES、CN-Celeb，每一组都测复现权重和固定官方参考权重。CN-Celeb 保持多段注册向量平均。只在六个程序全部正常退出、结果完整且有限时，写出 `RUN_ROOT/evaluation/summary.json` 和 `summary.csv`；各组原始 CSV 和日志也保留在该目录。

```bash
RUN_ROOT=/mnt/vepfs/redimnet2_runs/b6_mix_repro \
PYTHON_BIN=/实际Python解释器路径 \
REPO_ROOT=/实际冻结代码目录 \
bash /实际冻结代码目录/applications/speaker_rec/scripts/cloud/evaluate_b6_mix_reproduction.sh
```

`VOX1_ROOT`、`VOICES_ROOT`、`CNCELEB_ROOT` 可以覆盖数据根目录；默认仍是上一节已核实的开发机路径。`OFFICIAL_REFERENCE` 可以指定可信官方权重的路径。脚本不会改变上游参考文件。

当前提取程序均逐条完整音频前向，没有把多段补齐成一个批量，也没有分桶。最长单条音频决定显存峰值，不能随意截短后仍称为相同协议。O/E/H 会各自重新提取音频，存在重复计算。

2026-10-19 在开发机实查：O/E/H 分别为 4,708 / 145,160 / 137,924 条不同音频；Vox1-B、VOICES、CN-Celeb 分别为 42,561 / 11,392 / 18,576 条。对应的全部试验所需文件均存在。域外试验列表在 CPU 上保留，评分时的 25 万条分块会产生数百 MB 的临时向量矩阵。六组并行建议至少留出 32 GB 主机内存，并考虑 24 个数据读取进程的开销。

使用官方 B6 权重，在单张 A800 80 GB 上对固定抽取的 32 条完整 Vox1-O 音频测速：总音频 214.442 秒，每条长 4.160–14.760 秒，读取和前向共 1.318 秒，约 24.29 条/秒；GPU 已分配峰值约 630 MB，缓存保留峰值约 2,778 MB。仅按这个速度外推，E 协议同时测两份权重约需 3.3 小时，是六组并行的主要耗时。这是小样本量级估算，正式云端的磁盘速度、最长音频、评分和共享读取竞争都可能使耗时增加，不能据此承诺完成时刻或最长音频显存上限。

统一检查日志已复制到 `/root/codex_artifacts/verification/volcengine/redimnet2-b6mix-20261019/checkpoint-eval/`，原目录保留。`resources_and_paths.log` 保存协议与文件计数，`embedding_benchmark.log` 保存测速条件，`import_paths.log` 确认新代码目录优先，`wrapper_mock.log` 保存六路成功、子进程失败和来源 SHA 不匹配时的检查结果。
