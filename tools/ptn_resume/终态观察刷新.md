# 刷新尚未启动训练的终态观察引用

`refresh_terminal_refs.py`只发布操作者已取得的两份真实新观察，不查询平台、不改观察时间、不放宽一小时有效期，不导入Torch或访问GPU，也不提交任务或取得训练锁。没有新平台观察时，不能用它给旧材料续期。

首先由维护者核实当前平台任务已经终止、没有仍在写这个run的进程。`RUN`目录不存在只是一项文件条件，不能单独证明平台没有writer。工具额外要求两个指定前驱分别是固定任务的Terminated和Failed，active_workers为整数0、worker状态一致、时间带时区且通过原`contracts.terminal`的当前有效期检查。

入口可直接在仓库根运行，或将本文件与同版本`contracts.py`作为独立维护工具部署。不要把它补进已经冻结的候选3目录，不重写旧包索引：

```bash
python -B -m tools.ptn_resume.refresh_terminal_refs \
  --run-root /absolute/base/ptn-resume-model47-capture-20261026-v1 \
  --control-dir /absolute/base/ptn-resume-model47-capture-20261026-v1-control \
  --original /absolute/fresh/original-terminal.json --original-sha ACTUAL_64_HEX_SHA \
  --predecessor /absolute/fresh/predecessor-terminal.json --predecessor-sha ACTUAL_64_HEX_SHA \
  --audit-dir /absolute/new-external-audit-directory
```

示意中的base必须是工具固定的项目BASE；路径及SHA必须由实际原件填写。两输入不能位于control、run或本次审计输出目录内。control必须是当前用户所有、没有组或其他用户写权限的真实目录；规范引用也必须是同一用户所有的单链接普通文件。软链接、已经出现的RUN、冻结包/旧源码中的审计输出、已有审计目录都会被拒绝。

默认是dry-run：在新的外部审计目录保存两个规范引用的旧原字节、摘要和时间信息，保存输入原件、输入SHA及核验结果，规范引用本身不改变。审阅后执行时重新选择另一个全新审计目录，并在命令末尾显式加`--execute`。不能向dry-run目录追加以冒充另一轮审计。

执行会先保存两份旧原件及索引并fsync，再验证和封存两份新输入。每次发布都在临时文件完整写入并fsync后，立即再次检查RUN仍未出现，以及两个规范引用仍是封存或本次已经写出的那一代，之后才执行单文件原子替换和目录fsync。规范文件的字节必须与输入完全相同；不重新生成`observed_utc`，不美化或重写原JSON。

两个文件的替换不是一个事务。第一份已经替换、第二份失败，或者替换后fsync失败，都可能留下部分更新；工具保留旧原件、实际after状态和错误，`result.json`诚实列出`replaced_roles`、`actual_changed_roles`与`partial_update_possible`，返回非零退出码。不能把这当作两文件原子成功，也不能擅自改回旧时间或掩盖差异。父入口仍须再次读取真实材料并核验引用代次，不接受本工具的布尔结果作为运行许可。

成功只表示元数据已经按原规则核验、审计或发布。模型47、优化器、source190、八rank资源、数据读取进程、第一次SGD以及后续LM门均不在这个工具的授权范围内。排队再次超过有效期时，应重新取得平台真实观察再发布；不能将TTL改长来消除过期错误。

CPU测试位于`tools/ptn_resume/tests/test_refresh_terminal_refs.py`，使用临时合成JSON，不访问平台或GPU。覆盖正常新鲜观察、错任务、过期/未来时间、SHA错误、默认不执行、新旧原字节留存、已有RUN、软链接和不安全目录、冻结目录保护、RUN并发出现以及部分发布失败。
