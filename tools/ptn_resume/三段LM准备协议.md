# 三段主训练之后的大间隔微调准备协议

这是新三段检查器的设计，不是已经实现的LM执行器，更不是本次PTN恢复包的执行许可。现有两段检查器继续要求第二段完成36—120并成功；vggvm实际失败，它应该继续拒绝，不能把Succeeded改成Failed后放行。

三段的完整轮次分别固定为原任务1—35、失败vggvm已完整36—47、新恢复段48—120。vggvm的部分48单列保留为失败重做，不计入完整轮次；新段起点只认model47完整模型/动量/scaler和705047绝对时钟。原35→36八份恢复证明与新47→48八份证明分开绑定，不用旧成功覆盖新缺证据。

未来新检查器至少要读回以下原件：

1. 三段实际task/run身份、各自终态和无写入者证据；旧段Failed仅说明停止，不等于PTN目标完成。第三段必须真实完整完成120并具有实际成功证明。
2. 三份完整验证CSV分别精确覆盖1—35、36—47、48—120，完整训练末批与各段CSV相符；不重复或补造轮次。全谱系最佳必须从完整联合表选，不能只选第三段最佳。
3. 原七个已审FLAC事件仍只适用于原段；vggvm全部新异常保留，本次数值故障要有独立完整审查；新第三段异常逐条分类，不把历史许可整体搬入。未决异常必须列为未通过，不能删日志或放宽regex。
4. 原95/189、第三段新190与显式executor/helper差异、新包装和数据/映射身份分别核对。不能改原清单，也不能把公开派生audio_review当历史原字节。
5. 第115和120轮都必须来自真实第三段路径，字节、保存轮次、模型/优化器状态及稳定性合格；不能用旧vggvm路径做别名。LM仍依配方从115初始化模型，重建LM自己的优化器和scaler，而不是恢复PTN的SGD动量。
6. LM采用新独立输出和新合同；先做只读准备，真正启动前再在稳定独占锁下重核资源、来源和终态。任何CPU准备结果仍不授予LM执行资格。

建议新格式名`redimnet2-three-segment-lm-preparation/v1`，包含三个有序段、两条检查点恢复边、失败部分轮记录、逐段异常审核、联合验证表及best、第三段115/120引用，以及明确的LM冷优化器/冷scaler。不能让调用者用“全部通过”布尔值代替原件重读。

现在只实现model47→48的构建和状态比较，没有生成三段已完成记录、model115/120凭证或LM成功。待第三段实际完成并经过独立审阅后，再按本协议实现新检查器及正反例；旧工具和历史证据保留。
