# 第47轮接续包的真实双卡工程检查

这份工具不运行正式数据读取器，不提交平台任务，也不恢复旧故障波形。它只使用独立固定种子的合成波形与合法标签，验证新接续包在真实B6、357822分类头、单机双进程NCCL下是否能够完成优化、保存和恢复。结果不能替代正式八进程准入，更不能证明第48轮原故障已复现或修复。

入口是`tools/ptn_resume/engineering_two_gpu.py`。父进程只使用标准库与仓库的`word_ft_v3/resources.py`，不导入Torch或初始化CUDA。必须使用原PTN解释器启动；新包、合同和整个包的`bundle_files.json`都提供实际SHA。资源辅助代码、工具自身和可选新鲜平台证据的SHA会写入票据，worker重新核验。部署工具时须保持仓库相对目录，并同时提供仓库根目录的`word_ft_v3/resources.py`、`word_ft_v3/topology.py`及对应包初始化文件，不要把它添加进已经封存的190文件树或重封旧包。

每个case使用全新输出目录。输出必须位于源码、包、正式run、原实验保护树之外；按2026-11-09存储新规，默认放在共享盘的工程证据目录下：`/root/group-shared/voiceprint/artifacts/redimnet2/engineering/<case>-<日期>/`（旧例`/root/codex_artifacts/`属历史路径，不再作缺省）<!-- storage-policy-allow: 旧证据根的历史说明，不再作为缺省 -->。`--lock-root`应与其他协作程序使用相同的UUID锁目录；不能新造另一套锁来绕过既有占用。已有或未知compute PID即拒绝。0%利用率不能证明空闲。

维护者填入真实值后运行以下结构的命令，不能原样使用占位符：

```bash
/root/miniforge3/envs/redimnet2/bin/python -B \
  /absolute/repository/tools/ptn_resume/engineering_two_gpu.py \
  --package /absolute/new-package \
  --manifest-sha ACTUAL_BUNDLE_FILES_SHA256 \
  --contract-sha ACTUAL_RESUME_CONTRACT_SHA256 \
  --output /root/group-shared/voiceprint/artifacts/redimnet2/engineering/absolute-new-case-20261109 \
  --lock-root /absolute/shared-UUID-lock-directory \
  --expected-uuids ACTUAL_GPU_UUID_0 ACTUAL_GPU_UUID_1 \
  --case finite --max-seconds 1200
```

可选`--terminal-evidence /absolute/new-reference.json`提供原任务及失败前驱的最新平台原件引用，内容与`state_gate.verify_restored`的`terminal_evidence`接口一致。工具会固定这份引用文件的实际SHA；引用的两份原件仍由状态检查器重新检查任务、终态及新鲜度。未提供时沿用合同中的引用，陈旧就拒绝，不能改旧合同掩盖。

父进程持有两张UUID锁并做间隔至少5秒的两次空闲快照。两worker首先核190文件的新包和资源票据，分别写ready；父进程再读取一次真实空闲状态，确认身份后写CUDA ACK。只有收到ACK才能建立CUDA上下文。随后只启动一个`torchrun`，`nproc-per-node=2`、`max-restarts=0`。退出后再用两次快照检查所有compute PID已消失且显存回到保守空闲范围。无法证明自有进程组身份时不对未知进程发送信号；清理尚未证明完成时不能先释放锁。父进程不会把运行中的host PID当成已证明的本容器PID。

Torchrun版本可能为每个rank建立独立session，因此launcher退出并不能证明rank已经退出。ready原件还记录各rank实际PID、PGID、SID、启动时钟及本任务随机标识；父进程独立读取`/proc`核实，记录全部已证明的rank组后才能ACK。清理分别处理已证明的rank组和launcher组，并检查继承本任务标识的其他子组。身份或资源归还存在未知状态时，只保持锁等待和保留异常，不能杀未知进程，也不能释放锁假称完成。`--max-seconds`限制正常执行阶段，清理及资源归还等待可能超出它；1200秒不是整个工具的绝对墙钟上限。

清理先用内核公开的进程组和父子关系筛选本任务候选，才读取这些候选的随机标识，不读取无关新进程的环境。父进程来不及登记、但已经写ready的rank，仍须逐项重新核对真实PID与启动时钟后纳入。没有CUDA ACK且ready不齐时，未登记的CPU worker不可能通过本工具进入CUDA；工具保守留120秒退出宽限，不凭自报PID去杀进程。

## 有限数值与恢复检查

每个worker从独立新源码构造模型，严格加载model47、两组SGD动量和AMP缩放器。调用包内`state_gate`再次逐项比较原件，核原配方的705047时钟、学习率0.72和margin0.2。这里检查的是原W8配置谱系，实际工程通信仍只有W2，结果明确记录`formal_W8_admission:false`。

合成输入固定为每rank96×1×32240个float32采样点；种子和实际PCM摘要写入独立文件。没有真实音频，也不授予合成数据训练资格。运算使用原损失、学习率和AMP；为比较恢复，额外固定确定性后端策略。若缩放器因梯度溢出自动跳过SGD，只调用原有scaler.update进行正常backoff，不手改scale、学习率或裁剪梯度。每个实际更新最多尝试8次，参数`--max-attempts-per-update`可以明确调整但不得超过32次。每次实际SGD调用用优化器post-hook计数；正常AMP跳过另计，不能算优化步。非有限输入、向量或损失仍立即停止，不能为凑更新数量跳过坏批。

1. 第一步逐次前向、反向，直到真实调用一次SGD；这次更新的已有梯度必须全部有限。此前的正常AMP跳过另计，并逐项记录BN计数器变化。两rank核实实际更新数、attempt时钟和缩放器状态一致。
2. 每个rank分别保存完整第一步模型、优化器、缩放器、所有注册buffer和Python/NumPy/Torch CPU及本卡CUDA随机状态；文件摘要绑定该原件。
3. 按第一步实际成功后的绝对attempt时钟，连续完成第二次真实更新，保存CPU比较状态。删除旧模型、优化器和DDP包装，重新构造这些对象，严格加载第一步文件及随机状态，再完成第二次更新。
4. 精确比较模型、所有buffer、优化器、缩放器、随机状态，以及第二次更新前每个attempt的时钟、损失和自动跳过轨迹。这里确实重新构造了模型/优化器/DDP，但没有退出再创建操作系统进程，结果明确记录`process_restart_tested:false`。

耗时与吞吐只统计工程优化步本身，不把模型构造、保存、SHA回读及精确比较混成正式训练速度。峰值显存同时记录实际分配和保留字节数。两卡吞吐不能直接承诺八卡训练速度。

实际后端状态逐rank记录Torch/CUDA/cuDNN版本、TF32、确定性与CUBLAS工作区。cuDNN TF32维持原训练的True，矩阵乘TF32维持False；`deterministic_algorithms=True`和`CUBLAS_WORKSPACE_CONFIG=:4096:8`是额外工程设置，用于本工具内部连续与恢复比较。两rank归约与这些额外策略都不能冒充生产八rank的相同数值轨迹；只有模型、AMP、优化器、学习率和损失的配置保持原样。

## 独立注入故障

另用一个全新输出目录运行`--case injected-failure`。它仍恢复同一真实模型，但只在rank0人为把模型输出乘NaN，验证所有rank在反向前完整保存故障包并协调停止，不执行优化步。这是明确的注入测试，不能写成第48轮故障重现。两rank各自的payload、完成标记及协调文件须在真实执行后重新读取核验；父进程最终仍要证明资源归还。大文件导出限速和回读可能需要约100秒，最多1200秒只约束本次工程运算与等待，不能因超时去杀未知进程。

## 大型保存文件的只读回读

`tools/ptn_resume/inspect_engineering_artifacts.py`独立检查实际保存字节。显式传入两个候选包路径及各自包摘要、finite和injected目录以及全新外部报告路径；`--help`列出参数。必须在解释器启动前设置`CUDA_VISIBLE_DEVICES=''`。先使用标准库完整计算四个大文件的SHA，再导入Torch，以单线程CPU、`weights_only=True,mmap=True`读取，检查模型、动量、缩放器、缓冲区、输入、随机状态及原件绑定；不构造模型、不前向、不操作GPU。默认摘要读取速率为32MiB/s，可明确限制在1—64MiB/s。

检查器逐项核两个候选包实际成员及源清单，分别列出模型源码是否相同、运行包装有哪些变化。它不会把候选2的工程结果当成候选3的新八卡进程门已通过。连续/恢复第二步的全状态精确比较由固定工程源码在运行时执行，若没有另存两份第二步张量，离线检查器会明确说明这一范围。检查失败返回非零退出码，仍在新的外部报告中保存原因；不覆盖输入、旧报告或包。

命令必须另外提供`--runner-sha`，当前只接受独立审阅过的`54e089818583d69bf1c5b93c45363b6603ab17b5d8124b24282ed78bcdccb9e4`，并核两case记录中的工程源码身份相同。CPU RNG使用独立CPU生成器实际`set_state`，不影响全局随机状态；保存的CUDA RNG只做字节结构检查，输出明确写`cuda_rng_restoration_tested:false`。不能把离线CPU检查写成重放了CUDA随机过程。
