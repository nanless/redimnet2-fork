# 主训练接续的只读参考源码

这里补齐了当前主训练接续实际使用过的参考实现，供阅读和核对代码身份。它不能作为新的运行包，也没有获得新仓库版本的 GPU 验收。现有服务器训练、冻结目录和检查点没有被修改。

`archive/` 中有 9 个 Python 文件与 `launch.sh`，共 10 个参考源码文件。其中 9 个保持历史 `bundle_v3` 原始字节；`audio_review.py` 明确使用已审阅的公开派生版，移除了两项固定诊断样本标识，没有把该版本冒充历史执行源码。文件以不可执行的普通参考文件保存。逐文件字节数、当前 SHA256、历史 SHA256 和 exact/derived 身份见 [`archive_index.json`](archive_index.json)，该索引自身的 SHA256 固定在检查工具中。索引是本仓库的参考清单，**不是原运行包的 `bundle_files.json`，不能改名替代原凭证**。

## 每个文件的用途

| 参考文件 | 历史实现负责的检查或动作 |
|---|---|
| `entry.py` | 唯一主训练接续父进程；核旧任务终态、锁、环境与依赖，再准备一次八卡启动，最后核退出和保存。它包含实际启动与清理逻辑，因此不能为看代码而执行或导入。 |
| `worker.py` | 每个训练进程读取冻结训练源码、恢复状态和运行条件，在模型前向或更新前执行检查。 |
| `strict_restore.py` | 核源码、依赖、配置、检查点、实际导入位置和完整恢复结果；不允许用宽松恢复掩盖差异。 |
| `loader_worker_audit.py` | 在数据子进程产出第一批数据前记录实际子进程和加载器证据，核对训练确实使用预期工作进程。 |
| `epoch_guard.py` | 在每个训练进程的轮次入口执行保护，不把方法附着到数据集对象而引入额外序列化行为。 |
| `predecessor_gate.py` | 有界等待并核对前驱任务的外部终态凭证，检查等待前后文件是否改变；自身不启动训练。 |
| `decoder_runtime.py` | 核隔离音频解码库的文件身份与实际已加载库；要求在解释器启动前选择库路径，不在进程内热换库。 |
| `audio_review.py` | 明确的公开派生版：复用 `tools/lm_continuation/legacy_checks/audio_review.py`，按外部事件记录检查原音、解码窗口和完整原声身份；移除历史固定样本名后具有新的代码摘要。它不是历史原字节或实际执行证明。 |
| `cpu_check.py` | 历史真实模型检查点的 CPU 恢复与解码检查；文件名中的 CPU 不表示它不需要模型、Torch 或原始凭证，不应在归档审查中运行。 |
| `launch.sh` | 历史固定目录的启动包装；要求外部审阅过的原包摘要，并设置原解释器与解码库环境后执行 `entry.py`。原绝对路径为追溯而保留，不是本仓库新部署约定。 |

## 为什么默认不能运行

仓库没有复制或重新生成以下运行原件：原 `bundle_files.json`、`dependencies.json`、`source_189.json`、`resume.yaml`、前驱或失败任务终态、`audio_selfcheck.json`、成功或完整保存凭证、异常事件逐条审阅记录、真实音频、检查点、私有解码库、共享 GPU 基础库，以及被固定摘要绑定的完整训练源码树。需要外部原件的引用仍照原字节保留，缺少它们就应拒绝，不能补空 JSON、伪造成功记录或改摘要绕过。

不要执行 `archive/launch.sh`，也不要导入归档中的模块。它们包含历史启动和进程管理动作；只读参考并不使这些动作变成新授权。若以后确实要构建新主训练接续包，应另用明确的源码、模型、原异常与实际终态证据重新准备、审阅和验收，不能把这里的语法检查当成运行准入。

## 只核摘要和语法

从仓库根目录执行：

```bash
python3 tools/ptn_reference/audit_reference.py
python3 -m unittest discover -s tools/ptn_reference/tests -v
```

检查工具只使用 Python 标准库。它先核固定索引，再核精确的 10 个文件集合、文件字节数与摘要、软链接和读期间变化；Python 只编译语法而不执行，Shell 只用 `bash -n` 检查而不展开或执行历史命令。系统需有 Bash。额外的凭证文件、缺文件、字节变化和不合法语法均拒绝。合成测试还把“执行后立刻抛错”的 Python 和“创建标记文件”的 Shell 交给检查器，确认二者都没有执行。

正常检查的返回码 0 只表示参考代码完整性和语法通过，并明确返回 `historical_exact_files=9`、`public_derived_files=1`；不会声称十个文件全部为历史原字节。结果始终保留 `runtime_admission=false`、`historical_execution_proven=false`。显式要求运行准入时会拒绝并返回 2：

```bash
python3 tools/ptn_reference/audit_reference.py --require-runtime-admission
```

本次只新增参考源码与静态检查，不读取完整训练数据，不加载检查点，不导入音频运行环境，不访问服务器，也不启动 GPU、停止或迁移现有训练。

## 公开派生版的身份差异

独立审阅发现历史 `audio_review.py` 包含两项实际诊断样本标识，不适合直接公开。原件仍保留在受控实验目录，没有改动。这里的历史摘要为 `30f0f1f6fb9aecd9b5b4f8f00187ef6014982153a5df7107cf0ed4dcfcd06156`，公开派生摘要为 `f5d69d59148df4f2c8693f8f67dbd432823a41c3642016b07819210e6533c507`，差异在索引中并列记录。派生文件的具体字节与仓库已审阅的大间隔微调检查模块相同；不因此改变其他九个历史文件，也不继承原运行包的准入资格。

独立审阅已经逐文件复核上述9项历史原字节与1项公开派生身份，并重新运行6项合成测试和返回码0/2检查，均通过。记录见[`docs/reviews/PTN只读参考_有限独立复验.json`](../../docs/reviews/PTN只读参考_有限独立复验.json)。这仍只证明参考完整性与静态检查，运行资格保持拒绝。
