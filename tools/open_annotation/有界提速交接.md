# 转写提速的有界交接：不重开全库、不建设数据库

这组程序将已完成来源留给原生产者，只为缺失来源建立新生产者；它不停止任务、不启动模型、不创建CUDA上下文、不扫描所有音频或侧车。新计算合同不能直接写旧queue，也不能把旧结果改为新合同的job_key。新schema已显式接入worker、bootstrap和资源控制器，详见[有界提速正式运行](有界提速正式运行.md)；实际有限GPU恢复与质量证据仍须另行验收，CPU测试不是八卡上线许可。

## 为什么旧队列不能直接改配置

旧`WorkQueue`的identity同时绑定索引SHA、合同SHA、来源数和片数。旧`SidecarStore`还绑定version、contract、source完整记录及job_key；旧`Claim.finish`要求每条receipt都是当前单一合同的job_key。BF16、SDPA或计算引擎改变后，不能更新一个配置字段继续将旧queue／labels冒充同一生产者。

旧worker没有“完成当前片后暂停”的入口。父进程收到SIGTERM会进入异常清理，清理其精确自有worker；不能将它描述成优雅片尾停止。停止时可能留下完整已封账片、片内已发布侧车、阶段缓存、未完整推理，以及侧车已写但commit未写的孤儿。所有证据保留，不能删锁或将停止后的进程年龄当接管资格。平台停止动作、真实终态及GPU排空由操作者另行确认，本程序不执行信号或平台操作。

## 一、有界准备

维护入口为`bounded_speed_handoff.py`。显式输入描述schema为`annotation-bounded-speed-handoff/v1`：

- `purpose`为production或cpu_fixture；production的原总分母固定11,521,178。
- `old_index`、`old_contract`均为绝对路径和实际SHA；`old_queue_root`、`old_sidecar_tree`、`old_task_id`明确指向当前writer。
- `global_source_count`、`previous_retained_count`与当前旧索引来源数严格守恒。
- `new_queue_root`、`new_sidecar_root`必须与旧producer及彼此分离。
- production必须提供`portable_spec`路径和SHA。它复用`portable_source_identity.py`的既有显式内容证明，绑定本次旧合同、当前父索引、旧queue及旧labels；允许差异仍仅为device，不能删stat字段。

默认只读索引、一个broker快照和已完成固定槽，输出preview，不读取在途侧车或任何未领取JSONL，不取得旧锁，不生成可执行索引。

```sh
python -B tools/open_annotation/bounded_speed_handoff.py \
  --spec /ABS/bounded-spec.json --spec-sha SHA256 --output /ABS/NEW-preview
```

最终模式还需实际旧writer的新鲜终态观察、既有`.parent.lock`及最多8个既有claim锁全部可独占取得。没有创建或替换这些旧锁；已封账片只封存固定槽原字节，不重开其全部侧车。只读取最多8个在途片、总上限4096来源；已有侧车和commit逐条验证，原生／FIX／异常原字节保留。部分片中缺失来源写入新的小JSONL，已存在的结果写原producer引用。未领取片只复制元数据描述，实际JSONL文件不读、不复制。

```sh
python -B tools/open_annotation/bounded_speed_handoff.py \
  --spec /ABS/bounded-spec.json --spec-sha SHA256 --output /ABS/NEW-final \
  --execute-final --terminal /ABS/actual-old-terminal.json --terminal-sha SHA256
```

已存在侧车才执行内容证明：核编码SHA、读取前后完整stat、共享挂载别名，唯一允许device改变。任何其它stat差异、内容SHA变化、孤儿或损坏均保留并拒绝。历史解码失败可原样保留，但不得声称当前内容验证成功。侧车读取上限512MiB，已有原音编码读取上限4GiB；没有对缺失来源哈希媒体。程序不调用目录项库、联合库、ASR阶段数据库或SQLite连接。

主要输出为：

| 文件 | 意义 |
|---|---|
| `index.json` | 显式`annotation-bounded-source-index/v1`，不是旧v1索引 |
| `partials/*.jsonl` | 仅在途片中确实缺失的来源 |
| `retained-completed-slots.bin` | 已封账槽原字节；不是侧车全审 |
| `retained-partial.jsonl` | 已发布的在途结果原producer引用 |
| `portable-retained-partial.jsonl` | 已有侧车对应的实际编码SHA／新旧stat证据 |
| `report.json` | 精确守恒、读取范围、摘要与尚未授予GPU资格 |

原父索引的来源唯一性沿既有准备证明继承，不重做全库审查。`BoundedShardReader`构造时核真实旧index、contract SHA/version、queue identity、broker、已封账槽，以及最多8个在途片的原JSONL／小partial／retained ledger／真实commit。它要求全部未领取父后缀元数据逐项完整，不能删一片再缩小自报计数；每个lease的保留与缺失必须严格守恒且来源集合不重不漏。未领取JSONL在构造时仍不读取；`read(shard_id)`到实际领取该片时才核它的原父描述及JSONL摘要。不能把这个新schema直接传给旧`WorkQueue`。

## 二、旧锁必须贯穿新GPU生命周期

`bounded_speed_queue.py`提供`ExistingProducerLease`。GPU父进程在创建任何模型之前，重新核实际终态、计划／父索引、broker、固定槽和锁inode，再持有所有旧锁：

```python
lease = ExistingProducerLease(index_path, index_sha, terminal_pin).__enter__()
# ticket中固定 lease.fd_evidence，Popen显式传 pass_fds=其他锁 + lease.pass_fds。
# 原W2、以前继承的语义／队列锁、当前设备锁和CUDA独占监控继续保留。
# 所有自有GPU子进程退出且CUDA context已实际排空后，才lease.__exit__。
```

子进程不能重新open同一旧锁再竞争父进程，应由受资源ticket绑定的实际FD继承：

```python
lease = ExistingProducerLease.adopt_inherited(
    index_path, index_sha, terminal_pin, ticket['old_writer_lock_fds'])
```

该接口核实际FD、device、inode和锁路径；production还要求Linux`/proc/self/fdinfo`显示FLOCK WRITE。它复制同一打开描述，父关闭自己的FD后，子仍持旧锁；不是依据一个手填整数假称占有。ticket身份和实际继承必须由原资源控制器校验。CPU合成fork／FD测试不代表真实GPU子进程已经正确接入或排空。

本类只管旧writer互斥，不管GPU进程清理。资源控制器必须保留原nonce／PID-start／pidfd清理和context归还；不允许在异常时先释放旧锁、把仍有CUDA后代的卡称作空闲。父给每个GPU子进程传FD，让父异常后旧锁至少存活到持有它的子进程真正结束。

## 三、新队列及worker最少集成位置

`BoundedWorkQueue(index_path,index_sha,new_queue,new_contract_sha,new_sidecar_tree,lease)`使用新identity与新完成收据schema。输入根、输出根、旧producer和新合同都显式绑定。它只写新queue，不更新旧broker、不清旧lease、不重贴旧标签。新片原子发布与固定槽、代次、稳定claim锁均保留；可重获的中断片优先补完，不能按租约时间强占活worker。

新worker领取片之后、开始任何模型或阶段缓存新执行之前：

```python
with queue.claim_next(worker_id) as claim:
    for source in claim.sources():
        old_receipt = queue.previous_receipt(claim, source)
        if old_receipt is not None:
            receipts.append(old_receipt)  # 原contract/job_key/tree及内容证明
            # 独立计retained_existing，不计新ASR或新FA吞吐。
            continue
        # 原SidecarStore对新producer的lookup／阶段缓存／推理／publish。
        receipts.append(new_receipt)
    claim.finish(receipts)
```

已有原结果的查找只发生在当前片，不提前遍历未来片。原结果在新节点发生device变化时，复用同一严格portable证明；生成的原音SHA与新旧stat写入新chunk receipt中的`portable_source_evidence`，旧record／commit不变。`finish`重新核证明与原sidecar／commit绑定，不再次哈希媒体，不放宽其它字段。若新旧producer对同一来源都有结果，调用方须保留并明确拒绝或解决来源归属，不能按mtime挑一份。

新queue的chunk receipt可以逐源混合“原producer保留”和“本producer新计算”，每条都显式保存producer SHA、原job_key、tree及retained标记；缺失、重复或陌生来源拒绝。计数必须区分新推理、旧结果复用、新queue消费完成量，不能把保留结果写成新模型速度。旧`readonly_progress.py`不接受新queue schema，不得用旧parser强读。新模块已有`inspect_bounded_progress(index_path,index_sha,queue_root,contract_sha)`：只读取一个新broker和其中已封账固定槽，核每槽checksum、输入／producer绑定及current／retained来源和decision拆分，返回新queue消费下界和全局下界，不构造队列、不取得锁、不重开侧车。构造reader会复核最多8个旧在途片的JSONL和小commit，报告单独记录这部分读取；未领取JSONL为0。current_producer数量不等于当前attempt实际模型调用数，不能据此冒充新推理速度。

新`verify_bounded_terminal_metadata`确认全部槽封账并双读摘要稳定。GPU父内部传自己已持有的新queue `parent_lock_fd`，production核实际FD／inode／FLOCK；外部调用则须实际新鲜平台终态和可独占的原新queue父锁。它只给`metadata_complete`，明确不认证CUDA归还、完整侧车或人工质量。原v1路径及其要求不变，父launcher仍须另外证明所有GPU context实际排空。

## 四、冻结与实际验收缺什么

新worker／bootstrap／父launcher必须明确选择上述新接口，把两新模块及其真实依赖全部进入新冻结包和source-file校验；旧23文件包不改。父／子ticket、run描述、资源控制器和数据门仍要按新schema验证；新索引不是替换旧W2／平台／模型／挂载／质量检查的许可。

至少完成以下实际有限检查后才能接正式八卡：同一三域输入的冷速度及完整结果对照、真实旧／新producer混合保存、已提交后中断恢复零重推理、未封账小片恢复、资源归还及旧锁直到CUDA排空后才释放。孤儿需要单独按旧合同的严格恢复流程处理，不能因新合同想跳过而伪造commit。当前方法不会建立新数据库。
