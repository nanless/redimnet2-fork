# 跨引擎对照的输入、计账和恢复边界

`engine_protocol.py`和`audit_engine_comparison.py`读取已经保存的有限对照结果，不导入真实模型、不执行GPU、不领取队列，也不重读或哈希原音。它们与旧的单窗算子对照工具分别维护，旧工具的同源码、单窗限制没有放宽。

## 固定什么，允许改变什么

比较描述使用`annotation-engine-comparison/v1`。`purpose`只能是`cpu_fixture`或`pilot_validation`，`mode`可取`end_to_end`或`fixed_text_alignment`。最多20000个来源，不能拿它扫描运行中的千万条全量任务。

`fixed_controls`逐项保存`{value,sha256}`，摘要针对同一份实际JSON值计算，字段必须完整且两轨相同：模型权重、预处理、窗口与原采样钟、提示文字/语言政策、生成上限与非采样设置、质量规则、定位配置。`controls_from_contract(contract)`从实际固定合同生成这些字段。未知runtime字段也作为固定条件保留，不会因未识别便自动忽略。

`allowed_changes`只能显式列出`backend`、`code_sha256`、`precision`和`batching`。`code_identity(contract)`计算工程/第三方源码和依赖版本声明的合并身份；它与整个冻结文件包的摘要不是同一值。每个producer另须声明`bundle_sha256`，最终侧车的冻结包身份必须与它一致。

每轨producer使用`annotation-engine-producer/v1`，包括`producer_id`、`purpose`、固定的`contract:{path,sha256}`、`bundle_sha256`、`fixed_controls`、四个变量、`model_API_calls=0`与`release_training_labels=false`。来源的最终侧车仍使用已有完整格式和逐源commit，不能把新producer写进旧结果。

vLLM轨另外声明`native_asr_spec:{path,sha256}`及`native_asr_producer_sha256`。工具实际读取并校验这份配置，不能只提供一个看似合法的散列：配置的模型文件SHA、生成上限、seed、非采样政策、强制语言、上下文、支持语言、精度、批上限、窗口/规范化、源码及依赖身份都须与实验控制条件对应。旧合同没有明确这些控制项时，应建立新的受控小实验，不能事后给旧运行补造观察。

## 来源全集和每轨文件

描述文件的主要字段如下；所有引用都是实际绝对路径及完整小写SHA256。

```json
{
  "schema": "annotation-engine-comparison/v1",
  "purpose": "cpu_fixture",
  "mode": "end_to_end",
  "fixed_controls": {},
  "allowed_changes": ["backend", "code_sha256", "precision", "batching"],
  "inputs": {"path": "/absolute/inputs/sources.jsonl", "sha256": "实际摘要"},
  "baseline": {
    "producer": {"path": "/absolute/base/producer.json", "sha256": "实际摘要"},
    "results": {"path": "/absolute/base/results.jsonl", "sha256": "实际摘要"},
    "metrics": {"path": "/absolute/base/metrics.json", "sha256": "实际摘要"}
  },
  "candidate": {
    "producer": {"path": "/absolute/new/producer.json", "sha256": "实际摘要"},
    "results": {"path": "/absolute/new/results.jsonl", "sha256": "实际摘要"},
    "metrics": {"path": "/absolute/new/metrics.json", "sha256": "实际摘要"}
  }
}
```

这里的空`fixed_controls`和中文摘要仅说明位置，不能直接运行；应使用上述生成函数和实际文件摘要构建完整记录。测试中的`make_case(root)`提供完整、可执行的合成文件示例，不包含原声或模型。

`inputs`的每行有完整`source`、已保存的`source_identity`和计划`windows`。窗口身份包括原声上下文/拥有区采样点、模型PCM摘要/帧数/采样率、重采样及时钟规则；固定文字模式还须逐窗给出`fixed_text`。

每轨`results`逐行包含`source_id`、`sidecar`和`commit`两项固定文件引用。`execution`按实际窗口编号保存`asr`与`alignment`，各取`new`、`cache`、`reused`或`not_run`。vLLM实际新执行窗口须有`native_asr_refs`，保存独立的`annotation-asr-native-result/v1`文件引用。工具核稳定请求ID、原生内部请求ID所保存的证据、生产者、PCM、token/EOS、终止理由、规范化和最终ASR字段。原生内部`native.request_id`必须是非空、非纯空白字符串；阶段`cohort_sha256`必须是完整小写SHA256，不能删字段或写空值后更新文件摘要蒙混过关。两项形状核验保留真实阶段关联证据，本身不等于重新证明GPU执行或阶段数据库的整批内容。原生unknown、truncated或failed不能被最终侧车偷偷改成completed。

来源集合必须精确覆盖固定输入，重复、漏项和额外来源都拒绝。解码失败且没有窗口的来源仍须提供完整失败侧车和commit，错误原文保留在分母。成功解码的PCM和窗口身份不一致时拒绝，不能把输入变化称为引擎差异。

## 文字和字界怎样比较

`end_to_end`核每轨定位的目标与它自己的转写一致，再比较文字、语言和可比的时间。`fixed_text_alignment`核定位使用同一份显式固定文字。只有目标文字和原生词项序列相同、向量数量对应且数值有限时才算端点差；目标不同或缺窗时返回未测和空值，不记0毫秒误差。原生、FIX和错误观察分开保留，这些差异不等于相对于人工金标的准确率。

跨引擎不要求原生token或logits逐位相同。原生输出仍按各自真实格式保存，不能通过拼造旧字段来声称等价。特别是vLLM原生stop证据与实际输出中观察到EOS分别记录；无EOS不得伪填`eos_observed=true`。旧侧车规则仍可能把缺少EOS的记录保留为unknown，本工具不改变其训练资格。

## 计时、恢复和输出

每轨metrics使用`annotation-engine-metrics/v1`，有producer SHA、完整来源数、`whole_run_wall_including_loading_and_publication`时间基准、正的`wall_seconds`、API0和显式`synthetic_fixture`。ASR/定位四种执行类别的窗口数必须与逐行记录重算一致。

只有非CPU夹具、没有复用/缓存、固定窗口齐全且保存计账声明覆盖真实新执行时，才输出`reported_new_execution_wall_ratio`。这只是已保存记录报告的墙钟比例，不自认证真实GPU运行；`GPU_runtime_verified`始终为false、`validated_GPU_speedup`始终为空。真实GPU资源组证明仍需后续另接，不能凭一个JSON文件授予模型性能结论。

可选`published_before`引用`annotation-published-before/v1`，其中`entries`保存既有`source_id/sidecar/commit`。恢复后的对应引用必须原样保留，工具重新核字节摘要；这不要求未提交计算跨引擎逐位相同。旧文件缺失或改变时拒绝，不补commit、不修复或重新生成旧结果。

```bash
python3 -B tools/open_annotation/audit_engine_comparison.py \
  --spec /absolute/inputs/comparison.json --spec-sha '<实际SHA256>' \
  --output /absolute/review/new-report.json
```

输出只能写独立既有目录的新文件，不能进入输入、合同、侧车、原生阶段结果或计时所在树。报告含真实转写及来源ID，应保留在私有审阅目录；不提交公开Git。报告固定不授人工质量、正式训练/评测或八卡准入。

本轮实际测试使用合成文件，并包含假vLLM完整阶段提交、原生结果文件、最终侧车/commit、对照及只带元数据恢复的串联检查。它证明对应CPU行为，不证明真实vLLM/CUDA版本兼容、吞吐或完整字准确性。
