# 独立云端的转写提速串行验证

`run_bounded_speed_pilot.py`只执行明确固定的有限pilot，不选择正式生产剩余来源，不连接旧标注队列，不创建数据库，不自动切换八卡。原PTN和当前八卡标注继续使用原进程与冻结包。云任务名称以`zhounan_`开头，优先级6、最长6小时、自动重试关闭；这些平台配置仍须提交后回读，驱动本身不能认证平台表单。

## 固定计划

先用[有限同批准备器](有限同批转写提速准备.md)分别生成30与3000三训练域的prepared.json，三轨顺序必须为显式FP32/eager、FP32/SDPA、BF16/SDPA。两份prepared使用相同代码、模型、执行器与全局设备锁；30来源是3000的完整记录真子集。准备器应在源码全部稳定后封存，不能边改边冻。

```json
{
  "schema": "annotation-bounded-speed-pilot/v1",
  "purpose": "production",
  "model_API_calls_allowed": 0,
  "production_switch_allowed": false,
  "screen_prepared": {"path": "/absolute/screen-v1/prepared.json", "sha256": "实际SHA256"},
  "main_prepared": {"path": "/absolute/main-v1/prepared.json", "sha256": "实际SHA256"},
  "recovery_index": {"path": "/absolute/recovery512/index.json", "sha256": "实际SHA256"},
  "recovery_profiles": ["asr-bf16-sdpa"],
  "protected_roots": ["/absolute/current-annotation-run", "/absolute/current-PTN-run"],
  "wall_budget_seconds": 21000
}
```

`purpose=production`表示真实模型pilot，仍禁止正式生产切换。CPU合成演练必须显式cpu_fixture且提供测试假执行器，CLI不能借cpu_fixture真实启动模型；真实模式不接受替代执行器。500或512恢复索引也必须是3000的完整记录子集，不根据修改时间猜来源。可以显式为三轨都做恢复，但这不构成自动选型。

```sh
python -B tools/open_annotation/run_bounded_speed_pilot.py \
  --plan /absolute/plan-v1.json --plan-sha 实际SHA256 \
  --output /absolute/NEW-pilot-evidence
```

默认只核固定输入，不创建输出、不执行GPU。真实执行加`--execute`。计划、prepared、冻结源码、合同、索引与track均按SHA读取；输入采用普通文件和非阻塞打开，拒绝软链、FIFO与执行中置换。只接受已固定的gpu_launch路径及明确参数，不运行shell_command字段，不允许追加任意CLI选项。

## 每一步必须完成后才继续

1. 依次运行三条30轨。原gpu_launch负责实际UUID、设备锁、双快照、模型、上下文挑战、worker及归还。
2. 每一轨退出0后，先核parent_result合同／索引／bundle身份、完整readback、上下文排空、至少5秒归还双快照；再完整有限读取该轨侧车／commit。任何缺失或不一致都停止，不先起下一轨。
3. 三轨完成后做两份完整速度／文字／原生与FIX比较。缺少真实冷执行、完整分母或同原声窗口证据时，不进入3000。变化仍是模型方法差异，不是人工准确率。
4. 再依次三轨3000，沿同样的父归还、完整有限readback与比较。30每轨最大1800秒、3000最大7200秒，完成即退出；整任务预算耗尽即停止继续派发并通知本次父进程清理，不要求跑满时长。
5. 指定的恢复轨使用main同一冻结代码、同合同、同labels，新建有限512的queue和resource目录。不能复用已经全部封账的旧queue来伪造512条缓存消费。要求512全是完整侧车复用，新ASR／FA调用0、原始文字／字界严格一致、原侧车与commit的SHA／字节数／mtime／inode不变。

`report.py`对pilot_validation且来源不超过4096的完整复核使用有限set，保留逐来源和跨片重复检查，返回`source_disjointness_storage=bounded_pilot_memory_set`、`database_created=false`。驱动核这两个标记后才继续。正式全量的历史复核分支未改，本次不在真实数据上执行它。

## 中断与结果解释

TERM／INT只设置停止要求。驱动向本次精确Popen子父进程发送TERM，父进程按原资源协议清理自己worker并归还CUDA；驱动等待父退出，不向其它任务或GPU worker发组信号，也不在未清理时启动下一轨。所有命令、日志、异常、退出与已完成步骤保留，输出目录不能重用。

结果`all_finite_audits_completed=true`只说明这些有限任务和审计完成，`production_switch_allowed=false`、人工准确率未认证始终保留。`GPU_runtime_verified=false`是驱动不自授整体GPU验收的保守字段；每轨实际参数／forward／QKV证明在审计的`performance.actual_compute_execution_verified`和原上下文材料中，真实云平台／容器证据另核。不能因这个字段为false抹去实际调用，也不能用CPU合成结果把它改成true。

阶段数据、原文及差异含真实来源，留本机或任务专属私有证据，不入公开Git。原生产标签、异常、队列、缓存与冻结清单不由此驱动修改；正式新八卡交接仍单独审核，不复算已发布结果。
