# 仅元数据的标注进度

`bounded_metadata_progress.py` 用于运行中的新标注队列。它只核已经发布的
薄索引和准备报告、新队列身份、一次 broker 快照，以及快照中已经封账的
固定 1024 字节完成槽。不构造队列，不取得锁，不读任何来源 JSONL、
侧车、旧 commit、音频或模型，不连接数据库；默认只向标准输出返回 JSON。
它不会创建输出文件或目录，更不会启动、停止或修改标注与 PTN。

旧 `readonly_progress.py --bounded` 和
`bounded_speed_queue.inspect_bounded_progress` 会构造
`BoundedShardReader`，进一步核最多八个原来源片、partial JSONL 和旧结果
commit。这条严格闭包入口仍保留，但不能用它冒充本轮只读元数据进度。
新工具明确返回 `source_closed_scope_revalidated=false`、
`human_quality_verified=false`、`runtime_admitted=false`；来源闭包与运行
资格仍以已完成的原正式发布和原运行守卫为准。

必须提供薄索引、准备报告的实际路径和 SHA，以及新队列路径和合同 SHA。
准备报告须绑定这份索引，分母须守恒，计数必须为非负整数，未领取来源片
的顺序号必须为真正整数且连续；布尔值不能冒充 0 或 1。队列身份须精确
匹配索引和新旧生产者合同。对一次 broker 快照只读取非在途的前缀槽，
按该位置的分片 ID／SHA、合同、索引、来源数及新旧生产者计数逐项检查；
槽魔数、长度、摘要、补齐、完整字段集合和三种状态也都核验。

命令中所有占位符都必须改成已核原件；这只是说明接口，不能直接执行：

```text
固定Python -B /独立CPU工具目录/bounded_metadata_progress.py \
  --index /已发布薄索引/index.json --index-sha 实际索引SHA \
  --report /同次准备/report.json --report-sha 实际报告SHA \
  --queue-root /新run/queue --contract-sha 实际正式合同SHA
```

`committed_source_lower_bound` 是这个新队列已封账的来源数，在途工作和
快照之后的新提交排除。`current_producer_source_count` 与
`previous_producer_retained_in_this_queue` 分别记录新旧发布归属；它们不
直接代表本次新 ASR 调用数。`preserved_before_new_queue` 是发布前已经
保留的总量，不再算成新任务吞吐。`completed_by_storage` 区分最初八个
partial 和后续原未领取片，不能把较小 partial 的单片耗时当成正常整片
吞吐。`candidate` 是机器候选，`unknown` 是待审，均不等于人工完整字真值。

本轮操作最多取三份有意义快照。新 broker 尚未出现时只做间隔的单路径
元数据检查，不反复解析 11 MB 薄索引；首个完成片出现后取第一份，后续
至少间隔 120 秒。用新增条数除以实际时间差计算短窗口速率，并用同一
快照剩余量估计条件 ETA。它受在途片、业务音频长度和后续输入分布影响，
不是全程稳态或保证完成时间；失败数为 0 也不表示所有内部异常都没有。

九项普通与 `-O` CPU 反例均通过，覆盖完成槽损坏／额外字段／次序与
生产者不符、计数及类型伪装、在途坏槽排除、新旧归属独立、薄索引变化、
负数平衡计数和布尔顺序号。运行冻结源没有修改。实际采样还在独立调用
外加了读取审计守卫，禁止 JSONL、侧车、commit、数据库、模型、锁和写入
输入；完整小输出只保存在私有操作证据目录。
