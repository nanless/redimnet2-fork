# 有限原音的CPU和文件读取时延

`bounded_cpu_audio_timing.py`用于在不创建CUDA上下文、不导入torch、Qwen或vLLM的条件下，检查少量已核原件的编码读取、解码、摘要与窗口准备耗时。它不领取生产队列，不查看旧标注目录，不写原音／侧车或数据库，也不遍历数据集。进程以低优先级运行，数值库线程环境固定为1。

输入是明确的`bounded-cpu-audio-timing-input/v1`，最多24个唯一来源，编码总量不超过256MiB、单源解码PCM不超过64MiB。每个来源须含绝对`audio_path`、`source_id`、已保存的编码`file_sha256`及原采样率多声道`pcm_sha256`、`bytes/frames/channels/sample_rate`和最多8个原context窗口。每窗保存原源采样范围和实际16k单声道模型输入PCM SHA。输入来自已保存、身份核实的有限样本，不能用本工具临时扩样或扫描全库。

## 两次读取分别测什么

1. 首次只读打开编码原件，核打开前后stat稳定、大小及编码SHA。随后从这些已读字节在内存解码，核采样率、声道、帧数、有限PCM和完整原生PCM SHA；不会为这次内存解码再次打开原件。
2. 第二次只读打开同一原件，重核当前完整stat，再实际解码整源。核第二次PCM SHA，然后从内存中的连续原声切出已保存context，按既有均值单声道与`resample_poly`规则准备，并核每窗实际PCM SHA。上下文重叠只在内存取片，不额外重开原件。

每原件最多两次打开；首次身份不符就停止该源后续读取，完整异常保存，不能跳过失败只报成功均值。每步同时记录墙钟和本进程CPU秒。若预期主机不匹配，或进程已经导入重型模型模块，则在读媒体前拒绝。真实来源清单只放本机私有目录，不提交公开Git。

命令入口用base64传完整有限输入字节，同时提供它的SHA；这里只展示参数名，不提供真实名单：

```sh
env CUDA_VISIBLE_DEVICES= python -B tools/open_annotation/bounded_cpu_audio_timing.py \
  --inputs-base64 有限输入JSON的base64 \
  --inputs-sha 同一JSON字节的SHA256 \
  --expected-hostname 已核CPU测量主机名
```

默认结果写标准输出；操作者可保存到新的本机证据文件。远端可将同一维护源码按SHA绑定后通过SSH标准输入执行，不在服务器留下唯一实现或覆盖旧环境。输入不包含模型权重，推理GPU仍保持不可见。

## 结果不能解释成什么

这次测量不是生产worker原函数的逐阶段profile。为了限制读取次数，完整身份解码使用已读字节，第二遍整源解码后在内存切窗口；而旧生产流程是编码读取、完整PCM解码和逐window重开读取。共享盘页缓存、解码器缓存、文件布局、开发节点CPU负载及nice调度都会影响墙钟。因此不宣称冷缓存、不把开发节点CPU耗时直接除以云端总耗时，也不由这个结果计算八卡GPU阶段占比。

GPU利用率不是SM占用率，显存空余也不是新CUDA上下文的许可。判断转写提速仍须独立空闲GPU、同批实际模型、冷执行／复用分账、完整文字及结束证据、Ultra端到端、恢复与资源归还。本工具只补充CPU／文件读取的有限证据。
