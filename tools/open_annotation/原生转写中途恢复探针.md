# 原生转写中途恢复探针

目前的 512 来源接续检查会重新验证已经完整发布的侧车是否原样命中，并
确认没有再次执行 ASR 或强制定位。它不能证明另一种更早的中断可以恢复：
ASR 的第一个整批 JSON 已经保存，但后续整批尚未完成，整个来源组还没有
返回文字结果，更没有发布完整侧车。这个探针专门验证后者，不把全命中
恢复当作整批事务中途恢复。

## 独立任务与输入

`run_native_partial_recovery_probe.py` 默认只检查计划。真实执行必须显式
加 `--execute`，只用于另一个全新的单机两张 A800 任务，最多 1800 秒运行
预算。到期先让已有精确子父进程按原监督器清理，再退出；安全等待不能
为了卡住一个时间数字而提前结束。此探针不提交平台任务，不发送 API，
不修改正在进行的三千条试验、八卡标注或 PTN。

计划格式如下。所有路径和摘要须由本次真实准备结果填写，不能复制例子
里的占位值。任务名遵循 `zhounan_` 前缀，优先级与平台提交由外层操作。

```json
{
  "schema": "annotation-native-mid-cohort-probe/v1",
  "purpose": "production",
  "candidate_prepared": {"path": "/绝对路径/screen-v1/prepared.json", "sha256": "固定准备文件SHA"},
  "profile": "native-fp32-sdpa-b8",
  "anchor_source_id": "固定25.088秒原件的来源编号",
  "protected_roots": ["/既有PTN目录", "/既有八卡标注目录", "/既有独立试验目录"],
  "wall_budget_seconds": 1800,
  "controller_sha256": "run_native_partial_recovery_probe.py实际SHA"
}
```

只接受已经成功完成的固定 30 来源原生批次矩阵，候选批宽只能是 4 或 8。
重新检查原来的冻结源码包、合同、侧车、整批原件与父终态。原来三轨的
模型、FP32/SDPA 转写、Ultra FP32/eager 单窗、文字和源时钟规则都沿用，
没有重新冻结或修改 15 个计算语义源码。控制器本身的摘要进入计划；
SerialExecutor、原生试验驱动、合同、auditor、进程身份、严格JSON读取和
GPU 资源/拓扑守卫等九个依赖必须与候选冻结包中的原字节相同，不允许在
探针名义下换掉清理或资源规则；每阶段前再次核计划和控制面摘要。

新输出目录必须与代码、旧试验、原输入、UUID 锁、平台既有任务和计划
文件彼此分离。30 来源改写为一个新的有限单分片，仅改变明确的读取
顺序，原始来源字典全部保留。首组固定为 8 来源，包含已核的 25.088 秒、
两个模型窗口原件，至少有 9 个实际窗口。首批宽 8 时还剩一个窗口，宽 4
时还剩后续批次，所以能够观察“已提交与未提交并存”。这段单分片验证
只有一个 worker 领取工作，另一张卡仍走真实上下文验收；不能把它当成
两卡吞吐测试或新八卡容量估计。

## 三阶段依次执行

1. 在新 `cold/` 树完整冷跑 30 来源，原 GPU 父完成原样的双快照、UUID
   协作锁、上下文证明、原生结果读回与终态资源归还。保存完整结果。
2. 在另一新 `interrupted/` 树，以同冻结代码、合同和新有限索引开始。
   观察器只读取这个新树中首组的一个固定 `plan.json`，据其中明确列出的
   批次路径检查第一个已原子发布的完整 JSON。它核完整计划、来源/PCM、
   cohort、全部行覆盖和真实生成行号，并等目标硬链接数回到 1，确认
   原子发布已完成目录 fsync 与临时名清理，然后设置本次 SerialExecutor 的
   cancel。SerialExecutor 只向本次 Popen 精确身份对应的父 pidfd 发 TERM，
   并等待原 GPU 父自行清理 worker。没有 worker 注入，没有手工停止 GPU
   PID，没有进程组泛杀，也没有接管未知进程。
3. 原父命令返回后，保存所有已提交包、已发布侧车和 commit 的字节摘要、
   inode、mtime，以及未提交批次清单。另取同两个 UUID 的协作锁，在锁内
   做真实 NVML 5 秒双空闲检查，无 compute PID、显存符合原守卫规则才
   释放。随后以同一 queue、labels、合同和单分片索引，创建全新
   `resources-attempt2`；原 GPU 父仍要重新走自己完整的资源前置检查。

观察器可能错过短暂状态。若原父中止时首组所有批次已经保存、整个分片
已经完成、没有完整首包，或者观察到的计划不符，应明确报告无法完成这
次探针，而不是把其它形式的缓存命中解释成中途恢复。侧车没有 commit、
孤立 commit、原子写留下的 `.tmp` 都保留并拒绝继续，不能删除证据后重试。

## 恢复验收与不能得出的结论

attempt2 必须满足下列条件：已有首包与计划的 SHA、inode、mtime 不变；
故障前已发布的侧车与 commit 同样不变；原已提交 cohort 每个窗口均为
实际 native 缓存命中，实际 worker 的缓存命中总数精确相符；原未提交
cohort 保持原成员、原顺序和原 cohort SHA，不能拆掉部分行另组批，也
不能假报缓存。原有完整有限 auditor 重新检查真实原生包、padding/EOS、
输入/行映射、模型调用与 worker 摘要，失败样本仍在 30 来源分母内。

最终与独立冷跑比较时，两个新树的 packet 绝对根必然不同。只在完整
auditor 已认证后，将这一个目录前缀显式换成各自树内相对路径；不修改
原文件。再交给原 `analyze(..., mode="recovery")` 比较其余完整窗口原生
输出、文字、源钟、定位和原生/FIX 时间。缓存旗标由原比较器按已有规则
处理；其它差异和失败完整保留。这个结果不授予文字或完整字边界人工
金标，也不自动批准正式八卡生产接续。
