# 剩余索引角色统计与独立定稿

`finalize_remaining_roles.py`修复已完成portable准备的剩余索引角色聚合，写同目录新文件。它不改运行中的准备器，不覆盖v1索引、计划、分片、队列、侧车、合同或冻结清单，不读音频，不运行模型。

原索引的`role_union_counts`表示该索引实际来源的角色计数。每条来源可同时属于PTN与LM，两项之和可大于来源总数。旧准备器复制全量header后仅更新来源数、分片及域计数，导致剩余索引仍携带全量PTN/LM数。这是元数据计账错误；现有worker不读取该聚合，不因此改变音频或重复推理，但不能作为剩余LM分母。

未来准备器在写实际剩余JSONL时同步数每源角色，拒绝重复或未知角色，保存：

- `role_union_counts`：当前剩余来源的真实PTN/LM计数，含零值；
- `role_union_counts_scope="remaining_index_sources"`；
- `parent_role_union_counts`及`role_union_counts_parent_index`：原全库计数和原索引引用。

正式portable联合门在现有逐源核验中重算剩余roles，要求与header一致，并核父级统计引用。没有额外媒体或缺失PFS路径读取，原全库分母始终不变。旧strict协议没有增加宽泛跳过选项。

## 已完成v1怎样独立修正

必须等v1的`coverage-plan.json`完整发布并取得其实际SHA。默认命令：

```bash
python3 -B finalize_remaining_roles.py \
  --plan /absolute/prepared-v1/coverage-plan.json --plan-sha '<实际v1计划SHA>'
```

输出同父目录三个全新文件：`index-roles-v2.json`、`coverage-plan-roles-v2.json`、`remaining-role-finalize-v2.json`。可分别通过`--index-name`、`--plan-name`、`--receipt-name`指定新的单文件名；不得包含子目录、父遍历，不得使用已有文件。原`shards/...`相对路径继续有效。不得仅把新index移到另一目录而不复制实际分片，也不能用`../`或软链绕过路径规则。

定稿器按引用核原计划、原剩余索引、原全集、旧合同、内容规范、账本及只读目录库。部分片和未领取片保留结果的原侧车与commit也按实际SHA核对；内容证明只验证已保存绑定，不重新哈希或解码媒体。原已完成片的百万份侧车或音频不会为了修改header而重新打开。

角色统计顺序读取既有剩余JSONL。整片必须对应原父片的相同SHA与数量；过滤片逐记录核相应原小片的子集，拒绝同一origin重复、改source记录或与旧保留目录项重叠。每条source角色分别计数，因此正确保留PTN/LM重叠。再由原full角色向量减实际remaining向量得retained向量，并核PTN恰等各自来源数、LM不超来源数。不能按域比例或保留比例猜LM数。

v2只更正角色统计、父级作用域和所指新计划名；分片描述、实际分片字节、每个source和其顺序相对v1不变。计划只改`remaining_index`引用并增加`metadata_correction`，保留其旧队列快照、历史终态、内容账本及目录库引用。收据分别记录旧/新index和plan的SHA、三组角色向量、工具源码SHA及继承范围。后续union spec、消费索引和启动数据证明必须绑定v2新SHA，不能继续复用v1的联合证明。

`version`中的full文字、`script_sha256`、`excluded_dataset_counts`、`parent_registry_lineage_only`、`source_record_policy`、`scope`等保留原文，作为父级lineage；收据的`inherited_parent_metadata_scope`明确本工具没有重新执行原filter。特别是`source_record_policy`里的raw-line-byte-identical说明属于原filter：过滤片在v1准备时可能重序列化等值JSON字典。`source_shard_bytes_changed=false`只表示**v2没有改v1分片字节**，不宣称过滤片与原父片整个字节相同。

全库媒体内容、GPU运行、模型文字/完整字质量以及新任务完成均未由本工具验收；它只生成可以继续数据核验的元数据。输出报告及路径包含来源信息，应保存在私有服务器审阅目录，不提交Git。

## 可见进度与CPU证据

正式定稿和联合核验向stderr写阶段开始、每30秒计数及完成JSON；stdout只保留最终完整报告。联合进度包括原全库行数、旧保留核验数和剩余核验数，避免长时间百万侧车审计只有无进度等待。CPU夹具可注入回调测试，不需要实际等30秒。

测试覆盖PTN/LM重叠、未来准备器精确统计、v1字节和mtime不变、新计划与实际联合门衔接、错SHA/旧输出/路径逃逸/账本篡改拒绝，以及角色聚合错误被联合门拒绝。都是小型CPU文件测试；真实全库结果以现场带输入和源码SHA的报告为准。
