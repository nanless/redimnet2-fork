# 两版单窗结果比较与少量连续上下文复核

这两项工具只诊断明确选中的有限试验。它们不启动模型，不接触正在运行的
PTN 训练，也不将任何自动输出变成可训练或可评测的人工作业成果。不创建
数据库，不遍历完整语料库。真实原音、逐字文本、来源编号和图均保存在
仓库忽略的私有 `.audit-local/`，不要提交到公开仓库。

## 旧单窗与新版单行批处理的结果能否衔接

`compare_native_b1_bridge.py` 比较旧版显式 FP32/SDPA 单窗与新版原生批处理
B1。调用者必须分别给出两份固定准备文件的 SHA，以及两份父终态文件的
SHA；准备文件不能改为后来重新选择的清单。工具最多接受 64 个来源。

核查分成两层。第一层重新读取有限试验的历史发布文件：父终态指向的
worker 摘要、ready 与 ACK，摘要所记录的各片完成收据 SHA，固定完成槽，
每源的结果与 commit SHA。逐源还重算 job_key，并核查模型、运行设置和
源码包身份。侧车与 commit 即使被一起重新签名，也不能越过父摘要中
早已记录的片段收据摘要。这不代替云平台实例身份或当前 GPU 空闲核验。

第二层才比较音频身份、模型输入时钟、文字、语言、状态、原始与有效生成
token，以及相同文字目标下的原生/FIX 端点。新版原生输出另验证 EOS 与
padding 后缀及原始/有效分母；旧单窗保存的 EOS 位置仍属于旧 hook 当时
记录的证据，工具不凭空补出旧版没有保存的真实 pad 配置。文字目标变化
时不计算看似为零的可比较端点差。错误和 VAD 元数据单列，不删除或修正。

2026-10-28 的固定 30 来源实测共 34 个窗口；两端文字、有效生成 token、
原始 token、PCM 输入及时间映射均相同，32 个具有相同目标的可比较窗口
原生/FIX 端点差均为 0。两版代码和实际云机器不同，因此工具刻意不计算
速度提升比例，也不把这一比较当作正式八卡准入或人工文字准确率。
私有 `old-sdpa-to-native-B1-bridge-v1.json` 保留旧观察方式；`v2` 增加明确
父摘要与有限发布链，两个版本都保留，不能覆盖旧证据。

## 只准备指定连续上下文，不按模型猜测裁成“完整字”

`prepare_boundary_context_review.py` 接收已有选择清单、选择清单 SHA、
请求表、请求表 SHA、原音目录和新输出目录。请求表逐条包含
`case_id`、`review_id`、`start_sample`、`end_sample`，没有自动扩选。
每次最多 24 来源、48 个上下文，单个上下文最长 28 秒。

工具直接复用 `plot_saved_boundary_review.load_case`：核编码原件 SHA、
原采样率多声道 PCM SHA、帧数、声道及侧车身份。目前只接受原生 16 kHz
单声道，以免这次诊断隐式引入重采样或混音。上下文按原采样点连续取出，
不删 VAD 外声音、不填零、不归一化增益，保存为 FLOAT WAV 后逐样本读回
核验。所有参考文字固定为空串，输出可直接给现有 `sample_audio_review`
的 blind 模式。工具只准备文件，从不请求 API。

同一次调用画上下文波形、频谱、旧 VAD、原生时间、作者 FIX 时间和最终
源采样时间。`--plots-only` 可以用另一版本的侧车画同一上下文，不重新
生成或提交音频。零长和倒置区间仍用原样符号显示。每个输出记录清单、
请求表、绘图源码、准备源码、原音和侧车摘要。

这次指定的两个原件只生成三段连续上下文：第一原件 `[0,32000)` 与
`[164800,200000)`，第二原件 `[0,24000)`。它们分别用于姓名、缩写和
数词的听辨诊断，不能据此声称首尾是完整字边界。图上的发声能量与频谱
能提示复核位置，不能独立证明某个音素的精确字界。API 也是辅助内容
证据，句意未完不能直接当作声学削尾，既有 unknown 与错误不得由此清空。

## CPU 检查与实际 GPU 证据分开

桥接工具的 9 项 CPU 检查覆盖不同目标不得伪报零差、EOS/padding 后缀、
JSON 重复字段与非有限数、软链接、完成槽校验和、错误合同、自洽重签
侧车/commit 仍被历史收据拒绝。连续上下文工具的 5 项 CPU 检查使用合成
PCM，验证保增益逐样本连续片段、盲审空参考、越界与布尔采样拒绝、
重复或未选来源拒绝、原音摘要改变拒绝，以及仅绘图不生成音频。
普通模式和 `python -O` 均运行，检查不依赖 Python `assert`。

这些 CPU 检查不证明真实批处理吞吐、GPU 显存、断点恢复或人工字界质量。
正式选型仍需要对应冻结代码的 3000 来源实测、512 来源恢复对照、真实
父进程资源归还证据，以及全部实际文字变化的明确处理结论。
