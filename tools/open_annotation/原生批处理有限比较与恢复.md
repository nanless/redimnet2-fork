# 原生批处理的有限比较与恢复

`audit_native_transformers_batch.py`用于新原生Transformers批次的独立有限验证。它不能使用旧单窗审计的通过材料来给新batch4／8准入，也没有放宽`audit_speed_comparison.py`。真实模型执行、完整字质量和正式八卡接续分别验收；本程序只读已经完成的有限原件，不加载模型、不读取原音、不创建数据库。

对应的整批文件格式与恢复限制见[原生转写整批文件事务](原生转写整批文件事务.md)，新数值合同和试验顺序见[原生转写批处理独立验证方案](../../docs/plans/2026-10-28-原生转写批处理独立验证方案.md)。新试验必须使用同一份维护源码的batch1作为基线，与同数值方式、同模型、同输入、同Ultra单窗的batch4／8比较，不能把旧代码FP32/eager与新批处理混为单一batch收益。

## 输入与接口

每轨是明确的`redimnet2-annotation-native-batch-track/v1` JSON：

```json
{
  "schema": "redimnet2-annotation-native-batch-track/v1",
  "contract": {"path": "/ABS/native-contract.json", "sha256": "实际SHA256"},
  "index": {"path": "/ABS/fixed-index.json", "sha256": "实际SHA256"},
  "queue_root": "/ABS/new-run/queue",
  "output_root": "/ABS/new-run/labels",
  "resources_root": "/ABS/new-run/resources-attempt1"
}
```

仅接受新`asr_fixed_cohort_fa_single/v1`策略，批宽为1／4／8，Ultra固定FP32、eager、单窗。当前只接受独立pilot或明确合成CPU输入；正式silver合同不会因此获准批处理。来源数上限4096，不将这个入口用于全库检查。

Python接口是`load_track(path, sha)`和`analyze(baseline, candidate, mode='speed'|'recovery')`。前者完成完整有限读回，后者保存逐源／逐窗差异、完整错误和性能证据。命令行与旧工具的参数名一致，但入口和schema独立：

```sh
python -B tools/open_annotation/audit_native_transformers_batch.py \
  --baseline-spec /ABS/baseline-track.json --baseline-spec-sha 实际SHA256 \
  --candidate-spec /ABS/candidate-track.json --candidate-spec-sha 实际SHA256 \
  --mode speed --output /ABS/new-comparison.json
```

输出必须是生产目录之外的新文件。`recovery`模式允许以同合同3000例完整结果作为基线，候选为明确512例子集；换合同、换source记录、漏掉来源或重复来源均不能声称恢复通过。

## 完整读回检查什么

先沿有限索引读取全部输入片和已封账槽，逐源验证sidecar、commit、source完整记录、job_key、合同、模型、运行时和原冻结包；随后核worker summary、ready／ACK摘要、实际资源挑战和父结果。正在运行、未封账、资源未归还、摘要不符或侧车有损坏都不能成为成功轨道。

对每个实际完成预处理的窗口，还要读`durable_native_batch`引用的真实整批JSON，以及同一store的identity和完整固定计划。引用只能位于该producer标签树的`.native_torch_cohorts/`下；它不是一个可以指向任意外部文件的自由路径。

整批检查包括：

1. 计划、cohort、原子包字节SHA和内部内容摘要一致；原完整请求排序、分组、模型、合同、producer、源记录摘要、窗口PCM和16k帧数一致。
2. 原生结果覆盖原批全部row_id，每行的真实generate宽度和位置、inference_call来源顺序、输入帧数均与cohort相同，不能只按返回列表zip就宣布输入映射可靠。
3. 保存完整返回矩形token IDs，并独立核首EOS、有效token序列／长度、EOS后填充、实际token上限。早EOS后的填充槽不能计成真实生成文字token，不能把未知后缀自动裁掉而掩盖问题。
4. 实际输入token行必须完整保存且与mask同宽；左填充mask连续、非空，padded／nonpad数量正确。真实generate包装先核返回序列的prompt前缀逐行等于实际输入，不能把输出换行再伪称同映射。pad来源和“原pad为空时显式使用首个已配置EOS”的新策略要与真实保存配置一致。模型须是eval、inference-only、无梯度。
5. 完整原文、规范化文本、语言和原生字段必须等于整批包中该行，不另造一份“修正后的native”。Ultra实际调用仍须是一行。
6. 新发布来源所引用的未缓存整批包，其行数、批次数和宽度分布必须精确等于worker实际ASR调用计数；已提交批次复用单独计账，不能算进冷推理速度。Ultra新调用也须与新发布定位窗口相符。

预处理／解码失败的来源和窗口保留在完整分母中；不强造一个它未执行过的原生包。错误列表、缺失窗口、文本变化、原生时间与FIX后时间变化分别保存。原始返回token矩形因padding改变而不同，与有效token或文字不同是不同观察，报告不会把它们一律当成准确率错误。

## 冷速度和恢复结论

`cold_speed_ratio_valid`要求完整输入可比、没有缺窗或PCM变化、两边全部来源实际冷计算、没有整侧车或阶段缓存复用、真实首次计算兑现，以及完整整批文件读回。通过时才给`cold_end_to_end_speed_ratio`；CPU假模型永远不给这个GPU速度资格。“冷”指模型结果未复用，不宣称权重页缓存或操作系统缓存冷。

`strict_native_results_equal`和兼容字段`strict_recovery_native_results_equal`在恢复模式中要求原完整模型结果相等；只忽略执行时的cache-hit标志，不能忽略原子包路径／SHA、原生token、文字、字界或错误变化。调用driver还必须核恢复512条、整侧车缓存命中512、ASR与FA调用0、新发布侧车0，以及恢复前后既有sidecar／commit字节和mtime不变。完整整批结果复用与整侧车命中是不同计数，不能互相代替。

输出始终不授予人工文字／完整字正确性或训练标签资格。新批次改变了文字或边界时，需要继续逐项复核；即使所有机器输出一致，也不能据此将所有自动字界改为人工金标。新批处理也不能沿用单窗正式接续的选型准入；正式切换条件需在真实GPU验证后另行固定。

## 有限读回收据

完成`load_track`后，可调用纯内存函数`native_readback_receipt(track)`，由driver原子保存为`<stage>-<profile>-native-readback.json`。该函数只从本次已经读回并核实的records、完整cohort和原生包引用聚合，不再打开音频、模型、sidecar或目录。收据schema为`annotation-native-finite-readback/v1`，包含固定track／合同／索引／bundle SHA、全部来源的sidecar与commit原字节引用、完整source记录摘要、逐窗请求与原cohort／position映射、去重的packet／plan引用和原完整cohort成员，以及实际父结果与性能证明。

收据上限64MiB，超出就拒绝，不截断成员或错误分母；已读records被调用者改动也拒绝。恢复512仍会沿原sidecar读取并核实原生包，其原cohort可能包含不在512子集中的其它成员；收据保留完整原批次，不能为了让子集看起来独立而删除这些成员。新选型控制层可以固定这份有限收据和已核原生包，在启动时避免再逐个打开3000侧车；它仍须独立检查收据完整来源集合、原子包／计划及真实资源链，不能仅相信一个“通过”布尔。

## 当前CPU验证

最初15项新审计测试包括完整真实文件的有限源索引、sidecar／commit、原子批次、worker summary／ready／ACK和父结果链；前后所有生产原件字节一致，禁止数据库连接。另有逐源PCM／模型／合同／位置差异、包或计划改写、EOS后非填充token、错误padding mask、Ultra批处理、旧单窗审计仍拒绝新policy、失败分母保留和包SHA变化不能假恢复等反例。新增纯内存收据与硬上限检查后，目前17项测试通过。

整批store当前15项普通／`-O`测试也通过，其中新增反例保留第二次generate／映射异常携带的expected row IDs、已捕获原始tokens与padding属性，而不是只留一段缺少原生数据的traceback。以上都是CPU证据；尚未在真实GPU跑出的新batch1／4／8不能写成已经提速或质量已通过。


## 逐条官方B1特征协议的独立审计分支

旧native批次的PCM相同不能证明实际mel和非padding prompt相同；固定3000实测已有对应变化，旧约2倍速度未通过质量准入。新维护版审计器只对显式`runtime.asr_preprocessing={"policy":"official_b1_features_then_pad/v1"}`启动本节规则。旧无声明合同保持原有限诊断行为；它不会被隐式修正、重标或授予新协议资格。新协议还须有独立冻结的`native_b1_feature_padding.py`，与原14计算源及原生文件事务源合计16源，重新取得GPU证据。

新顶层`asr_preprocessing_sources`必须使用`annotation-official-b1-feature-sources/v1`，固定七个角色：Whisper特征提取器、sequence padding、BatchFeature、ProcessorMixin、音频工具、Qwen处理器和SDK normalizer；每个角色是绝对路径＋SHA，另固定真实模型`preprocessor_config.json`。审计在内存核这些声明和原SDK／模型manifest互绑，并要求基准、候选合同中的完整结构相同。它不在每个窗口反复读取环境源码；实际类、函数和配置由真实worker从live对象定位并核字节，其终态`asr_preprocessing_sources_observed`必须与合同一致，不能只写一个通过布尔。

每个已提交原生row的`native.preprocessing`包含两部分：独立官方B1处理所得的有效mel形状、float32摘要、实际有效feature mask及dtype、SDK处理后PCM、去padding后的完整prompt及音频占位数；真正`generate`入口从实际kwargs张量读取的对应字段。审计逐项比较两部分，核实际张量形状、dtype、有效mel SHA、右补零mask、特征padding为零、去左padding的prompt、实际batch行数／行号，随后再绑定原request的row_id、PCM和frames。Feature mask沿官方原dtype，int32或int64均可，但B1与真实generate必须一致；不能为了凑dtype擅自把原SDK语义改掉。

跨B1／B4／B8比较时，batch总padding宽可不同；有效mel、有效mask、SDK PCM、去padding prompt及来源绑定必须相同。差异以`ASR.preprocessing_*_equal`记录，进入完整窗口分母。即使原PCM完全一致，只要其中一项实际有效输入变化，`cold_speed_ratio_valid`就为false且加速比不授资格，不能把不同输入的运行时间称为受控提速。正式质量层也不能把任何这些false字段标为padding元数据。

新增CPU反例覆盖：整包读回、伪造真实tensor布尔但SHA不符、mask/dtype/形状／prompt变更、另一个PCM／来源、缺失协议或七类源、换库但模型相同、缺失真实worker源观察、B1／候选有效mel不同但PCM相同、SDK PCM或prompt变化、仅batch padding宽变化。旧17项加新15项合计32普通及32项`python -O`测试已通过；完整真实文件链也在新协议下验证。测试使用明确合成输入，不能代替真实SDK Tensor组和新的GPU精度、吞吐及完整字质量验收。旧冻结audit和旧native结果始终保留原SHA，不热改。


独立互审又发现逐row声明getter里不必要的`Path.resolve()`会做文件系统metadata探测；修后直接使用已经固定的canonical绝对路径字符串。新增100次getter在`Path.stat`和`Path.open`全部禁止时仍通过的反例，确认不会每窗重新探测SDK／PFS路径。32项普通及`-O`复验再次通过；另独立核新准备器9项普通／9项`-O`、正式准入36项普通／36项`-O`，均通过。准备器新补路径中的`..`拒绝，避免词法保护比较被父目录跳转绕过；正式层任何`preprocessing_*_equal`非True都不能作为metadata-only放行。CPU通过仍不等于新协议GPU质量通过，实际源SHA与完整独立收据另存`new-B1-feature-independent-review-receipt.json`。
