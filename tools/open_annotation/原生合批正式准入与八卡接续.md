# 原生转写合批的正式准入与八卡接续

本入口只接受新原生合批试验的实际证据。CPU测试、模板、合同工厂、材料发布成功，都不能证明真实GPU推理或完整字边界质量已经通过。真实3000条冷运行、512条严格恢复、逐差异文字与字界复核、端到端提速和资源归还全部满足后，才允许建立正式八卡运行。本文的样例含`REPLACE_`占位符，故意不能直接执行；质量样例所有接受字段也故意为false。

本入口不扫描正式全库、不建数据库，不修改旧侧车、旧批次结果、PTN或正在运行的标注代码。新增任务名必须以`zhounan_`开头，优先级为6。

## 1. 为什么独立增加v2

旧单窗入口`bounded_speed_queue_handoff.py`及`annotation-bounded-speed-runtime/v1`只接受原单窗试验证据。原生合批的整批输出、每行输入位置、有效生成token、结束符、padding和完整原始批次恢复有不同约束，不能借用旧单窗成功记录。新入口分别使用：

| 文件 | 明确的协议 | 职责 |
|---|---|---|
| `native_batch_admission.py` | `annotation-native-selected-pilot-admission/v2` | 核真实试验、逐差异质量和新旧代码身份 |
| `native_batch_readback.py` | `annotation-native-finite-admission-readback/v2` | 封存有限试验完整结果；启动时复算字节和原始输出 |
| `bounded_speed_runtime.py` | `annotation-bounded-native-runtime/v2` | 继承实际旧运行、祖先锁和唯一接续声明 |
| `native_batch_queue_handoff.py` | `annotation-native-batch-queue-blueprint/v2` | 新八卡实例上的有限等待、旧终态材料发布和正式父进程交接 |

合同默认仍只生成试验用途。显式`make_native_formal_contract`工厂只能写新数据文件；它不会改变数学源码、启动GPU或放行训练标签。正式native合同带默认关闭声明，GPU父进程、bootstrap和worker都必须获得对应v2真实租约。普通v1样本索引或旧单窗运行不能绕过。

## 2. 必须来自同一组真实试验的材料

对照组是原生B1，候选为实际选中的B4或B8。两者都必须是FP32/SDPA；除批大小外运行、模型和声明的计算源码摘要完全一致（原合批15个；显式逐源B1特征协议16个），Ultra继续FP32/eager且单条。候选最大批宽必须实际出现，不能只在合同里填写4或8。

正式准入要求至少3000条、最多4096条的同源冷运行；恢复恰好512条。主运行和恢复的合同相同，恢复引用主运行原侧车、原提交标记和原完整批次；恢复512条可以引用包含其他主运行成员的完整批次，不得把整批拆成伪造的512条专用结果。恢复不得重新调用ASR或强制对齐，不得重新发布侧车。

固定材料包括三轨track、两个比较报告、原生pilot结果、准备矩阵、每轨父结果、两次资源归还快照和终态排空记录。主/恢复计划、具体track、执行包和每步父结果SHA相互绑定；不能把另一组成功GPU试验配到本组质量报告上。父结果中的worker摘要、ready/ACK、实际计算dtype、SDPA的Q/K/V和调用行数会重新核验。端到端速度比由真实父进程墙钟相除重算，必须大于1；不接受单独填写的“速度快”或`actual_compute_execution_verified=true`。

选型文件模板见[原生选型字段样例](templates/native-batch-selected-admission.example.json)。其中`resource_evidence`路径必须是实际track资源目录下的`parent_result.json`、`resource_return_double_probe.json`、`terminal_drain_complete.json`，不能照抄模板控制目录占位路径。

## 3. 有限侧车封存与启动时核验

先在真实有限试验完成后，用该试验实际冻结的审计器读取这最多4096条侧车和提交标记，生成一次完整封存。只读有限试验，读原音、加载模型、建数据库都不在此步骤内。命令参数分别固定track和实际试验代码包的SHA：

```sh
/root/miniforge3/envs/qwen3-asr/bin/python3.10 -B /明确维护控制目录/native_batch_readback.py \
  --track /实际有限试验/main-track.json --track-sha 实际TRACK_SHA \
  --audit-code-root /实际冻结native候选代码 --audit-bundle-sha 实际BUNDLE_SHA \
  --output /新控制目录/main-sealed-readback.json
```

baseline、main、recovery各生成一个新文件，不覆盖原件。真实冻结审计器的`load_track`不返回`receipts`；封存器从已固定的父结果小JSON收集chunk引用，至多额外读一次父控制文件，不借此重读正式全库。CLI回归使用真实`load_track→seal→verify`接口，避免只在手工拼接对象上通过。

封存文件保存完整record，包括schema、未知顶层字段、源身份、VAD、units、decision、质量轴、完整window几何、context/owned、时间映射和对齐观察。成功ASR从真实整批文件按原位置恢复。启动时在内存重建完整record，逐条核标准JSON原字节SHA等于原sidecar SHA，并重建提交标记SHA和完整records聚合SHA；源sidecar/commit SHA还必须等于真实chunk提交收据，chunk再绑定父worker摘要。因此同时重签封存视图和比较报告，也不能把假字界、假VAD或假units变成原始结果。

正式八卡启动不重开这3000条侧车，更不重读百万侧车。它读取固定封存、原始整批/计划和少量父/worker/chunk控制JSON，重算比较器的所有行和计数，包括全部输入几何、文字、有效token、结束符、对齐坐标、来源观察和变化flags。删除检查字段、两边改成相同假几何、自洽编造性能都应拒绝。旧未绑定几何的readback/v1明确不受理。

## 4. 每条文字及字界差异要有实际处置

模板见[原生逐差异质量字段](templates/native-batch-quality-review.example.json)。所有有变化的source恰好一个处置，`window_ids`恰好覆盖实际变化窗口；证据固定实际本地听审、文字比较或波形/频谱边界检查文件SHA。`text_and_boundary_reviewed`需要同时确认文字及削首、削尾、邻字污染。`metadata_only_verified`只能用于文字、有效token、结束符、源输入与全部字界几何均未改变的元数据差异，不能用它掩盖padding以外的实际文字或时间变化。

接受字段只能在实际核验后填写。候选侧车仍是自动结果，`candidate_labels_released=false`保持不变；本次性能试验不自动授予训练和正式评测资格。

## 5. 从真实候选代码复制正式执行包

正式包从**实际已冻候选GPU代码目录**复制，禁止从仍有其他实验改动的维护工作目录重新freeze。声明的计算源、GPU父进程、bootstrap、上下文挑战、资源守卫及清理源码都保持实际GPU试验原字节。

本轮仅四个CPU控制文件允许审阅后替换：`native_batch_admission.py`、`native_batch_readback.py`、`native_batch_queue_handoff.py`、`bounded_speed_runtime.py`。显式overlay文件格式为`annotation-native-cpu-helper-overlay/v2`，其`files`映射文件名到实际文件路径及SHA；没有声明就不替换，见[四控制文件替换样例](templates/native-batch-helper-overlay.example.json)。替换GPU父进程或数学源会拒绝，而不是降级成CPU审阅。新增其他辅助脚本也不会悄悄装进GPU包。

```sh
/root/miniforge3/envs/qwen3-asr/bin/python3.10 -B /明确维护控制目录/native_batch_admission.py prepare-code \
  --pilot-code /实际冻结native候选代码 --pilot-bundle-sha 实际候选BUNDLE_SHA \
  --candidate-contract /实际候选pilot合同.json --candidate-sha 实际候选合同SHA \
  --output /root/experiments/redimnet2/open-annotation-ultra-20261025/native-speed-successor-20261028-v1/frozen-native-reviewed-v1 \
  --overlay /明确控制目录/four-helper-overlay.json --overlay-sha 实际OVERLAY_SHA
```

输出目录必须全新；准备收据仍写`independent_review_complete=false`。之后由独立审阅证据固定新旧bundle、逐文件原/新SHA差异、全部声明数学源相同、实际CPU日志及审阅结论，形成`annotation-native-control-source-review/v2`，见[独立源码审阅样例](templates/native-batch-control-review.example.json)，实际只列真正变化文件，不能照样例补四个假变化。选型文件同时绑定`formal_execution_bundle`和`control_source_review`。这只是允许四个控制修复进入正式包，不能声称这些新字节已经做过GPU计算测试；计算和GPU资源控制字节仍是原始实测字节。

新增逐源B1特征计算模块属于数学变更，不能塞进四个CPUhelper例外。使用它时必须先取得该16源新候选的真实GPU证据，再复制该实际新包；旧15源成功记录不能直接授新协议正式运行。七类官方预处理源和配置声明必须在基线、候选和正式合同中精确相同，任何`preprocessing_*_equal`非True也不能归元数据差异。

随后从这份复制代码中的工厂调用`freeze_contract.make_native_formal_contract`，只在外部新目录写正式合同。数学、模型、runtime、source各字段不变，只有purpose/version和默认关闭声明变化。正式新合同版本必须不同于pilot及旧生产者。

## 6. 新八卡先等待，再交接旧标注的终态

资源足够时可先核新实例；实际碎片使旧标注占据可释放整八卡时，不要求实例request先存在。按平台skill先提交并核唯一正式新ID/配置与碎片证据，已有授权下只受控停止精确旧annotation，再等新实例request并在其之后真实刷新旧终态、发布有限回复，PTN不动。代码不需要放宽；见[碎片排队时的受控接续顺序](../../docs/plans/2026-10-28-标注八卡碎片排队时的受控接续顺序.md)。下文先核新实例的顺序是资源充足时减少中断的选择，不是额外强制门。

新蓝图样例见[原生八卡等待字段](templates/native-batch-queue-blueprint.example.json)。原生独立外层必须从准备好的正式GPU包复制共同helper：

```sh
/root/miniforge3/envs/qwen3-asr/bin/python3.10 -B /正式代码/native_batch_queue_handoff.py build-controller \
  --gpu-code /正式代码 --gpu-bundle-sha 实际正式BUNDLE_SHA --controller-output /全新独立外层目录
```

新16源逐条特征协议构建外层时，必须显式加`--feature-contract /实际候选或正式合同.json --feature-contract-sha 实际合同SHA`。构建器核合同声明的全部16个数学SHA与实际GPU包逐项一致，才复制`native_b1_feature_padding.py`原字节，形成精确26成员外层；receipt同时绑定实际GPU包pin、该合同及七源配置。旧15源不传此参数，继续精确25成员，不要求原包存在新核心。不能给新16源沿用旧25成员外层，检查会在选型import前拒绝。源码修复只影响新控制包，不改当前已冻GPU包。

蓝图先固定真实选型、新合同、正式包、原解释器、原锁目录和真实旧运行。平台提交仍是单机八A800、优先级6、`zhounan_`名称，外层一次运行，不是DDP的八个重复等待者。平台命令使用独立外层的`wait --blueprint ... --blueprint-sha ... --execute`。旧`queue_handoff.py`与cf7单窗外层不能消费这个新schema。

新实例实际分配后，等待器在该云节点建立PID/start/boot/hostname/task ID/nonce请求，并只读NVML核八张可见空闲A800。最多等待1800秒；这时实例已经分配，可能计费，不能称为免费排队。超时、信号、未知回复或身份变化保留失败原件后退出，不自动重试或停止旧任务。

资源充足时，操作者可先核新task实际身份和请求可读，再受控停止**旧annotation专属任务**。碎片阻塞时，按本节开头的替代顺序先核唯一正式新ID/配置与真实碎片证据，受控停止旧annotation，等新请求后再真实刷新旧终态。本工具没有停止PTN或旧标注的代码。原标注的实际终态、当前平台竞争任务、真实云节点证明均取得后，才发布回复。`publish`只允许处理最终最多8个旧在途片；未领取的旧片只比较索引元数据，不提前读千万来源JSONL。旧已done槽跳过、在途已发布记录原字节保留、其他来源惰性继承。

有界薄索引仍使用原`annotation-bounded-speed-handoff/v1`协议，来源范围和旧writer规则不扩展，见[最终交接字段](templates/native-batch-final-handoff.example.json)。旧完成总数和全局分母只保留实际前驱的固定值，不因新任务重算全库。平台观察沿用原明确协议，见[新实例和旧终态观察字段](templates/native-batch-queue-observation.example.json)。操作者的发布命令为：

```sh
/root/miniforge3/envs/qwen3-asr/bin/python3.10 -B /独立外层/native_batch_queue_handoff.py publish \
  --blueprint /固定蓝图.json --blueprint-sha 实际蓝图SHA \
  --request /实际新云请求.json --request-sha 实际请求SHA \
  --observation /实际新平台观察.json --observation-sha 实际观察SHA
```

发布动作可以从有共享盘且能读已固定代码/材料的dev环境完成，但dev的`/proc`、GPU和hostname不能代替新云节点。发布器要核真实新请求，以及实际平台新观察；等待器会在云端重新核自己PID/nonce/时效，然后原GPU父进程再核旧终态、祖先锁、唯一声明和资源双快照，才建立CUDA。每个孩子继承同一租约FD，退出排空/双快照后才释放。请求、回复或`exec-intent.json`均不证明GPU已启动。

原始semantic锁、祖先`.parent.lock`、当前旧writer锁和永久唯一后继声明贯穿运行。稳定核心绑定old/new合同、索引、代码包、选型及新run，不能顺序换个newrun重跑已发结果。同一稳定核心的新attempt可补新鲜平台观察；不能改变业务核心。终态观察默认一小时有效，排队后由专用等待协议发布新鲜材料，不改旧时间或放宽门槛。

### 同次命令的有限选型证明复用

默认仍执行完整选型检查。只有操作者在`wait`或`publish`命令中分别显式传`--reuse-verified-selection`，该次Python调用才建立`NativeSelectionScope`。第一次仍完整校验真实有限封存、原完整packet、字界、质量、资源和计算证据；只有成功后才签发进程内对象。后续相同输入仍逐文件实际读取并核对全部SHA，只复用这次成功的JSON解析及原生映射重构结果。scope不能序列化、跨PID、跨CLI、换候选或换正式合同；命令退出立即失效。普通dict或“通过”布尔值不能代替它，返回的选型JSON也不携带能力。

首次捕获会重核所有证据SHA、实际GPU包成员、选型原件自身和明确SDK源/配置，并固定文件dev/inode/size/mtime/ctime/mode。每次复用先核全部唯一祖先目录的dev/inode/mode及无软链，以文件指纹快速拒绝身份变化；随后对全部已验输入逐文件实际读取核SHA，最后再核祖先目录。指纹相同不能替代字节完整性；即使同长度改字节后恢复mtime并碰巧保持全部metadata相同，SHA仍必须拒绝。目录mtime/ctime不固定，以免无关文件创建误拒；文件变化、目录替换或软链均立即拒绝，并永久撤销当前scope；恢复路径或mtime不能使它重新有效。初次签发前还需对已捕获输入完成统一复核，不能只逐个捕获而漏掉前后交错变更。GPU包成员由实际`result→plan→main_prepared→选定freeze`角色定位，不能按文件名或大小猜测。此能力仅复用选型，不能跳过平台新鲜观察、请求身份、旧writer终态、永久声明、锁链或GPU资源检查。`selection_reuse_scope`是命令独立计数，不是准入凭证。

GPU父子间的另一机制由运行协议独立显式声明`proof_transport={"policy":"parent_sealed_memfd/v1"}`，缺省仍走原严格路径，`null`、额外字段及旧schema均拒绝。它不由CLI scope自动启用，也不能把scope传给孩子。该机制的真实Linux内核FD认证、资源释放、独立审阅与真实有限证明启动成本须单独验收；本节不把合成CPU测试或运行意图当作真实八卡上线证据。两个可选机制均不写持久缓存或数据库。

此前候选仅靠metadata复用，在实际Linux共享文件系统出现“同长度改字节并恢复mtime”未被ctime指纹捕获的反例，已保留原失败与修前源码。该路线已否决：现改为每次复用对全部输入实际核SHA，不抽样、不靠sleep、不换文件系统、不删反例，也不声称减少IO。只期望省去巨大JSON解析、原生映射重建及相应峰值内存，实际收益和完整启动成本须实测。新增强制全部metadata相同但字节变化的CPU反例，及实际Linux组合复验后才能据真实证据判断；缺省全核路径继续保留。

## 8. 当前测试口径与未完成项

### 原异常仅含冻结入口目录差异的独立处置

新16源3000条比较中，119个来源保持`unknown→unknown`，`changed_fields`恰为`errors`和`vad`。逐叶复核发现差别只在`errors[0].traceback`和`vad.errors[0].traceback`的冻结代码目录：B1和B8各自独立`code`根不同。原异常为旧FireRed VAD区间非法；它仍是异常，不能据此把来源变成候选或可训练标签。

新增独立分类`frozen_traceback_root_only_verified`，没有放宽原`metadata_only_verified`。完整准入从已pin的`pilot_result→plan→main_prepared→variants`派生实际B1和选定候选根，核对两份实际冻结bundle及全部成员SHA，并把这些原件纳入证据pins；质量表不能自行填写替换目录。只改比较副本中完整traceback行的`File "<实际root>/<bundle内Python成员>", line …`目录前缀，两个traceback叶都必须实际发生替换，且两侧帧数相等。成员名、行号、函数、源码行、异常类型与正文均保留；普通字符串、相似前缀目录、未声明成员、任意其他路径都不被替换。

规范化后的完整`errors/units/decision/quality_axes/vad`必须逐字段相同。分类还限定原`reuse_vad`失败、`identity_mismatch_or_invalid`、空VAD结果、原因中保留一次`processing_errors_preserved`、无人工金标、训练及评测可用标志均为false。119来源中61个还含其他原异常（最多14项），69个还含额外原decision原因；它们必须完整保留并逐字段相同，不能只留下VAD异常来让校验通过。程序只定位`source.errors[0]`唯一的`reuse_vad`，且要求它与`vad.errors[0]`对应，不规范化其他异常的路径。每leaf还固定真实Traceback头、换行及最终`contracts.Refused: invalid old VAD interval`，不能把两侧一起改成普通文本或另一异常。

窗口计数两侧都须真正的整数，拒绝`True`和`1.0`；`both_present/input_identity_equal`都必须真正的`True`，拒绝`1/0`借truthiness。窗口文字、有效token、EOS、首EOS位置、生成上限、预处理有效输入和全部定位几何仍须不变。新分类仅允许`generated_token_ids_equal/post_eos_token_ids_equal/raw_returned_token_count_equal`这3项矩形尾部padding标志为false，其他已声明ASR相等标志一律须True；首EOS位置及生成上限还必须显式存在。全部变化来源仍要一一列入质量dispositions，原始比较/错误/unknown不写回、不删除。最后依旧从已封存原侧车字节重算完整比较，防止同时伪造两侧观察或自签质量表。这个分类证明“差异只来自两份实际冻结入口路径”，不证明原VAD正确或边界达到人工金标。
