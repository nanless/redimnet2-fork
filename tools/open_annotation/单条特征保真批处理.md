# 单条特征保真批处理：问题、修复协议与验收

截至 2026-10-28，这份新协议已经完成 CPU 实现、真实官方 processor 检查与独立
代码审阅，可以进入新的独立 GPU 对照；正式八卡标注接续仍关闭。旧批处理试验
的全部结果、未知项和错误均保留，不能用旧速度结果代替新协议的质量证明。

## 为什么相同 PCM 还会得到不同的模型输入

旧原生 FP32/SDPA 批次 4 在固定 3000 来源、3067 窗口上，完整冷墙钟从批次 1
的 1692.66 秒降到 980.84 秒，约快 1.73 倍；同时有 110 窗标准化文字变化、130
窗有效生成 token 变化。批次 8 有 122 窗标准化文字变化。批次 4 的 110 窗在
批次 8 中仍是同样的变化文字，后者另多 12 窗。这些变化包括结尾词消失和新的
零长定位，不能当成补齐 token 引起的表面差异，也不能因为机器 candidate 数
净增 3 就认定质量更好。

旧记录核了 PCM SHA、采样率、输入帧数、窗口和源时钟。官方 SDK 随后执行
`processor(text=..., audio=..., padding=True)`，在这里还会产生新的前处理差异：

1. Qwen processor 把音频交给 WhisperFeatureExtractor。它先把同批波形按最长
   输入右补零，再计算短时傅里叶变换（STFT）和对数梅尔频谱。
2. 单条输入的右边界由 STFT 的反射方式处理；较短波形放进较长批次后，同一
   位置后面变成补零。尾部频谱会变化；每条音频内部的频谱最大值若改变，
   `max-8` 动态范围地板还能把差异传到前面和中间的低能量频点。
3. 特征 mask 从波形 mask 按 hop=160 取样，最后仅按整批最长长度的余数统一
   截一帧。较短且不是 160 整倍数的波形，单条有效帧数可能是 floor(L/160)，
   合批却变成 ceil(L/160)。Qwen 据此计算音频占位 token 数，实际 prompt 也
   会改变。解码器的左侧补齐无法弥补这个声学输入变化。

固定合成 PCM 的实际官方 CPU 检查如下。梅尔通道数来自下载配置，为 128；
采样率 16000、hop 160、n_fft 400、dither 0。没有读取真实音频或模型权重。

| 原采样点数 | B1 有效特征帧/音频占位数 | B4/B8 原处理有效帧/音频占位数 |
|---:|---:|---:|
| 16000 | 100 / 13 | 100 / 13 |
| 16128 | 100 / 13 | 101 / 14 |
| 49408 | 308 / 40 | 309 / 41 |
| 401408 | 2508 / 326 | 2509 / 327 |

诊断器的 16000 点合成样本虽然计数不变，有效梅尔频谱 SHA 仍不同，最大绝对
差约 0.284；100 帧中 99 帧超过 1e-6。原始 STFT 差异集中于最后一帧，再由
每条音频自己的动态范围地板传到其它帧。等长批次与单条结果逐 bit 相同，把
同伴振幅乘 100 也不改变目标结果；这个用例没有跨样本归约污染，不能笼统归因
于 CPU 批量 FFT。另三种长度在共同 floor 前缀中逐 bit 相同，但多出的有效帧
与占位仍真实进入模型，所以只修 mask 长度或只改左补齐都不充分。

旧实际原件也已有直接证据：同为 401408 个输入采样点，其 prompt 非补齐
token 数从 B1 的 341 变成 B4/B8 的 342；49408 点窗口从 55 变成 56。不过五个
机器资格变化例中还有四例的非补齐 prompt 完全相同，文字仍变化。旧结果没有
保存有效 mel SHA，无法事后逐一证明 110 窗的具体原因。新协议要保存真正进入
模型的声学输入，并重新测量剩余的解码器批次数值影响。

## 新协议如何保持单条输入

运行设置必须显式包含：

```json
"asr_preprocessing": {"policy": "official_b1_features_then_pad/v1"}
```

原生 ASR 固定批次、FP32/SDPA、Ultra FP32/eager 单窗规则继续保留。
`native_b1_feature_padding.py` 成为第 16 个计算语义源码，进入合同摘要；旧的
15 源协议没有这个字段，仍按原义保留用于历史诊断，不能被悄悄改成新算法。

新 `B1FeatureBatchProcessor` 作为 processor 代理，官方 SDK 的
`transcribe → processor → generate` 调用顺序继续使用。代理对同一 cohort
逐条调用原官方 processor，使用与 B1 完全相同的 kwargs；保存每条原生有效
mel、特征 mask、非补齐 prompt 和音频占位数，然后只在特征域尾部补零，在
文本左侧补 pad。原生有效帧不会被截短，原 PCM 不删音、不补波形、不调增益。
SDK 既有的浮点幅度归一化仍调用其原函数；原输入与 SDK 归一化后的 PCM
分别记录摘要，不能把这两层身份混成一个 SHA。

特征域补零只填有效帧之外。当前已固定官方模型的 `get_audio_features`
逐行执行 `input_feature[:, :feature_len]`，之后才交给 audio tower；这些补齐
帧不进入有效卷积输入。原生 feature mask 的实际 dtype 是 int32，文本 mask
是 int64；代理保留各自 dtype，不为了方便审计擅自统一转换。

每个 cohort 只允许一次 SDK processor 合批调用及一次真实 generate。代理
内部逐条提取特征属于 CPU 前处理，不是多次模型调用。SDK 隐式拆批、重排、
重复调用、漏行、未知 tensor 字段或 kwargs 改变都停止并保留异常。

## 证明来自真实 generate 入参

代理构造时的摘要只作为 B1 参考。生成包装器在真正调用 generate 前，再从
实际 `input_features`、`feature_attention_mask`、`input_ids` 和 `attention_mask`
张量读回并核查：

- 每条有效 mel 的 shape、float32 dtype 和 SHA 与独立 B1 原件一致。
- 原有效特征帧和 mask 不变，特征补齐区实际全零，mask 补齐区实际全零。
- 去掉文本左补齐后的完整 token ID 列表、音频占位数与 B1 完全一致。
- 实际行数、行号、输入 PCM、SDK PCM、原采样点数都对应原固定 cohort。

这些观察保存到每窗 `asr.native.preprocessing`。原始输入 token、mask、生成
矩形 token、首 EOS、有效生成 token 与 EOS 后补齐仍全部保留。新有限比较器
逐窗比较 B1/B4/B8 的 SDK PCM、有效 mel、有效 mask 和非补齐 prompt；任一
不相同，不能声称这是只有批宽变化的冷速度对照。

逐条提特征、保存摘要、实际入参读回和复制的耗时都包含在完整 ASR 阶段与
冷墙钟中。新协议是否还足够快，要依实际新实验决定，不能沿用旧 1.73 倍。

## 精确绑定来源，避免每窗重复读库文件

旧合同 `source_files` 保留原字节内容。新顶层 `asr_preprocessing_sources`
绑定七个实际依赖：WhisperFeatureExtractor、SequenceFeatureExtractor、
BatchFeature、ProcessorMixin、audio_utils、Qwen processor、SDK normalize。
每个角色保存实际源文件路径与 SHA；下载模型的 `preprocessor_config.json`
另存路径与 SHA，并与模型文件清单中的同一配置摘要互绑。

`collect_b1_feature_sources(contract)` 供 CPU 准备器收集上述明确来源；不加载
模型权重、不遍历整个环境。实际 processor 构造及首个 SDK 调用再次核实例
类型、继承的 `_merge_kwargs`/`pad` 方法、归一化函数、BatchFeature 的真实
来源，以及实际特征提取配置。worker 摘要保留实际路径/SHA/配置观察；逐窗
原生证明绑定同一来源声明摘要。

`asr_feature_profile` 只核声明结构与已有摘要，不访问文件系统。实际来源完整
哈希放在准备、构造和首调用；之后每 cohort 仅检查已缓存的八个明确文件身份、
对象身份及配置稳定性。文件身份变化立即拒绝，不能重算一个新 SHA 当作许可。
计数反例已覆盖 100 次 getter 不得 open/stat/hash，以及 20 次已缓存检查只能
做已知的 160 次 stat、不得重新 hash 或 import/inspect。这样来源证明不会变成
每个窗口反复读取整套库文件。

## CPU 检查与后续 GPU 条件

普通全套测试发现阶段不导入 torch。真实 Tensor 测试必须显式在隔离 CPU
子解释器启用 `REDIMNET_B1_TENSOR_TESTS=1`，并令 `CUDA_VISIBLE_DEVICES` 为空。
不能删除 `sys.modules` 来伪装没有导入重库。

现有服务器环境已经完成六项真实 Tensor 检查，使用实际 WhisperFeatureExtractor
和 BatchFeature.to，验证 B1/4/8 有效 mel 逐 bit、mask 与非补齐 prompt 保真，
以及真实 generate 入参被篡改时拒绝。该轮连同五项合同检查共 11 项，普通及
`-O` 全部通过，无跳过。随后新增缓存调用计数反例，在本机普通及 `-O` 通过；
旧原生执行包装十项也在独立进程回归通过。

还用实际下载模型的 AutoProcessor、官方 normalize 和真实七源 live guard，
对四条合成波形运行两个连续 cohort。有效帧恢复为 100、100、308、2508，
占位为 13、13、40、326；dtype、有效 mel 和实际 prompt 检查通过，CUDA 未
初始化，审计钩子记录权重和真实音频打开尝试均为零。这项只加载 processor
配置和 tokenizer，不构造 ASR 或强制定位模型。

下一步必须由同一新 16 源版本分别运行 B1/B4/B8 的 30 来源对照，再完成 3000
来源、512 来源及需要的真实整批中途恢复。所有新文字/语言/定位变化继续逐条
保留和处理。只有完整输入证明、实际质量、恢复与资源条件均通过，才允许显式
正式合同工厂和已认证的 native v2 接续；普通 freeze 仍只生成试验合同。
PTN、旧八卡标注、旧试验原件和未通过的新候选不得被这个过程覆盖或停止。
