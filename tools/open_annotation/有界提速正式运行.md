# 有界提速正式运行：旧结果保留与 GPU 父子接续

这份新接口用于独立的新生产者。它不修改旧合同、旧冻结包、旧队列或旧侧车，不停止任何平台任务，也不扫描全库或创建数据库。已经封账的旧片保留原固定槽，最多八个未封账旧片在准备时逐源核实。尚未领取的父片仅保留描述，真正领取时才读取原片并检查可能已存在的旧结果。

`bounded_speed_handoff.py` 和 `bounded_speed_queue.py` 的准备及队列条件仍以[有界提速交接](有界提速交接.md)为准。新增的 `bounded_speed_runtime.py` 将这些条件接入 `gpu_launch.py`、`gpu_bootstrap.py`、`worker.py`、`report.py` 和显式只读分支。维护代码通过 CPU 合成测试，不代表当前生产已切换，也不代表真实转写变快、完整字质量通过或新八卡任务已验收。

## 1. 操作者需要的原件

正式运行必须同时具备以下材料。每个 `path/sha256` 都指实际原件的绝对物理路径及完整 SHA256，不能仅填“通过”。

1. 最终薄索引及其固定计划。计划必须在已核实最近旧标注任务终态、取得旧父锁和未封账片锁后生成。活动快照只能预览，不能执行。
2. 最近旧生产者实际使用的 `annotation-portable-successor-run/v1` 或 `/v2` 配置。程序沿其中的 `old_control`、`freeze_receipt` 和 `union_spec` 找原始语义锁及原始父锁，不允许手填另一套祖先锁。已有永久声明须绑定这份旧配置及其合同、父索引和运行目录。
3. 有限真实双卡试验的选型材料：同一批至少 3000 条的历史 FP32/eager 基线与选定候选、至少 512 条同合同恢复、三者实际父进程结果、CUDA 排空和两次空闲资源快照、文字及完整字边界逐差异复核原件。CPU 假模型材料只能在 `cpu_fixture` 中测试格式，不能用于正式准入。
4. 新合同、新冻结源码包和独立新 `run/queue`、`run/labels`。所选候选与新合同的模型、Ultra、窗口、字界、归一化、解码和质量规则必须相同。只有 `worker.py` 与 `report.py` 的控制工程差异可通过明确的独立审阅原件准入；其他模型语义源码有差异就拒绝。
5. 在实际新实例启动前发布的最近旧任务终态与平台无竞争后继观察。时区必须明确，观察不得来自未来，不得早于一小时。旧任务 ID、队列、worker 身份和终态逐项核实。观察工具不会凭本机 `/proc` 编造跨节点进程已消失。

现有 `queue_handoff.py` 外层仍只支持旧 portable `/v1`、`/v2`。新schema的专用等待与发布入口为 `bounded_speed_queue_handoff.py`，详见[有界八卡排队与材料交接](有界八卡排队与材料交接.md)：候选和新版本先固定，新八卡实际分配并发布请求后才受控停止旧标注、准备最多八片材料，等待最多1800秒。原一小时时效不延长、旧时间戳不改。一次已获准的长 GPU 运行不会逐片要求终态观察持续新鲜；它持续依靠真实旧锁与固定原件保护。

## 3. 最小入口及运行顺序

调用新冻结 `gpu_launch.py` 时，除原有明确的合同、索引、run、queue、labels、resources、UUID 锁和预算参数，新增以下两个成对参数：

```text
--bounded-runtime-spec /root/experiments/redimnet2/actual-bounded-runtime.json
--bounded-runtime-sha 实际文件的完整SHA256
```

正式 `purpose=production` 必须使用 `--target-uuids auto8` 并实际看到八张 A800。旧 v1 索引不能夹带新参数；新薄索引缺少新参数也拒绝。原独立 `pilot_validation` 的 `auto2` 分支保留。新 schema 禁止 `--full-verify`，它的终态验收只核固定槽及完整元数据，不触发全库侧车读取或数据库。

运行顺序是：核显式小控制链和新鲜平台终态，取得原始语义锁及原始父锁，取得当前旧 writer 的父锁和最多八个旧 claim 锁，核固定快照，执行原 W2 原字节原参数，再核同一原始 RW/RO 挂载和共享别名。旧 fresh-run 挂载脚本的原 SHA 被保留，但不执行其“旧 run 必须不存在”的不适用条件。然后进入原有 UUID 协作锁、双资源快照、CUDA 挑战、模型守卫和独占监控。

所有旧锁的实际 FD、路径、device 和 inode 写入每个子进程 ticket，并通过 `Popen(pass_fds=...)` 继承。子进程在 `import torch` 前核同一打开描述及 Linux `fdinfo` 中的排他 flock，不能重开文件冒充继承。祖先与最近旧 writer 的锁在所有自有子进程清理、CUDA 排空及资源归还前保持；旧 v1 清理流程没有被替换。实际解释器也须等于原控制文件固定的 Python 二进制。

`worker` 领取片后，在源读取、ASR、定位、阶段缓存和新发布之前检查旧生产者结果。旧结果保留原 job、原合同和原树；跨节点只按既有明确编码 SHA 和前后 stat 证明允许 device 不同。若新旧树同时有同源结果，保留双方并拒绝，不自动选一边。`retained_previous_producer_hits` 和对应 decision 计数独立记录，不冒充本次新推理或新提交；当前同合同缓存命中也与旧生产者继承分开。

## 4. 只读进度与终态结果的限制

`readonly_progress.py --bounded` 明确选择新元数据分支，不构造队列、不取得锁、不写生产文件、不重开未领取 JSONL 或百万侧车。它只报告固定槽已封账下界、当前生产者与前一生产者的发布计数，以及固定全局分母。当前生产者计数不能直接当本 attempt 新 ASR 调用数。

`report.py` 的新终态分支要求内部真实父锁 FD，或外部新鲜终态原件、实际任务 ID 和已存在父锁。它核全部完成槽、生产者身份、源总数和稳定双读；明确写 `full_sidecar_readback_verified=false`、`GPU_resource_return_verified_by_this_tool=false`。真正 GPU 排空与资源归还仍由父进程原协议单独证明，人工完整字正确性也不由元数据报告推断。

## 5. 永久唯一后继声明与同一运行的接续

并发 flock 只会阻止同时启动，不能单独阻止“第一个后继做完后，再拿相同旧快照创建第二个新 run”。为此，新入口在持有原始语义锁和最近旧 writer 锁后，在原始专属控制目录发布 `annotation-bounded-speed-successor-claim/v1` 永久声明。文件名使用最近旧合同、父索引及旧队列的组合 SHA，避免拼接多个完整摘要导致文件名超过文件系统上限。旧队列、旧侧车和旧冻结包仍不写入。

声明固定薄索引、新合同、新 bundle、新源码根、新 run 和选型准入证据。首次运行配置及时间另外保留；后续同一核心、同一新队列的接续可以使用更新的真实平台观察，但不能借此换另一新生产者、另一个 run 或另一份薄索引重跑已完成结果。发现不一致时拒绝并保留原声明与全部原件，不删除声明“重试”。该声明摘要同样进入父子 ticket，运行前、子进程导入模型前和终态再次核实。
