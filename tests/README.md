# tests/ 目录

这里同时有可直接执行的模型检查和 `unittest` 合成回归。本文原有的掩码实测是历史模型实验，下面单独说明；新增工具的测试范围与依赖应按各目录 README 和本次检查记录区分。

纯标准库测试可以用 `python3`，需要张量计算或模型权重的测试则使用已安装相应依赖的解释器。历史开发机曾使用 `/root/miniforge3/envs/redimnet2/bin/python`，这不是任意机器上必然存在的路径，也不能据旧记录断定现在的 `python3` 有无 torch。

训练接续、自动标注和完整字消费的入口见 [实验维护与验收边界](../docs/16-实验维护与验收边界.md)。`tools/open_annotation/tests/` 的测试使用合成输入，不证明新仓库版本已通过真实 GPU；完整字正式训练仍需满足独立的数据资格检查。

## `test_varlen_masking.py`

检查模型层"变长输入 + 补零掩码"这件事有没有退化。

```bash
# 快速跑一遍：两个权重、短音频
/root/miniforge3/envs/redimnet2/bin/python tests/test_varlen_masking.py --quick

# 全部 20 个权重
/root/miniforge3/envs/redimnet2/bin/python tests/test_varlen_masking.py

# 额外做一次"改动前后逐位一致"的比较（需要一份旧代码）
/root/miniforge3/envs/redimnet2/bin/python tests/test_varlen_masking.py \
    --baseline-pkg /path/to/old/pkg_parent
```

它检查下面几件事（第一行的向后兼容检查需要加 `--baseline-pkg` 才会跑）：

| 检查 | 要求 | 为什么 |
|------|------|--------|
| 不传 `lengths` 时与改动前逐位一致 | 最大绝对差 = 0 | 已发布权重与官方数字依赖这条路径，不能变 |
| 掩码**全有效** vs 不传掩码 | 相对 L2 ≤ 1e-4（实测约 2e-6） | 证明掩码机制本身没算错 |
| 掩码**半有效** vs 逐条推理 | 余弦 ≥ 0.90 | 防退化下限 |
| 传 `lengths` 比不传 `lengths` 好多少 | **补回比例 ≥ 0.80** | 证明掩码确实在起作用（成对比较，见下） |
| 同一批里较长的那条 | 余弦 ≥ 0.999 | 补齐不应影响不补齐的那条 |

退出码 0 表示全部通过；非 0 会打印具体差在哪一项。

### 那条判据为什么用"比例"而不是绝对差值

上面最后一行**不能**用一个写死的余弦阈值、也不能用绝对差值来判断。
原因是不同权重输出向量的相关程度差别很大：同一个模型对两段互不相关音频的余弦，
`b0-vox2-lm` 只有 0.64，而混合数据训出来的那几个高达 **0.98~0.99**。
后者的向量高度相关，余弦被压在很窄的区间里，绝对差值天然就小 ——
实测 20 个权重 × 两种长度共 40 组里，绝对差值分布在 **0.202 ~ 0.658**，
拿一个固定数字当阈值，必然有的权重误报、有的权重漏报。

所以判据改成**补回比例**（与尺度无关）：

```text
补回比例 = (传 lengths 的余弦 - 不传 lengths 的余弦) / (1 - 不传 lengths)
```

意思是"把'不传掩码'离完全一致还差的那部分，补回来了多少"。
实测 40 组全部落在 **0.900 ~ 0.995**，取 0.80 作下限留了余量；
掩码一旦失效，这个比例是 **0**。

这条判据是逐步换出来的，把走过的弯路记下来免得再犯：

1. 最早写死"不传掩码的余弦 ≤ 0.60" —— 20 个权重里 5 个误报失败（都是
   b3/b6 的 vb2/cnc2 那几份），整个套件退出码变成 1。
2. 改成"比该模型自身的基准低 ≥ 0.12" —— **方向是反的**：掩码失效时
   "不传掩码"当然更差、离基准更远，这个差值反而更大，于是照样通过。
   实测把掩码整个删掉，这个数不变（都是 0.312112），完全没有分辨力。
3. 现在这条"补回比例"才是对的：掩码正常时 0.90 以上，掩码删掉时是 0。

### 为什么这里没有"变长 == 逐条"的断言

因为**做不到**，这一点是实测结论，不是偷懒：

- 补齐会改变**总帧数**（例如 96 帧 vs 196 帧），下采样后的时间上下文随之不同；
- 最后一个真实帧的卷积感受野会读到补零区；
- 骨干里有跨时间位置的全局运算（特征加权、时间注意力、`ASTP` 的整条 softmax），
  边界帧的差异会被扩散到全部帧。

实测：补齐比 1.00 时余弦 = 1.000000；2 倍时 0.938；4 倍时 0.982（b0）。
所以脚本记录的是**下限**。训练侧用掩码，是为了把补零帧排除在统计量之外
（这一步把 0.326 救到 0.938），不是为了追求逐位等价。

要缩小这个差距，靠的是**分桶**：同一批里长度越接近，补齐比越小，偏差越小。
