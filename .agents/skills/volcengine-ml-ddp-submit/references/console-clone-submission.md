# 控制台“复制任务”提交：当前唯一可用通道

适用：需要在火山引擎机器学习平台提交一个自定义任务，而 CLI 用不了（缺 AK/SK）。这时能走的只有控制台复制既有任务这条路。本文是这条路的唯一主文档：入口怎么填、AX 怎么点、会话和网络断了怎么办、提交后先看什么，都在这里；其他 reference 讲表单字段、挂载和实验合同时只链接本文，不再各写一套点法。

实测基准：2026-11-06 首次成文，2026-11-09 复测 CLI、规格型号、隧道连通与源任务状态。平台侧数字每次提交前都要重新核，本文只保留方法与已验证的历史值。

---

## 0. 一句话流程

任务列表 → 目标行操作列点 `复制` → 表单被预填（URL 带 `?Id=<task>`）→ 只改三处（任务名、描述、入口命令）→ 点 `复制任务` → 详情页逐字段核对 → 5 分钟首屏自检。

---

## 1. 通道现状：CLI 存在但调不通

| 事实 | 实测值 | 复测方法 |
|---|---|---|
| 程序位置 | `/root/.volc/bin/volc`、同目录 `mlp`（70,664,479 B） | `ls -l /root/.volc/bin/` |
| 版本 | `volc` 自报 1.2.55，提示最新 1.2.57 | `volc --version` 或直接运行，启动横幅会打印 |
| 是否在 `PATH` | 不在 | `command -v volc` 为空 |
| 凭据 | `~/.volc/credentials` 不存在；目录下只有 `access_token`（68 B），CLI 不认这种形式 | `ls -l /root/.volc/` |
| 调用结果 | `volc ml_task get -i <task_id>` 与 `volc ml_task list`、`mlp job list` 都返回 `AccessKeyId or SecretAccessKey is empty, please check $HOME/.volc/credentials or config it by using volc configure`，`volc` 外层报 `exit status 255` | 见上，2026-11-09 复测 |

`volc` 只是外壳，真正干活的是 `mlp`；不补 `PATH` 时会先报 `exec: "mlp": executable file not found in $PATH`。

`ml_task list` 的厂商自述是“只打印所有非终态任务”，任务结束（成功/失败/停止）后就不在 `list` 里，查历史要用 `get -i <id>`。这条语义本身没问题，但当前凭据缺失，`list` 同样返回 255，所以此刻它既查不了历史也查不了在跑的任务。`list` 里看不到，推不出“任务不存在”。

读到 `access_token` 不等于能调通：它换不出可用的 AK/SK，复制它只是多留一份凭据副本。

**结论：控制台“复制任务”是当前唯一可用通道。** 配好 AK/SK 后这条结论要重新实测，不能当成平台能力结论。

## 2. 复制来源任务：`t-20261026074833-ctjsk`

控制台复制需要挑一个字段全部正确的源任务。当前已验证可用的是 PTN 主训练任务 `t-20261026074833-ctjsk`，名称 `zhounan_redimnet2-b6-ptn-r47-capture-8a800-p6-20261026-v2`，2026-10-26 07:48:57 启动。

|---|---|---|
| 框架 | PyTorchDDP | 任务详情 |
| 实例 / GPU | 1 个 worker × 8 张 A800-SXM4-80GB | 任务详情 |
| 规格型号 | `ml.pni2l.28xlarge`（GPU 型 112 vC） | 任务详情、`tools/ptn_resume/lm_launch/submit.conf.yaml` |
| 镜像 | `prod-cn-beijing.cr.volces.com/aiplatform/dev_zhounan:4.0` | 任务详情 |
| 队列 / 可用区 | `aiplatform-SPEECH`（预付费）／可用区 B | 任务详情 |
| 优先级 | 6 | 任务详情 |
| 最长运行时间 | 720 小时（2,592,000 秒） | 任务详情 |
| 自动重试 | 关闭 | 任务详情 |
| 挂载 | 用户 PFS → `/root`（读写）、group-shared → `/shared/group-shared`（只读），两个目标互不包含 | 任务详情 |

三点使用注意：

1. 该任务 2026-11-03 已跑完 120/120 轮、八卡归还（`docs/10-云端八卡训练.md` 状态段）。复制一个已结束任务的**表单**仍然有效，因为它带的是配置而不是运行状态；但复制不等于“重试”，也不要顺手点“重新运行”。
2. 空白表单或复制自优先级 4 的表单，点 `6` 后仍显示 `4`（2026-09-28 MMS 案例）。所以起点必须是已确认优先级 6 的任务，提交后再从详情页核一次。
3. 规格名称会随资源目录调整失效。`ml.pni2l.28xlarge` 是当前有效写法；历史文档里出现过 `ml.hpcpni2l.28xlarge`，那个型号名在实际任务详情里查不到，提交前以详情页显示为准。

## 3. 打开预填表单

1. 进入自定义任务列表页，按完整任务名或 ID 定位目标行。ID 被截断时读 tooltip 或打开详情；靠截图辨认容易认错行。
2. 在目标行的操作列点 `复制`。
3. 表单页打开后先看地址栏，应形如 `/customTask/create?Id=<源任务ID>`。`Id` 就是被复制的源任务，记进报告，它是“这次提交从哪来”的唯一凭据。
4. 表单此时已带出源任务的全部字段。带出来不等于每个字段都还适用，逐项走第 5 节。

## 4. 要改的三处

| # | 字段 | 改成什么 | 判据 |
|---|---|---|---|
| 1 | 任务名称 | 以 `zhounan_` 开头、全局唯一（含实验标识与版本/日期） | 提交后详情页名称与表单逐字一致；`zhounan_` 前缀是归属标识，丢了按前缀检索不到 |
| 2 | 描述 | 如实写：源任务/父任务、本次改了什么（配置/入口/挂载）、已知限制 | 详情页描述非空且与表单一致 |
| 3 | 入口命令 | 本次要跑的那一行（整体替换，不是追加） | 重新读回编辑器的完整值，与预期入口逐字相等 |

### 4.1 入口写成一行短脚本，不写长命令

网页代码编辑器对长命令不可靠：粘贴或自动化写入多行命令时，首字符会丢（用户观测，2026-11-08 至 11-09 多次复现），丢掉的往往是 `/` 或 `e`，命令于是从“路径”或 `exec` 变成不存在的命令，任务启动即失败。因此入口只写一行：

```
/bin/bash /root/codex_artifacts/repo-handover-20261107/run_handoff_v7.sh
```

这行只有“解释器 + 脚本绝对路径”两个成分，没有引号、没有换行、没有需要转义的特殊字符，丢首字符时也会立刻表现为 `/bin/bash` 不存在而不是静默跑错。脚本本体放在共享盘上，可以正常编辑、`bash -n` 校验、按需换版本（v2…v7 的差别只在 CTRL 路径、blueprint 路径与 sha 三行）。

历史做法是用 `/bin/bash -lc '...多行...'` 把环境变量和 exec 全部塞进入口，2026-11-06 的 LM 提交就是这个形态。该任务后来在门禁处被拒（入口多带 `--execute`，见 `docs/10-云端八卡训练.md` 的状态段），原因不在截断，但说明入口里塞的东西越多，出错面越大：截断、追加、多带参数都会落在同一行里，而详情页上看起来都“像那么回事”。2026-11-09 起改用短脚本，需要改的内容留在脚本里，入口不再承载它们。

### 4.2 提交前用 AX 读回原文

编辑器已有旧命令时，自动化的 `fill` 可能把新内容追加在后面，命令于是变成“旧命令 + 新命令”。提交前必须重新读一次编辑器的实际完整值（`AXTextArea` 的 `AXValue`），与预期入口逐字比对；只看“设置成功”的提示不够。提交后再从详情页读一次，两次都与预期相等才算落值。

## 5. 沿用项（照抄源任务，逐项确认）

| 字段 | 期望 | 备注 |
|---|---|---|
| 镜像 | 与源任务相同的私有镜像与 tag | 换镜像前回项目技能确认 tag |
| 队列 / 可用区 | 同源任务 | 队列满时排队等待；重复提交绕不开队列 |
| 优先级 | `6` | 用户硬要求；提交后从详情页再核 |
| 规格（每 worker GPU 型号/数量）/ worker 数 | 同源任务 | 与 launcher 的拓扑合同一致 |
| 框架 | `PyTorchDDP` | — |
| 挂载（双挂载） | 同源任务，容器目标互不重叠 | 继承来的额外挂载逐项确认是否仍必要 |
| 自动重试 | 关闭（诊断/首次验证阶段） | 复制会继承源设置，要显式确认 |
| 最长运行时间 | 用户给定上限；留空也可提交 | 见 6.3 的 `AXIncrementor` 问题 |

继承风险：复制会静默带上源任务的环境变量、额外挂载、自动重试和可见范围。每项要么确认沿用，要么清空。表单不报错只说明字段通过了校验，不代表取值合适。

## 6. 自动化操作要点

### 6.1 用 AX 元素动作，不用坐标点击

- 可用：`AXPress` 点按钮；`set_value` 填 `AXTextField` / `AXTextArea`（任务名称、描述、入口命令）。
- 不可靠：按屏幕坐标点击。页面顶部“所有产品服务”大菜单一旦展开会整体遮挡，点击会偏到相邻行或相邻按钮，曾因此点到别的任务行。确需点坐标时，先用 `Escape` 关闭菜单，再用 AX 树确认目标元素在最上层。
- 容器类节点（`AXGroup`/`AXUnknown`）随渲染变化，直接找可交互的叶子。

### 6.2 AX 快照 60 秒过期，且重采会移位

快照里的元素索引不是稳定 ID：重新采样后同一按钮的索引会变。一次采样后立刻动作；超过 60 秒重新采样并重新定位，不复用旧索引。动作后读回该元素的 `AXValue` 确认落值。

### 6.3 `AXIncrementor`（数字步进框）不接收 `set_value` 和合成输入

“最长运行时间”这类数字框写进去会被清成 0，看起来很像“已设置 0 小时”。实测处置是留空，平台接受提交（2026-11-06 LM 提交即这个状态）。确实要设值时用框旁加减按钮或人工输入，提交后从详情页核对实际值。

### 6.4 提交按钮叫 `复制任务`

不叫“创建”或“提交”。点它就会创建新任务，属于对外写入；确认已获授权再点。

### 6.5 锁屏时 CUA 不可用

macOS 锁屏后，Computer Use 拿不到 screenshot 与 AX 树，报 `CGSSessionScreenIsLocked`。此时不要反复重试点击，也不要用坐标点击“猜”界面；先让用户解锁，再重新采样。判断当前是否锁屏：`CGSessionCopyCurrentDictionary()` 里出现 `CGSSessionScreenIsLocked` 即为锁定；只有 `kCGSSessionOnConsoleKey=True` 表示用户仍在前台会话（2026-11-09 实测 unlocked）。

## 7. 会话过期与网络中断

| 现象 | 判断 | 处置 |
|---|---|---|
| 控制台操作 3–4 小时后要求重新登录，或表单提交无响应 | 会话过期（用户观测，未独立复测具体时长） | 重新走当前账号的认证路径；不要退出账号，退出会把其他登录一起清掉 |
| 页面打不开，但公网正常 | 隧道/VPN 断了 | 见下 |
| `ping 10.43.6.199` 100% 丢包，而 `curl https://www.baidu.com` 返回 200 | VPN 断，不是平台故障 | 重连 VPN 后重试；不要在这时判断任务失败或重复提交 |
| `ping 10.43.6.199` 有回应 | 隧道通（2026-11-09 实测 3/3 通，平均 25.4 ms） | 继续 |

`10.43.6.199` 是开发机内网地址，只有 VPN 通时可达。把“内网 ping 不通 + 公网正常”当成 VPN 掉线的判据，比盯着控制台刷新可靠：平台侧任务状态在这期间不会变，变化的只是本机能不能看到它。

判定顺序：先 `ping 10.43.6.199`，再 `curl` 公网，最后才刷新控制台。顺序反过来容易把网络问题写成任务故障。

## 8. 提交后核对

1. 详情页逐字段核对：任务名、描述、入口命令（完整一行）、优先级 `6`、框架、队列/AZ、worker 数与每 worker GPU、镜像 tag、挂载、自动重试、时限。
2. 记录完整任务 ID（`t-YYYYMMDDHHMMSS-xxxxx`）与创建时间，写进报告。任务号不能当状态用，平台侧终态与本地留档要分开记。
3. 5 分钟首屏自检（找的是“启动即错”，不是训练质量）：
   - 状态是否从 `排队中` → `部署中` → `运行中`；
   - 首个 rank 日志是否出现镜像/入口回显、`torchrun` 或 launcher 的启动行；
   - 是否出现 `No such file`、`permission denied`、`exec format error`、缺挂载等启动错误；
   - 是否已经出现真实 batch/step 行（出现才算真跑起来）。
4. 判据：`排队中` 只证明创建成功；`运行中` 只证明平台调度状态；日志里出现真实计算行、训练任务再出现有限 loss，才算跑起来。三种证据分开写。

首屏 5 分钟的用途是抓“入口写错、镜像不对、挂载缺”这类一次就能看出来的问题。它抓不到训练质量，也不证明能跑完一个 epoch。

排队等待、失败定位和交接窗口另见[排队、失败定位与交接窗口](queue-and-failure-triage.md)。

## 9. 常见误判

| 现象 | 不等于 |
|---|---|
| `ml_task list` 里没有这个任务 | 任务不存在（`list` 只列非终态，且当前缺凭据直接返回 255） |
| 表单显示“设置成功” | 入口命令已经是新的（可能被追加或截断；要读回完整值） |
| 数字框显示 0 | 你设置了 0 小时（可能是 `AXIncrementor` 把输入清掉了；确认是否本应留空） |
| 点到了某一行 | 点对了行（大菜单遮挡会让点击偏移，用 AX 确认） |
| 页面 `运行中` | 训练在推进（要日志有步数、共享存储有 checkpoint） |
| 详情页 `失败` + 某 worker 异常结束 | 一定是代码 bug（也可能来自短输入、挂载、依赖或 GPU 初始化；按日志证据定性） |
| CLI 报 `AccessKeyId or SecretAccessKey is empty` | 平台坏了（是本地凭据没配） |

## 10. 证据清单（提交后应能拿出这些）

- 表单 URL 里的 `?Id=<源任务ID>`；
- 提交前表单的入口命令完整文本 + 提交后详情页的入口命令完整文本（两者与预期逐字相同）；
- 新任务完整 ID、名称、创建时间、优先级、镜像、队列、worker/GPU、挂载、自动重试、时限；
- 5 分钟首屏日志片段（含时间戳与 rank）；
- 若失败：失败时间、失败 worker、首个错误的完整栈，以及第 2 节之外的三步定位结果。
