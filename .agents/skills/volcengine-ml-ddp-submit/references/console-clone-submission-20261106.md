# 控制台"复制任务"提交手册（2026-11-06 实测可用）

适用：需要在火山引擎机器学习平台提交或复制一个自定义任务，而 CLI 不可用（`~/.volc/credentials` 不存在、只有 `access_token`，`volc ml_task get` / `mlp job list` 报 `AccessKeyId or SecretAccessKey is empty`）。这时能走的只有控制台复制既有任务这条路。

- 上游事实：`提交通道的现实约束（2026-11-06 核实）`（`SKILL.md`）+ 2026-11-06 事实清单第四节。
- 本文只写操作步骤与核对方法。实验合同（镜像 tag、入口、挂载、输出）仍归对应项目技能，不在本文。

---

## 0. 一句话流程

任务列表 → 目标行操作列点 `复制` → 表单被预填（URL 带 `?Id=<task>`）→ 只改三处（任务名、描述、入口命令）→ 点 `复制任务` → 详情页逐字段核对 → 5 分钟首屏自检。

---

## 1. 打开预填表单

1. 进入自定义任务列表页，按完整任务名或 ID 定位目标行。ID 被截断时读 tooltip 或打开详情；靠截图辨认容易认错行。
2. 在目标行的操作列点 `复制`。
3. 表单页打开后先看地址栏，应形如 `/customTask/create?Id=<源任务ID>`。`Id` 就是被复制的源任务，记进报告，它是"这次提交从哪来"的唯一凭据。
4. 表单此时已带出源任务的全部字段。带出来不等于每个字段都还适用，逐项走第 2 节。

---

## 2. 提交时要改的三处

| # | 字段 | 改成什么 | 判据 |
|---|---|---|---|
| 1 | 任务名称 | 以 `zhounan_` 开头、全局唯一（含实验标识与版本/日期） | 提交后详情页名称与表单逐字一致；`zhounan_` 前缀是归属标识，丢了按前缀就检索不到 |
| 2 | 描述 | 如实写：源任务/父任务、本次改了什么（配置/入口/挂载）、已知限制 | 详情页描述非空且与表单一致 |
| 3 | 入口命令 | 本次要跑的入口（多行命令整体替换，不是追加） | 重新读回编辑器的完整值，与预期入口逐字相等；只看"设置成功"的提示不够 |

> 入口命令的多行形态示例（LM 场景，来自 2026-11-06 事实清单，仅示范格式）：
> ```bash
> /bin/bash -lc 'set -euo pipefail
> export LM_PACKAGE_SHA=<sha>
> export LM_CONTRACT_SHA=<sha>
> exec /bin/bash <package>/runtime/lm_launch.sh'
> ```

入口命令最容易出错的地方在于：复制来的编辑器里已有旧命令，自动化的 `fill` 可能把新内容追加在后面，命令于是变成"旧命令 + 新命令"。提交前重新读取编辑器的实际完整值并逐字比对；不比对的话，提交出去的就是拼接后的命令。

---

## 3. 沿用项（照抄源任务，逐项确认）

| 字段 | 期望 | 备注 |
|---|---|---|
| 镜像 | 与源任务相同的私有镜像 & tag | 要换镜像时先回项目技能确认 tag |
| 队列 / 可用区 | 同源任务 | 队列满时排队等待；为绕开队列重复提交没有作用 |
| 优先级 | `6` | 用户硬要求；提交后从详情页再核一次 |
| 规格（每 worker GPU 型号/数量）/ worker 数 | 同源任务 | 与 launcher 的拓扑合同一致 |
| 框架 | `PyTorch DDP` | — |
| 挂载（双挂载） | 同源任务，容器目标互不重叠 | 继承来的额外挂载要逐项确认是否仍然必要 |
| 自动重试 | 关闭（诊断/首次验证阶段） | 复制会继承源设置，要显式确认 |
| 最长运行时间 | 用户给定上限；留空也可提交 | 见 §4 的 `AXIncrementor` 问题 |

继承风险：复制会静默带上源任务的环境变量、额外挂载、自动重试和可见范围。每一项要么确认确实要沿用，要么清空；表单不报错只说明字段通过了校验，不代表取值合适。

## 4. 自动化操作要点

### 4.1 用 AX 元素动作，不用坐标点击

- 可用：`AXPress` 点按钮；`set_value` 填 `AXTextField` / `AXTextArea`（任务名称、描述、入口命令）。
- 不可靠：按屏幕坐标点击。页面顶部"所有产品服务"大菜单一旦展开会整体遮挡，点击会偏到相邻行或相邻按钮上，曾因此点到别的任务行。确实要点坐标时，先用 `Escape` 或关闭菜单，再用 AX 树确认目标元素在最上层。

### 4.2 AX 快照 60 秒过期，且重采会移位

- 快照里的元素索引不是稳定 ID：重新采样后，同一按钮的索引会变。
- 所以一次采样后要立刻动作。采样完再思考、回头点，索引可能已经移到别的元素上。超过 60 秒重新采样并重新定位，不复用旧索引。
- 动作后重新读回该元素的值（`set_value` 之后读 `AXValue`），确认落值；"操作成功"的提示说明不了值已经写进去。

### 4.3 `AXIncrementor`（数字步进框）不接收 `set_value` 和合成输入

- "最长运行时间"这类数字框是 `AXIncrementor`：`set_value` 和合成键盘输入都会被清成 0。不是填不上，而是填进去又被归零，看起来很像"已设置 0 小时"。
- 实测的处置是留空，平台仍接受提交（2026-11-06 LM 提交即这个状态）。确实要设值时，用框旁的加减按钮或在页面上人工输入，提交后从详情页核对实际值。

### 4.4 提交按钮叫 `复制任务`

- 不叫"创建"或"提交"。点它就会创建新任务，属于对外写入；确认已获授权再点。

## 5. 提交后核对

1. 详情页逐字段核对：任务名、描述、入口命令（完整多行）、优先级 `6`、框架、队列/AZ、worker 数与每 worker GPU、镜像 tag、挂载、自动重试、时限。
2. 记录完整任务 ID（`t-YYYYMMDDHHMMSS-xxxxx`）与创建时间，写进报告。
3. 5 分钟首屏自检（找的是"启动即错"，不是训练质量）：
   - 状态是否从 `排队中` → `部署中` → `运行中`；
   - 首个 rank 日志是否出现镜像/入口回显、`torchrun` 或 launcher 的启动行；
   - 是否出现 `No such file`、`permission denied`、`exec format error`、缺挂载、`AccessKeyId or SecretAccessKey is empty` 之外的鉴权/网络错误；
   - 是否已经出现真实 batch/step 行（出现才算真跑起来）。
4. 判据：`排队中` 只证明创建成功；`运行中` 只证明平台调度状态；日志里出现真实计算行、训练任务再出现有限 loss，才算跑起来。三种证据分开写。

---

## 6. 常见误判

| 现象 | 不等于 |
|---|---|
| `ml_task list` 里没有这个任务 | 任务不存在（`list` 只列非终态；已结束任务要用 `get -i` 或控制台查） |
| 表单显示"设置成功" | 入口命令已经是新的（可能被追加；要读回完整值） |
| 数字框显示 0 | 你设置了 0 小时（可能是 `AXIncrementor` 把输入清掉了；确认是否本应留空） |
| 点到了某一行 | 点对了行（大菜单遮挡会让点击偏移，用 AX 确认） |
| 页面 `运行中` | 训练在推进（要日志有步数、共享存储有 checkpoint） |
| 详情页 `失败` + 某 worker 异常结束 | 一定是代码 bug（也可能来自短输入、挂载或依赖；按日志证据定性） |

---

## 7. 证据清单（提交后应能拿出这些）

- 表单 URL 里的 `?Id=<源任务ID>`；
- 提交前表单的入口命令完整文本 + 提交后详情页的入口命令完整文本（两者应逐字相同）；
- 新任务完整 ID、名称、创建时间、优先级、镜像、队列、worker/GPU、挂载、自动重试、时限；
- 5 分钟首屏日志片段（含时间戳与 rank）；
- 若失败：失败时间、失败 worker、首个错误的完整栈。
