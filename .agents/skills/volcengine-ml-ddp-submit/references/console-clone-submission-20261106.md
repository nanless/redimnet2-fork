# 控制台"复制任务"提交手册（2026-11-06 实测可用）

适用：需要在火山引擎机器学习平台提交/复制一个自定义任务，而 **CLI 不可用**（`~/.volc/credentials` 不存在、只有 `access_token`，`volc ml_task get` / `mlp job list` 报 `AccessKeyId or SecretAccessKey is empty`）。此时**控制台复制既有任务是唯一可用通道**。

- 上游事实：`提交通道的现实约束（2026-11-06 核实）`（`SKILL.md`）+ 2026-11-06 事实清单第四节。
- 本文只讲"怎么做、怎么验"。实验合同（镜像 tag、入口、挂载、输出）仍归对应项目技能，不在本文。

---

## 0. 一句话流程

**任务列表 → 目标行操作列点 `复制` → 表单被预填（URL 带 `?Id=<task>`）→ 只改三处（任务名/描述/入口命令）→ 点 `复制任务` → 详情页逐字段核对 → 5 分钟首屏自检。**

---

## 1. 打开预填表单

1. 进入自定义任务**列表页**，按完整任务名或 ID 定位目标行（ID 被截断时读 tooltip 或打开详情，不要靠截图猜）。
2. 在目标行的**操作列**点 `复制`。
3. 表单页打开后**先看地址栏**：应形如 `/customTask/create?Id=<源任务ID>`。`Id` 就是被复制的源任务——把它记进报告，它是"这次提交从哪来"的唯一凭据。
4. 表单此时已带出源任务的全部字段：**不要假设你看到的都是对的**，逐项走第 2 节。

---

## 2. 必须改的三处（只改这三处）

| # | 字段 | 改成什么 | 判据 |
|---|---|---|---|
| 1 | **任务名称** | 以 `zhounan_` 开头、全局唯一（含实验标识与版本/日期） | 提交后详情页名称与表单逐字一致；`zhounan_` 前缀不得丢 |
| 2 | **描述** | 如实写：源任务/父任务、本次改了什么（配置/入口/挂载）、已知限制 | 详情页描述非空且与表单一致 |
| 3 | **入口命令** | 本次要跑的入口（多行命令整体替换，不是追加） | **重新读回编辑器的完整值**，与预期入口**逐字**相等；不能只看"设置成功" |

> 入口命令的多行形态示例（LM 场景，来自 2026-11-06 事实清单，仅示范格式）：
> ```bash
> /bin/bash -lc 'set -euo pipefail
> export LM_PACKAGE_SHA=<sha>
> export LM_CONTRACT_SHA=<sha>
> exec /bin/bash <package>/runtime/lm_launch.sh'
> ```

**入口命令最容易出错的一点**：复制来的编辑器里已有旧命令。自动化的 `fill` 可能把新内容**追加**在后面，于是命令变成"旧命令 + 新命令"。提交前必须重新读取编辑器的实际完整值并逐字比对。

---

## 3. 沿用项（照抄源任务，但要逐项确认，不是默认相信）

| 字段 | 期望 | 备注 |
|---|---|---|
| 镜像 | 与源任务相同的私有镜像 & tag | 需要换镜像时先回项目技能确认 tag，别猜 |
| 队列 / 可用区 | 同源任务 | 队列满时排队，不要为绕队列重复提交 |
| 优先级 | **`6`** | 用户硬要求；提交后从详情页再核一次 |
| 规格（每 worker GPU 型号/数量）/ worker 数 | 同源任务 | 与 launcher 的拓扑合同一致 |
| 框架 | `PyTorch DDP` | — |
| 挂载（双挂载） | 同源任务，容器目标互不重叠 | 继承来的额外挂载要逐项确认是否仍然必要 |
| 自动重试 | **关闭**（诊断/首次验证阶段） | 复制会继承源设置，必须显式确认 |
| 最长运行时间 | 用户给定上限；**留空也可提交** | 见 §4 的 `AXIncrementor` 坑 |

**继承风险**：复制会静默带上源任务的**环境变量、额外挂载、自动重试、可见范围**。每一项都要么确认"确实要沿用"，要么清空；不要因为表单里没报错就当它对。

---

## 4. 自动化要点（血泪，按重要性排序）

### 4.1 用 AX 元素动作，不要用坐标点击

- **可用**：`AXPress` 点按钮；`set_value` 填 `AXTextField` / `AXTextArea`（任务名称、描述、入口命令）。
- **不可靠**：按屏幕坐标点击。页面顶部"**所有产品服务**"大菜单一旦展开会**整体遮挡**，点击会偏到相邻行/相邻按钮上——曾导致点到别的任务行。若必须点，先 `Escape` 或关闭菜单，再用 AX 树确认目标元素确实在最上层。

### 4.2 AX 快照 60 秒过期，且重采会移位

- 快照里的元素索引**不是稳定 ID**：重新采样后同一按钮的索引会变。
- 因此：**一次采样 → 立刻动作**，不要"先采样、再思考、回来点"。超过 60 秒必须重新采样并重新定位，绝不复用旧索引。
- 动作后要**重新读回该元素的值**（`set_value` 之后读 `AXValue`），确认落值，而不是看"操作成功"。

### 4.3 `AXIncrementor`（数字步进框）不吃 `set_value`/合成键入

- "最长运行时间"这类数字框是 `AXIncrementor`：`set_value` 与合成键盘输入都会被**清成 0**（不是填不上，是填了又被归零，很容易误判为"已设置 0 小时"）。
- 实测处置：**留空**，平台仍接受提交（2026-11-06 LM 提交即该状态）。若必须设值，用框旁的加减按钮或直接在页面上人工输入，并在提交后从详情页核对实际值。

### 4.4 提交按钮叫 `复制任务`

- 不是"创建"/"提交"。点它=真正创建新任务（外部写入），确认已获授权再点。

## 5. 提交后核对（缺一不算提交成功）

1. **详情页逐字段核对**：任务名、描述、入口命令（完整多行）、优先级 `6`、框架、队列/AZ、worker 数与每 worker GPU、镜像 tag、挂载、自动重试、时限。
2. **记录完整任务 ID**（`t-YYYYMMDDHHMMSS-xxxxx`）与创建时间，写进报告。
3. **5 分钟首屏自检**（找的是"启动即错"，不是训练质量）：
   - 状态是否从 `排队中` → `部署中` → `运行中`；
   - 首个 rank 日志是否出现镜像/入口回显、`torchrun` 或 launcher 的启动行；
   - 是否出现 `No such file`、`permission denied`、`exec format error`、缺挂载、`AccessKeyId or SecretAccessKey is empty` 之外的鉴权/网络错误；
   - 是否已经出现真实 batch/step 行（出现才算真跑起来）。
4. **判据**：`排队中` 只证明创建成功；`运行中` 只证明平台状态；**必须**看到日志里的真实计算与（训练）有限 loss 才算跑起来。三种证据分开写。

---

## 6. 常见误判

| 现象 | 不等于 |
|---|---|
| `ml_task list` 里没有这个任务 | 任务不存在（**`list` 只列非终态**；已结束任务要用 `get -i` 或控制台查） |
| 表单显示"设置成功" | 入口命令已经是新的（可能被追加；要读回完整值） |
| 数字框显示 0 | 你设置了 0 小时（可能是 `AXIncrementor` 把输入清掉了；确认是否本应留空） |
| 点到了某一行 | 点对了行（大菜单遮挡会造成偏移，必须用 AX 确认） |
| 页面 `运行中` | 训练在推进（要日志有步数、共享存储有 checkpoint） |
| 详情页 `失败` + 某 worker 异常结束 | 一定是代码 bug（也可能是短输入/挂载/依赖；按日志证据定性） |

---

## 7. 证据清单（提交后应能拿出这些）

- 表单 URL 里的 `?Id=<源任务ID>`；
- 提交前表单的入口命令完整文本 + 提交后详情页的入口命令完整文本（两者应逐字相同）；
- 新任务完整 ID、名称、创建时间、优先级、镜像、队列、worker/GPU、挂载、自动重试、时限；
- 5 分钟首屏日志片段（含时间戳与 rank）；
- 若失败：失败时间、失败 worker、首个错误的完整栈。
