## 4. 失败特征（迹象与处置）

| 迹象 | 含义 | 处置 |
|---|---|---|
| `LM_GATE_REFUSED {…}` | 包/合同/权重/映射/目录任一不满足，没进训练 | 按 error 文本修；同目录重试会撞上已存在的输出 |
| `unrecognized arguments: …` | 入口命令带了 gate 不认识的参数 | 改入口命令；包本身没问题 |
| `sha256sum: … FAILED` | 包或合同字节被改 | 停；包已不可信 |
| `resume: restored optimizer state from` / `restored GradScaler state from` | 按 PTN 同阶段恢复了动量，冷启动失败 | 停任务 |
| `could NOT restore` / `freshly initialised` | 恢复路径被动过 | 停任务并留日志 |
| `Traceback` / `ChildFailedError` / `CUDA out of memory`（前 5 分钟） | 环境或显存 | 停任务，证据留在 `EXP_DIR` |
| `EXP_DIR` 已存在导致 gate code=2 | 复用了旧目录 | 换新版本目录 |

## 5. 2026-11-06 的真实事故：入口多了 `--execute`

`lm_launch.sh` 把 `"$@"` 透传给 `lm_stage_gate.py`；PTN 的 `entry.py` 有 `--execute`，照抄过来的入口命令于是也在末尾带了它。
gate 的 argparse 不认这个参数：`sha256sum` 两道门都过了，接着报
`lm_stage_gate.py: error: unrecognized arguments: --execute`，exit 2，一条 gate 日志都没有，训练根本没开始。
任务排到卡就立刻失败，看起来像"包坏了"，实际是入口参数与 gate 不一致。

处置状态（2026-11-08 复核）：`t-20261106195855-rq2b7` 为该 bug 版本，从未运行（入口带 `--execute` 会被 `lm_stage_gate` 的 argparse 拒绝）；其后 `t-20261107053934-6lcmt` 因冻结包内 `source/applications/speaker_rec/launch.sh` 缺可执行位而 `launcher_missing` 失败（1 分 01 秒）；最终 `t-20261106110454-vd8pq` 于 2026-11-07 03:05–05:37 UTC 跑满 1 轮、13,075 步、exit 0、`vox1-eer-8s=0.293%`。

这三个任务号都是平台侧记录，本地没有留档：运行目录里 `cloud_launch_lm.log`、`train.log`、`lm_receipt.json` 都不含 `task_id` 字段，`volc ml_task get` 又因缺凭据读不到终态。所以"哪个任务号跑完了"只能在控制台核，本地能证到的只有"某个运行目录跑完了一轮"。产物 sha 现查：`sha256sum <lm>/models/model_1.pt`（或看仓库 `docs/STATUS.md` 第 4 节）。注意 `lm_receipt.json` 仍记 `ok:false`，原因是门禁只读 `train.log` 找冷启动标记，而该标记打在 `cloud_launch_lm.log`（14 次）——源码已在 `7d03d3c` 修正，但冻结包 r3 未重打。处理顺序是：停掉该任务 → 用『复制任务』重提、入口末尾去掉该参数 → 任务名加 `-v1b`。

包不重建，r3 的两个 sha 仍有效。仓库源码同时把 `--execute` 改成 no-op 兼容，并加了
「带与不带行为一致」的单测；这要重新打包才生效，r3 包内仍是严格版。
于是在重提完成之前，任何照抄本 runbook 旧入口（带 `--execute`）的提交都会 exit 2。

平台入口命令要和 `lm_launch.sh` → gate 的 argparse 对齐；参数不一致时 gate 直接报 unrecognized arguments，任务连训练都没开始。提交前用 `--help` 本地验一遍。
