# 训练巡检与恢复范围

## 证据采集

先核对任务ID、run root、启动身份、阶段与数据集。分别读取持久 train.log、外层 reproduction.log 和云stdout，避免重复输出累计异常次数。固定一个完整统计快照；其后的最新行作为补充复核，注明各自时间与时区。实际GPU状态从精确任务worker采样，不能用开发机代替；浏览器登录失效时请用户完成登录，不读取认证材料。

检查：多rank对齐、日志是否推进、loss/LR/margin/Acc是否有限、Traceback是否被捕获后继续、OOM/NCCL/子进程退出、短音频限频打印、检查点稳定性和磁盘可用性。WARNING 训练行是常规输出，不按日志级别计为异常。只转录或存储必要白名单运行字段，避免整份环境变量或凭证。

异常以独立发生的轮次、前后批号、音频和原文登记。同一发生在stdout/reproduction中的副本可去重；不同轮批再次发生，即使key和归一化块SHA相同也分别计数。原始字节SHA与换行规范化后比较SHA分别保存。已被捕获且日志继续不等于未来阶段门禁已接受，需按专用阶段规则另行核验；音频复查成功不证明历史根因已经消失。 整段及首中末成功不排除生产裁剪或近文件末端seek/read失败；区分当次加载的soundfile.py与原生libsndfile路径、摘要、版本及探测位置。仅巡检时记录失败与推进，不自行改事件许可或解码环境。开发机私有库对照通过与真实worker验收分开，未记录的历史随机起点不得写成已完整重放。

## 指标解释

当前计量器rank0每16批采样1批，本轮累计、每25批打印，无跨卡归约。loss/Acc不是最近25批瞬时均值；分类Acc不是验证准确率。日志批次是数据批次/更新尝试，AMP存在跳过更新可能，不能称已证明成功的 optimizer step。

本次已核实计划为120轮、每轮15001批的PTN累计进度为 `(epoch-1)*15001+batch` 除以 `120*15001`；其他配方或后继任务先从实际有效配置核实轮数和每轮批数，不套用这些常数。新任务不继承被停止旧任务的累计计数。监控协议相同才能比较EER趋势。百分数、百分点和相对变化分别计算，快速8秒验证与最终整段LM协议分别报告。数值有限不代表质量改善；与LR同时变化不证明因果，不能仅凭数轮回升宣布过拟合或发散。

GPU至少记录采样时刻、卡号、利用率、MiB显存/总显存、温度、功耗；短时间多次采样仍不是全程均值/峰值。rank PID、WORLD_SIZE、cwd、worker子进程数可证明当前运行结构，不能证明每个训练batch成功更新。

## 检查点

先stat，再用CPU、单线程、mmap逐份读取可信本项目checkpoint；读取后复核size/mtime稳定。正在写的TMP不当完整恢复点。核对epoch与文件名、model/optimizer/scaler、head形状、浮点有限性与optimizer/scaler状态；给出最新和最佳验证点两个身份。检查点读取成功不证明加载入口、源码冻结或未来阶段可用。

现行按整轮原子保存，不含完整RNG、loader游标和轮内状态。恢复通常重做当前轮；不要承诺逐批/逐位复现。原PTN续训恢复model、optimizer、scaler与epoch；PTN→新LM只初始化模型并新建optimizer/scaler，不能把两者混同。执行恢复前读阶段门禁引用。

## CPU 恢复演练（2026-11-06）

对 `model_120.pt` 做过一次纯 CPU、单线程、mmap 的只读恢复演练，结论是**文件本身自洽**：

- 四键齐全（`model`/`epoch`/`optimizer`/`scaler`）；823 张量、81,422,833 元素（含 78 个 int64）；584 份 SGD 动量；`scaler=16384.0`；`lr` 与 `val_log.csv` 第 120 轮逐位一致；1,329 个浮点张量 0 非有限；体积闭合 0 字节误差。
- **能加载 ≠ 能续训**：检查点没有 per-rank RNG，也没有 48—120 段的 dataloader 游标。恢复只能重做"已保存的完整状态 + 绝对时钟"，不能承诺与不中断训练逐位相同。PTN→LM 更是只取模型参数，动量与 scaler 一律新建。

两个"假通过"，都出现过：

1. **`torch.cuda.amp.GradScaler` 在无 GPU 的机器上会静默 Disabled**：`load_state_dict` 变成空操作、`get_scale()` 恒返回 1.0，于是"scaler 恢复成功"是假的。CPU 演练必须用 `torch.amp.GradScaler("cpu")`，并显式断言 `get_scale()` 等于检查点里的值。
2. **`read_bytes=0` 不等于"没读"**：页缓存命中与 mmap 访问不计入 `/proc/<pid>/io` 的 rchar。拿 rchar 判断"是否真的读过权重"会得出反的结论；要证明读过，看读到内容后的校验结果（张量数、非有限计数、体积闭合），不看 IO 计数。

演练本身不授权任何 GPU 或新阶段；它只说明这份文件能被人读懂。

## ETA

同时给短窗口批耗时与近期完整轮周期。批耗时只取同轮窗口，另算一次轮间开销；完整轮周期已经含保存、验证、重建，不能再加一次。明确端点：`WARNING 15000→下轮25` 与 `INFO15001→下轮25` 不同，两者都包含下一轮前25批，不能称纯验证耗时。

报估算锚点、剩余批数、方法差异和阶段边界。PTN与LM帧数/batch不同，32批LM短测不足以可靠外推完整阶段；未执行的导出、完整评测不算进PTN ETA。方法范围不是置信区间；门禁已知会失败时不要承诺无人值守整流程完工。
