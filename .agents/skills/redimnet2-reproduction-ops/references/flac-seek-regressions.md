# FLAC定位回归与逐事件版本更新

本页记录ReDimNet2里被捕获的FLAC读取异常，以及未来LM接续时的修复。当前训练进程、源码、音频和冻结证据都保持原样。巡检阶段只记录事实，不改许可、库或入口；只有用户明确要求修复，才准备独立的新版本。一次授权不等于接受以后任意重复的同类错误。

## 逐次审阅，不按样本合并

本轮（2026-10-23）的授权范围是严格七次原PTN发生、三份音频，第8次仍然拒绝。四次同movie、两次同interview即使完整原始块SHA相同，也分别保留位置和轮次——同一段音频的两次发生不是同一个事件。第5次新id11211的栈是初始f.seek，异常末行虽然相同，不能因此说旧两文件已经被覆盖。固定新版本时，要保留完整日志前缀及旧prefix的来源链，逐条绑定task/run/attempt、offset、完整原文及上下文、raw/换行规范化SHA、key/spk/wav和前后首次显示进度。预取让显示的批号不等于失败样本的实际batch；历史的随机起点没有记录。

代码里固定登记文件路径和SHA；contract不接收任意允许次数、任意ledger或新SHA——额度与日志一旦可以自选，七次许可就形同虚设。完整日志里新出现的Traceback/read_failed及变体、裸异常、非有限和致命标记仍然拒绝；删、重排、移位或重新拼日志都不能通过。新授权要配新版本和新证据，v3的历史不原地改。

## 避免有限网格漏掉定位失败

顺序全读、首中末和0/可裁剪范围0.5/末端通过，不保证任意随机seek都能通过。本次id11211共379321帧@16k，SEEKTABLE点在159744/319488。旧生产网格的PTN点是0/171928/343856，漏掉了已经实证的319487。取点要从元数据和真实错误出发，保留定位表及块边界邻点；每点fresh open，先seek再tell/read。只在全读到EOF后的同一handle上压测成功，不能算生产成功。

已实证PTN319487、请求35464这两个点：旧后端1.0.28在3个新解释器上共15/15次初始seek失败，私有1.2.2在同样条件下15/15成功，PCM与顺序参考一致。319487超出该文件LM88264请求的合法起点范围，所以不冒充LM的生产点；取邻点要按各阶段范围过滤，nearEOF压力另记。本轮代码计划是旧11+新13个PTN/8LM共32窗口；实际数量要由当前代码和真实审计输出重新数，计划清单不等于32项实际通过。后续更改不硬套这个数量。

三份音频的path/resolved/bytes/SHA及新样本头信息固定登记。读前后身份不变；每个生产点校seek/tell、精确长度、默认float64、有限值，并与独立顺序切片的PCM SHA比对。任何失败都保留部分审计并整体拒绝——跳过该文件，或用后面的成功盖掉失败，都会让这一点的结论失去依据。实际用到的原旧库对照、指定新库、同soundfile.py、actual maps及版本都要记录；CPU/真实worker/GPU各自界限清楚。

两个后端的整段PCM及16bit MD5都命中原FLAC的STREAMINFO，说明本文件的顺序音频一致；它不证明全随机空间/全数据一致，也不证明模型逐位等价。旧库与私有库的链接依赖不同，所以只能说本次二进制及依赖组合存在行为差异，不能直接归因某个单一上游提交。私有库只给未来的新解释器设置LD路径，保留平台NCCL/NVIDIA项、清PRELOAD/AUDIT并核真实映射；当前PTN系统/Conda环境不热换，原数据不重编码/删改。
