# 完整字自然变长实验

对外汇报状态时，按[任务状态与只读巡检](task-status-and-readonly-progress.md)区分这条实验、PTN／LM与正在运行的侧车标注。10月28日22:28的记录里，官方模型完整字微调和本轮模型的交叉长度正式评测都还没启动。

2026-11-06 更新：长度交叉评测的 CPU 部分已完成。导出 `ptn-model_115.pt`/`_120.pt` 各 51,411,906 B，链校验 48 格 0 差异、`cache_hits=0/180`；9 格均值 EER 官方 4.6871 / PTN-115 4.6743 / PTN-120 5.3512，27/27 组 CI 两两重叠，所以不能判复现成败。官方模型的完整字自然变长微调仍无启动证据。自动标注做得再多，也不自动改变这两条。

代码在 `word_ft/`、`word_ft_v3/` 及对应 `scripts/`、`configs/`；`duration_ft/` 的固定秒数裁片只作历史压力诊断，不能替代完整字输入：它测的是固定长度下的压力，与完整字输入不是同一口径。维护版本的命令和测试以仓库内 README 为准。

用户要的是一个或几个完整的字词，不是任意秒数的截取。固定相同起点的 1、2、3、6 单位前缀族需同原音、说话人、发生序号与原时钟；靠重复四个来源填满八卡，等于把八卡batch变成同一批样本的复制。正式分组、说话人、会话和用途证据不足时明确待核，不猜身份。

自动标注消费默认只生成待核提案。工程导出要重新核编码文件、完整原采样率 PCM、头信息与稳定 stat，并保留待审核状态、未授训练/评测资格和独立工程分组。旧训练器或正式评测入口默认应拒绝这些候选；显式导出时如果全被拒绝或零导出，应以非零码退出，否则空结果会被当成成功。

外部保护表中的真实诊断来源，在提案和导出两层都拒绝：只拦一层的话，另一层就是绕过口。精确来源 ID 和已经证明的绝对路径别名可以核实；按路径后缀或文件名猜不行，猜错的代价是保护来源漏进训练。原训练表保留原字节，不靠改原保护字段掩盖消费者遗漏。

三个完整字训练入口还须检查原来源资格。外层`split=train`不能清除metadata、记录、provenance及其中`source`、现有适配器使用的`source_original`所保留的留出、保护或明确禁训证据；两个来源字段同时出现时都要核，不能挑一个信。注册的`evaluation:*`、`supplemental:test`、校准及受保护回归角色仍拒绝。原字段明确写`dev`，与仅在音频路径中出现`dev`不是一回事，不能把VoxCeleb开发集目录名猜成评测用途。显式候选开关不覆盖这些资格约束。

从官方模型微调时绑定官方权重身份、新说话人头与冷优化器；它与复现主训练转大间隔阶段不是同一任务。评测先冻结注册/测试两端的长度或完整单位组合、成对协议、样本发生序号、说话人和用途隔离，再比较原官方模型与微调模型。缺失败样本或只剩可对齐样本时，不报完整总体性能，那样的数字只覆盖留下来的那部分。

没有足量独立来源、真实完整字边界审核和正式数据质量，CPU 测试通过仍不能启动正式微调。模型间一致率不是字界准确率，旧完整句基线也不是短单位的收益。
