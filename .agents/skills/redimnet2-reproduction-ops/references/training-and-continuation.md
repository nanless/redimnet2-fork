# 主训练和大间隔微调

训练入口在 `applications/speaker_rec/`，跨段准备工具在 `tools/lm_continuation/`。先读相应目录说明，再执行仓库测试；不能从旧实验目录导入仓库中没有的唯一依赖。

历史普通接续入口、数据子进程和恢复检查参考在 `tools/ptn_reference/`。先读其 README、逐文件索引和公开维护差异；只可用 `audit_reference.py` 核摘要、Python 编译语法与 `bash -n`。不要导入归档模块或执行 `archive/launch.sh`，其中含实际启动和进程管理动作。缺少原合同、源码凭证、终态和权重时不能补空文件放行；`runtime_admission` 始终为 false。去除真实诊断标识后的公开版本有新身份，不能声称与全部历史文件原字节一致或已继承 GPU 证明。

同阶段恢复应恢复检查点中的模型、优化器、梯度缩放器及训练步数，核分类头说话人映射。主训练转大间隔阶段则遵配方选择初始化轮数、重建阶段优化器；不要把两者混为“继续训练”。完整验证最优权重与配方指定的阶段初始化权重也要分清。

跨两段记录时绑定前段终点、后段八进程的同一恢复来源、完整训练与验证记录、固定依赖、异常审查和新鲜终态。原段允许的逐条已审异常不能自动移植到后段。裸 `LibsndfileError`、`OSError` 或其他异常即使没有 Traceback，也不能漏过后段检查。

CPU 准备检查应始终与真正执行分开：合成的未来完成记录只验证代码分支，不能授权启动。真实读取检查点前限制到可信路径，拒绝通过自供摘要加载任意 pickle。输出只写本次专用准备目录，不创建训练输出树，不拿启动锁冒充实际许可。

巡检记录需包含日志观测时刻、实际步数、验证指标、最新与最佳检查点、八个计算进程和 GPU UUID。0% 利用率不是空闲；没有计算进程、显存和真实设备身份的完整证据，不据此启动新 GPU 工作。预计剩余时间说明窗口吞吐、剩余轮数及维护/排队不确定性。
