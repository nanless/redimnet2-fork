# 开源模型自动标注

实时封账进度可用`tools/open_annotation/readonly_progress.py`：只读一个原子broker快照及其中已完成、非活动租约的固定槽，不构造WorkQueue、不拿写锁、不扫描全部侧车。报告必须称完成下界；`failed`是发布决定，不表示所有操作错误为0。一个快照不能给ETA，须同口径时间窗口增量；输出放新审计目录，不能放队列内。原子替换可改变旧FD的ctime，不能只凭该变化误拒合法快照；仍核已打开FD的尺寸、mtime、完整JSON及固定身份。

2026-10-26检查时待复核约占七成，包含原生零/负时长、未解决重叠、库内修补及文字读法未决。`processing_errors_preserved`可能是保存这些模型结果几何错误，不一定是worker程序崩溃。不得为提高产出比例放宽判据；候选和待复核都不自动授予训练或正式评测资格。固定前缀抽查不是随机金标，不能推算全库文字/字界准确率。

维护代码在 `tools/open_annotation/`。本轮批量范围是 VoxCeleb2、VoxBlink2、CN-Celeb2 的实际训练来源，主训练与大间隔清单中的同一来源只计一次。额外评测域、噪声、房间脉冲和业务诊断不加入主分母。范围改变须按本次用户要求重新确定，不能沿用历史混合批。

保留原件编码摘要、原采样率多通道解码摘要、模型实际输入摘要、时钟和原始说话人/用途信息。旧 VAD 只能据实际存在的身份材料复用，不把路径/stat 绑定描述成旧音频 SHA 绑定；无关路径不能用相同文件名放宽。

必须保存模型原始文字和语言、归一化每一步、原生时间、库内修补和几何错误。零长、越界、生成截断、空转写、不支持语言、数字/混合脚本读法未决均入完整分母。对多个汉字组成的原生粗词不平均拆时间，机器听辨不充作人工审核。

单窗执行合同须绑定实际调用宽度与缓存语义；同窗在不同批次中可能变化，不能仅往缓存键加批大小而继续跨组合复用。恢复比较完整基线与新输出的原生 ASR、对齐及观察层；分开旧结果复用、缓存消费与实际重执行。

发布需核原子输出、提交记录、队列归属、代次与输入集合，不只看 worker 退出码。CPU 队列测试不能证明远端文件系统或跨节点锁语义；现场验收分别保存资源主动证明、实际 worker、所有 rank 和归还快照。

完成后的全量审查要从重新打开的侧车重算三状态，逐片与完成槽计数核对，并核完整的单源提交描述及分片身份；摘要字段存在不等于字段互相一致。Ultra原生观察还须核实际logits摘要、行数/词表形状、类别范围与输入位置范围。运行中不要拿终态审查缺少完整分母的结果当软件故障。输出、缓存和队列路径要检查根目录与中间目录软链，不能只核最后一个文件名；拒绝时保留原文件，不清锁或改旧冻结代码来绕过。

候选状态和几何合法不能把 `usable_for_training/evaluation` 改真。保护引用作为显式外部输入按调用者提供并核实的固定 SHA 绑定；公开测试用合成保护表，不发布真实名单。未知或失败仍允许诚实保存为待核自动标注，但不能承诺完整字准确率。

## 正在运行时如何只读计数

现场代码须先与部署身份对应。不要为了巡检实例化`WorkQueue`，其构造器会创建目录、加锁及初始化文件。`report.py`即使非全量模式也要求全局完成，不能将运行中尚未完成的分母错误直接当作任务失败。

轻量进度读取原子更新的`queue/broker.json`、`identity.json`和已核摘要的固定索引。核对游标、租约编号与`next-len(leases)==completed_chunks`；以该次队列记录的完成集合为准，按分片实际`count`求和，不能乘以固定256。完成槽按1024字节读取，检查魔数、载荷SHA、索引/合同/分片身份和三状态计数之和。记录读取起止时间，活动租约不计入；按协议已封账槽应已完整同步，校验不通过就保留错误并拒绝成功报告；如需复核，另取新完整快照，不越过旧快照读活动槽，也不修写现场槽或清锁。

`chunk_committed.decision_counts`是每个工作进程本次启动后的累计数，不能把日志各行相加；恢复后的当前日志也不覆盖旧轮已提交量。`worker_summary.json`和`parent_result.json`需要相应终态，运行中缺失不单独判失败。租约领取时间不是心跳，不能按租约年龄擅自接管。

`failed`主要表示原件解码失败；空文字、语言不支持、零长、库内修补、旧VAD无效及多种处理问题会进入`unknown`。进程日志无Traceback或`failed=0`不能替代侧车质量审阅。ETA用两次带时间戳的已完成来源增量估算，计入三种状态；说明抽样域与阶段，不用候选数、单次GPU利用率或平台最长时限当吞吐。人工完整字审核与最终全库核验时间另外记录。


## 十进制原钟和文字条件对照

新`source_clock.py`把已保存十进制秒按`Fraction(str(seconds))`映回原采样钟，外向floor/ceil，不加epsilon、不裁边、不拉伸。16k下16.24秒等精确共享端点，旧二进制float乘法可能凭空多出1采样点重叠；这是映射缺陷，不能解释成模型真的重叠。44.1k下真实非整数网格的外包络重叠仍待复核，真正时间重叠、零/负时长和库内修补标记不放宽。v1仍用于按旧声明重建旧记录，新合同明确v2；每窗映射必须与producer runtime一致，不能由窗口自选。

归一化A/B是诊断，两个新合同都用同一十进制映射、同一原音/PCM/模型/窗口和单窗策略；A用legacy文字规则，B显式保留字母之间的ASCII撇号。B仍保留词内撇号待审核标记；原始全角撇号经NFKC成为ASCII时也必须留标记。数字、混合脚本、弯引号等不能猜读法或自动变成候选。旧默认规则继续按原字节重建。

若复用历史完整ASR，只能绑定原generated token/EOS/模型与解码器身份，正式推理还要重新核原件和PCM。两轨ASR缓存消费、实际FA重执行、原生/FIX与最终单位分别计账。表面较少的unknown或合法几何不等于转写或完整字更准；固定16条前缀不是三域随机质量金标，缺少某域时如实列出，不能外推全库。

10月26日观测的54cd旧包与后来f8等诊断包按各自具体摘要读，不热补、不重封。`quality_axes.py`新包导入修复是仓库新源码：包消费者采用显式相对`.source_clock`，脚本入口采用同目录绝对导入；不能把本次维护SHA写成已跑A/B的producer身份。旧侧车的读取工具应核显式历史合同/包SHA，而非要求它们等于当前可变源码。


## 吞吐诊断与优化边界

吞吐调查同时看已完成来源增量、窗口/音频时长、实际阶段调用及缓存。历史三域3000条的两个真实worker摘要中，ASR阶段占累计进程时间87.81%，Ultra定位占4.20%；其中2635份新侧车、365份整侧车复用，阶段缓存均0。该历史样本可确定同执行策略下的优化优先级，不能当全冷启动或当前全库阶段实测。16例固定ASR对照不适合估计完整生产吞吐。旧冻结worker只在终态输出累计backend_metrics，不能为其虚构运行中细分时间；10月27日维护版本另加每片轻量performance计数，未热改旧任务。

独立维护版本已补运行中小型阶段计时，GPU真测速尚未执行。不以空余显存或单点GPU利用率直接判定I/O瓶颈。生产单窗、FP32/eager/TF32关闭有历史结果敏感性约束；转写批量、精度或计算方式改变时，使用新合同/输出/缓存，比较文字、EOS、字界、异常分布和恢复，不热改原54cd生产包。完整原件/PCM身份、严格边界及候选准入条件保留。新旧任务不共写队列；任何提速倍数须标明实测或数学情景。具体调查与尚未执行的验证见仓库内`docs/reviews/2026-10-26-标注吞吐瓶颈与提速验证安排.md`。

带日期的任务进度和阶段耗时不因文档同步而更新为实时状态。10月27日早间文档同步只使用10月26日快照；后续11:22—11:34另取新只读证据并实现提速候选，分别按日期读报告。用户随后要求“GPU先不测了”，当时完成联合全库接续、唯一消费者、跨引擎审计和vLLM最小适配的CPU实现，798项CPU单元测试实际0skip通过，该CPU实现阶段没有新增GPU进程或切换任务。之后另有八卡WebShell事故与当前已授权的独立恢复，不能用早期CPU结论概括整天。后续源码不能继承此前现场验收。详细接口、未领取片预置结果保留、新数据门与旧运行门的区别，以及排队后新鲜证明外层，见[转写提速及接续](asr-speed-and-continuation.md)和仓库`tools/open_annotation/排队后新鲜证明交接.md`。
