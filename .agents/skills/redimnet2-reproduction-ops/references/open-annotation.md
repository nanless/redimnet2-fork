# 开源模型自动标注

旧v1分片协议的实时封账进度可用`tools/open_annotation/readonly_progress.py`读：它只读一个原子broker快照，以及其中已完成、非活动租约的固定槽；不构造WorkQueue，不拿写锁，也不扫描全部侧车。这么读出来的报告只能写完成下界，因为单快照只覆盖已封账的那部分槽。`failed`是发布决定，不代表所有操作错误为0。单快照也给不出ETA；要ETA得取同口径的两个时间窗口做增量。输出写到新的审计目录；写进队列目录，审计产物就和被计数的对象混在一起。原子替换会改变旧FD的ctime，只凭这一项变化就把快照判为非法，会误拒合法快照；判断仍要核已打开FD的尺寸、mtime、完整JSON及固定身份。

2026-10-26检查时，待复核约占七成，涵盖原生零/负时长、未解决重叠、库内修补和文字读法未决。`processing_errors_preserved`可能只是保存模型结果时留下的几何错误，不一定是worker程序崩溃。提高产出比例不能靠放宽判据：判据一松，候选和待复核就会被当成已通过，而这两类状态本来都不自动授予训练或正式评测资格。固定前缀抽查不是随机金标，推算不出全库的文字/字界准确率。

维护代码在 `tools/open_annotation/`。本轮批量范围取 VoxCeleb2、VoxBlink2、CN-Celeb2 的实际训练来源；同一个来源若同时出现在主训练清单和大间隔清单里，只计一次。额外评测域、噪声、房间脉冲和业务诊断不加入主分母。范围要改时按本次用户要求重新确定；沿用历史混合批，分母与本轮口径就对不上。

要保留原件编码摘要、原采样率多通道解码摘要、模型实际输入摘要、时钟，以及原始说话人/用途信息。旧 VAD 结果只在身份材料实际存在时才复用；路径/stat 绑定不等于旧音频 SHA 绑定，写成 SHA 绑定会高估证据强度。文件名相同不能作为无关路径的复用依据。

模型原始文字和语言、归一化的每一步、原生时间、库内修补和几何错误都要保存，缺一项后面就无法复算当时的输出。零长、越界、生成截断、空转写、不支持语言、数字/混合脚本读法未决均入完整分母，从分母里剔掉这些，比例会好看，含义却变了。多个汉字组成的原生粗词不按平均拆时间。机器听辨不能充作人工审核。

单窗执行合同要绑定实际调用宽度和缓存语义。同一个窗在不同批次里可能变化，缓存键上只加批大小、其余照旧跨组合复用，会读到不属于本次组合的结果。恢复时比较完整基线与新输出的原生 ASR、对齐和观察层；旧结果复用、缓存消费、实际重执行三类分开记。

发布要核原子输出、提交记录、队列归属、代次和输入集合；worker退出码正常只说明进程结束，说明不了这几项。CPU 队列测试证明不了远端文件系统或跨节点锁语义。现场验收分别保存资源主动证明、实际 worker、所有 rank 和归还快照。

完成后的全量审查从重新打开的侧车重算三状态，逐片与完成槽计数核对，并核完整的单源提交描述与分片身份。摘要字段存在，不等于字段之间互相一致。Ultra 原生观察还要核实际 logits 摘要、行数/词表形状、类别范围和输入位置范围。运行中的终态审查缺完整分母，这种结果不能当软件故障读。输出、缓存和队列路径要连根目录和中间目录的软链一起看；只核最后一个文件名，会漏掉指到别处的软链。拒绝时保留原文件；清锁或改旧冻结代码绕过校验，等于把现场证据抹掉。

候选状态和几何合法都不改变 `usable_for_training/evaluation`，这一项保持原值。保护引用是显式外部输入，按调用者提供并核实的固定 SHA 绑定。公开测试用合成保护表，真实名单不发布。未知或失败的结果可以如实保存为待核自动标注，但不能因此承诺完整字准确率。

## 正在运行时如何只读计数

现场代码先与部署身份对应。巡检不实例化`WorkQueue`：它的构造器会创建目录、加锁并初始化文件，等于对现场写入。`report.py` 即使非全量模式也要求全局完成，所以运行中分母尚未完成时报出的错，不能直接当成任务失败。

轻量进度读取原子更新的`queue/broker.json`、`identity.json`和已核摘要的固定索引。核对游标、租约编号与`next-len(leases)==completed_chunks`；求和以该次队列记录的完成集合为准，按分片实际`count`累加；乘固定256，累计条数就和逐片实际条数对不上。完成槽按1024字节读，检查魔数、载荷SHA、索引/合同/分片身份和三状态计数之和。记录读取的起止时间，活动租约不计入。按协议，已封账的槽应当已完整同步；校验不通过就保留错误并拒绝成功报告。要复核就另取一份新的完整快照：越过旧快照读活动槽，或者修写现场槽、清锁，读到的状态就不再有同一口径。

`chunk_committed.decision_counts`是每个工作进程本次启动后的累计数，把日志各行相加会重复计数；恢复后的当前日志也不覆盖旧轮已提交量。`worker_summary.json`和`parent_result.json`要等相应终态，运行中缺失不单独判失败。租约领取时间不是心跳，按租约年龄接管，会抢走仍在工作的租约。

`failed`主要表示原件解码失败；空文字、语言不支持、零长、库内修补、旧VAD无效以及其他处理问题进的是`unknown`。进程日志里没有Traceback，或者`failed=0`，都替代不了侧车质量审阅，这两项只说明进程没崩。ETA 用两次带时间戳的已完成来源增量估算，三种状态都计入；报 ETA 时说明抽样域和阶段。候选数、单次 GPU 利用率、平台最长时限都不是吞吐。人工完整字审核与最终全库核验的时间另外记录。


## 十进制原钟和文字条件对照

新`source_clock.py`把已保存的十进制秒按`Fraction(str(seconds))`映回原采样钟：外向 floor/ceil，不加 epsilon、不裁边、不拉伸。16k下16.24秒这类精确共享端点，旧二进制 float 乘法可能凭空多出1采样点重叠；这是映射缺陷，读成模型真的重叠就错了。44.1k下真实非整数网格的外包络重叠仍待复核；真正时间重叠、零/负时长和库内修补标记不放宽。v1仍用于按旧声明重建旧记录，新合同明确写v2；每窗映射要与 producer runtime 一致，由窗口自选会让同一份输入算出两套时间。

归一化A/B是诊断：两个新合同都用同一十进制映射、同一原音/PCM/模型/窗口和单窗策略，差别只在文字规则，A 用 legacy 文字规则，B 显式保留字母之间的 ASCII 撇号。B 仍保留词内撇号的待审核标记；原始全角撇号经 NFKC 变成 ASCII 时，标记也要留。数字、混合脚本、弯引号这些不猜读法，也不自动变成候选。旧默认规则继续按原字节重建。

复用历史完整 ASR 时，绑定范围限于原 generated token/EOS/模型与解码器身份；正式推理还要重新核原件和 PCM。两轨的 ASR 缓存消费、实际 FA 重执行、原生/FIX与最终单位分别计账。unknown 看起来少、几何合法，都不等于转写或完整字更准。固定16条前缀不是三域的随机质量金标；缺某一域时如实列出，不能外推全库。

10月26日观测的 54cd 旧包和后来的 f8 等诊断包，按各自的具体摘要读，不热补、不重封。`quality_axes.py` 的新包导入修复属于仓库新源码：包消费者走显式相对`.source_clock`，脚本入口走同目录绝对导入。本次维护的 SHA 不是已跑A/B的producer身份，写混了两边就对不上。旧侧车的读取工具核的是显式历史合同/包SHA；要求它们等于当前可变源码，历史侧车就都读不了。


## 吞吐诊断与优化边界

吞吐调查同时看已完成来源增量、窗口/音频时长、实际阶段调用和缓存。历史三域3000条的两个真实 worker 摘要里，ASR 阶段占累计进程时间87.81%，Ultra 定位占4.20%；侧车来源中2635份是新侧车，365份整份复用，阶段缓存均为0。这个历史样本能定同执行策略下的优化优先级，但它不是全冷启动，也不是当前全库的阶段实测。16例固定 ASR 对照不足以估计完整生产吞吐。旧冻结 worker 只在终态输出累计 backend_metrics，运行中的细分时间没有来源，补写就是虚构；10月27日维护版本另加每片轻量 performance 计数，旧任务未热改。

10月26日该维护版本已补运行中的小型阶段计时，当时 GPU 真测速还没执行。10月28日之后，逐条特征 B8 完成了真实对照和恢复，并接入独立正式任务，按[转写提速及接续](asr-speed-and-continuation.md)末节读；当时的“未测”不再写成当前结论。空余显存多、单点 GPU 利用率低，都不足以判定 I/O瓶颈。旧生产单窗、FP32/eager/TF32关闭有历史结果敏感性约束：转写批量、精度或计算方式一变，就要用新合同/输出/缓存，比较文字、EOS、字界、异常分布和恢复；热改原 54cd 生产包，已发布的结果就换了口径。完整原件/PCM身份、严格边界和候选准入条件保留。新旧任务不共写队列。任何提速倍数都标明是实测还是数学情景。早期调查和当时未执行项见仓库内`docs/reviews/2026-10-26-标注吞吐瓶颈与提速验证安排.md`。

带日期的任务进度和阶段耗时，不会因为文档同步就变成实时状态。10月27日早间的文档同步只用10月26日快照；之后11:22—11:34另取了新的只读证据并实现提速候选，两段要按日期分别读报告。用户随后要求“GPU先不测了”，当时完成的是 CPU 实现：联合全库接续、唯一消费者、跨引擎审计和 vLLM 最小适配，798项 CPU 单元测试实际0skip通过；这个阶段没有新增 GPU 进程，也没有切换任务。之后另有八卡 WebShell 事故与当前已授权的独立恢复，早期 CPU 结论概括不了整天的情况。后续源码继承不了此前的现场验收。详细接口、未领取片预置结果保留、新数据门与旧运行门的区别，以及排队后的新鲜证明外层，见[转写提速及接续](asr-speed-and-continuation.md)和仓库`tools/open_annotation/排队后新鲜证明交接.md`。

## 待审原因的有限实音复核（2026年10月28日）

用户要求查具体 unknown、且禁止额外全库审查时，核查范围限于明确的历史批次和有上限的对照：不重启联合库，不新建数据库，也不为凑满计划数量取样。完整片实际可以取到251/253/256条；只收恰好250条，再把剩下的算作失败，就把可用样本记成了缺件。读取次数、唯一样本、API 原件、视图和必要裁片分别记录。已拒绝或保守退出的保留完整证据；缺失的 stage 交叉表如实说明，不靠默默重扫补齐。

本次历史2452个来源里，716个是候选，1736个待核；未知按整源级判定，任一窗口告警即算，原因之间可以重叠。886项来源处理问题不等于崩溃。835条规则名 native_zero_or_negative_duration 实际检查的是作者最终 items；把它们都读成 raw argmax 的原生零长，会认错零长的来源。真实纯 FIX 重放已经证明正时长可以被作者修成零长；原生、FIX、units 和消费裁片要分开核。零长项被 units 排除，不等于它的声音从连续裁片里消失，按剩下的两项切音，可能把中间的词夹进来。

实际转写配置支持30语言，Ultra 定位支持11，两者数量并不相等。501个不支持定位的单位是窗口，不是文件；ASR 语言预测仍要听辨核实。真实的512-token截断和 EOS 集合／捕获问题要分开处理：把预算统一升上去，只会把语言不支持盖住。RTTM 毫秒尾端比物理帧数多7sample的两例，是已核身份匹配的格式量化问题，不是 device 误拒；由此个例放宽任意越界，会把真的越界也放过去。旧 float 源钟六对1sample假重叠已经实证。维护v2与实际生产v1按各自的身份核；23文件冻结包不热改。

有限原音和 API 工具见仓库`tools/open_annotation/有限原音与内部API复核.md`，图工具见`已保存原音与字界图审.md`。先盲审，参考只在出现具体冲突时用。批准的原件范围和内部目的地明确之后沿用，不反复确认。默认预检不读密钥、不联网，最多24唯一来源；裁片保留连续原声和完整的 native/FIX 背景。真实 API 输出只表示模型的观察结果，usable_model_observation 只说明协议／结构合格；API 自己会漏字、变读法，也会把音乐切口或句意未完的地方按语音硬切，所以不能充作人工字界真值。源坐标看绑定清单；局部 WAV 的0…frames不等于原 owned 范围。

本次实际24原音、32上下文视图以及少量同源必要裁片都留在本机；完整文本／原件／原始 SSE 不入公开 Git。具体数字，以及 PTN 八 rank、192worker、瞬时八卡的信息，见`docs/reviews/2026-10-28-待审原因有限抽样与PTN实测.md`。之后的报告仍要重新读取带时间的真实证据；10月28日的快照不能称作实时。
