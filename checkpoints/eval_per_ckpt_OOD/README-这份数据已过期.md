# `eval_per_ckpt_OOD/` 是什么，以及为什么不能用

## 结论先看这里

**同一个权重的 CN-Celeb 数字，本目录与 `checkpoints/eval_ood_all.csv` 对不上。**

| 权重 | 本目录的 CN-Celeb | 汇总 CSV 的 CN-Celeb | 官方数字 |
|------|------------------|---------------------|---------|
| `b3-vb2+vox2+cnc2_v0-lm.pt` | 5.632 | **4.776** | 4.78 |
| `b3-vb2+vox2+cnc2_v0-ptn.pt` | 6.207 | **5.294** | 5.29 |
| `b6-vb2+vox2+cnc2_v0-lm.pt` | 4.037 | **3.605** | 3.59 |
| `b6-vb2+vox2+cnc2_v0-ptn.pt` | 4.823 | **4.316** | 4.32 |
| `b6-vb2+vox2_v0-lm.pt` | 7.829 | **7.399** | 7.49 |
| `b6-vb2+vox2_v0-ptn.pt` | 9.203 | **8.510** | 8.50 |

汇总 CSV 的数字与官方数字相差很小（绝对值最大 0.09 个百分点），
而本目录的数字普遍高出 0.8～0.9 个百分点——因为**用的不是同一个评测协议**。

## 差别只在 CN-Celeb 这一列

另外两个协议（VOICES、Vox1-B）两处**完全一致**，说明不是整体过期，
而是 CN-Celeb 那一列当年用了**旧的单段打分口径**。

CN-Celeb 的正确口径（与 WeSpeaker 的 CN-Celeb 配方一致）是：

1. 读 `CN-Celeb_flac/eval/lists/enroll.map`，一个注册人对应多段 wav；
2. 每段各提一个说话人向量，**先取平均再做 L2 归一化**；
3. 用这个平均向量去和测试段算余弦。

本目录当年没有做第 2 步的"多段平均"，所以数字偏高。

## 现在应该看哪一份

- **要用数字**：`checkpoints/eval_ood_all.csv`（以及
  `checkpoints/eval_per_ckpt_CNC_AVG/`，两者一致）。
- **要看说明**：`checkpoints/reports/03-域外试验结果.md`，它用的就是 Avg 口径，
  并在第 5 节写清了正确流程。
